# Roadmap archive — 2026-05

## Archived 2026-05-25

- **CI-RUFF-PRECOMMIT-01**: `Backend ruff + mypy` and
  `Pre-commit hooks` CI jobs sat red across v1.23.2 → v1.25.0
  while `make release-test` ran green at every release. Root
  cause: the aggregate Makefile target invokes `make test` +
  frontend build + vitest + `sync-versions-check` +
  `verify-plugin-locks`, but does NOT run `ruff check`,
  `ruff format --check`, `mypy`, or `pre-commit run
  --all-files` directly. Per the release-workflow.md rule
  these are MANDATORY for every release; the local aggregate
  target diverged from the documented workflow and the gap
  let CI debt accumulate.

  Filed and closed in v1.25.1 (this release). Concrete debt
  reconciled in v1.25.1:
  - 3 ruff errors (`I001` × 2 import ordering, `UP017`
    `datetime.UTC` modernisation) — auto-fixed.
  - 2 ruff-format files (line-length drift in `app/main.py`
    + `app/services/help_glossary.py`) — auto-formatted.
  - 1 pre-commit auto-fix on a Claude.ai parser fixture
    (trailing-whitespace + end-of-file).
  - 2 mypy errors that had been latent (the
    `Backend ruff + mypy` CI job fails fast on ruff before
    reaching mypy, so they never surfaced): a `None`-narrowing
    issue in `app/services/imports.py` and a missing
    `py.typed` marker on the gamification plugin (resolved
    via a new `[[tool.mypy.overrides]]` entry).

  Follow-up worth filing if it recurs: extend `make
  release-test` to invoke the four MANDATORY checks
  explicitly. The current aggregate runs `make test` and the
  frontend pieces; folding `ruff check && ruff format --check
  && mypy && pre-commit run --all-files` into the same target
  would close the gap structurally. Deferred from this hotfix
  because the immediate goal was the green CI badge, not the
  Makefile refactor.

## Archived 2026-05-23

- **COVERAGE-WORKFLOW-PLUGIN-INTEGRATION-01**: 55 plugin-
  integration test failures in Coverage Backend Coverage AND
  CI Backend Tests since v1.23.2. The filing-time hypothesis
  (`coverage.yml`-only bug rooted in `pytest-cov` /
  entry-point-discovery race) was wrong: `ci.yml` Backend
  Tests was ALSO red across the same window with the same 55
  failures, and both jobs use identical `poetry install
  --no-interaction --no-ansi` steps. The handover document
  filed in commit `2e6595c` ranked four fix paths (A:
  `make install-plugins`, B: two-pass pytest, C: pin
  `pytest-cov`, D: trace fixture order) — none addressed the
  actual cause.

  Real root cause: `backend/config/app.yaml` is gitignored.
  On a fresh CI checkout, `app.main` module-level code copies
  `app.yaml.example` -> `app.yaml`. The example was last
  touched in commit `d990645` (ai-openai + ai-gemini plugin
  landing) and never updated when `gamification` (Phase 29A),
  `anki` (Phase 30B), and `notebooklm` (Phase 32) were added.
  CI was running with only 7 of 10 plugins enabled. The 54
  failing tests from those 3 plugins' integration suites plus
  1 collateral failure in `test_tracking_plugin_integration`
  account for all 55.

  Diagnostic evidence in every failure log:
  `Plugins enabled in config (7): assessment, ai-anthropic,
  ai-openai, ai-gemini, session, tracking, tools`. The
  filing-time investigation didn't reach this line because
  the hypothesis was set before reading the actual log.

  Fix: 3-line addition to `backend/config/app.yaml.example`
  bringing it in line with the production `app.yaml` shape.
  Local `make test` remained green throughout (developer
  machines all carry a populated `app.yaml`); the bug was
  invisible to anyone who didn't run a fresh CI-like setup.

  Lessons-learned implications captured separately in
  `.claude/rules/lessons-learned.md`.
