# WCAG 2.1 AA Re-Audit — v1.25.0 → v1.41.0 components, across all themes

**Date:** 2026-05-29
**Phase:** 58I (v1.41.0 — UX/UI Audit + Theme System)
**Predecessor:** [wcag-2026-05-23.md](wcag-2026-05-23.md) (v1.24.0)
**Scope:** the components shipped in the 17 releases since the last
audit, re-checked against WCAG 2.1 AA in the new 6-theme system.

## Method

- **Tooling:** `@axe-core/react` runs on every render in dev mode
  (wired since Phase 39 C6, [main.tsx](../../frontend/src/main.tsx#L38);
  tree-shaken from prod, verified by `grep -r axe dist/assets`).
- **Contrast:** pinned by
  [contrast.test.ts](../../frontend/src/styles/contrast.test.ts) across
  **all 6 themes** (light, dark, ocean, forest, high-contrast, sepia):
  body/secondary/muted text, accent buttons, status colors, and
  exercise feedback all assert ≥ AA. 30 assertions, green.
- **Code audit:** keyboard operability, focus management, ARIA roles,
  `aria-live` announcements, and `prefers-reduced-motion` were checked
  per component by reading source (not just axe, which can't see
  keyboard flow or live-region intent).

This is a code + automated-contrast audit. Items that need a live
screen-reader pass are marked **[SR-verify]** for manual QA; none block
the release on code grounds.

## Findings + fixes (this phase)

1. **Content download status not announced (SC 4.1.3 Status Messages)
   — FIXED.** The download button changed text (`Downloading…` →
   `Installed`) but, being `disabled` during the fetch, the change
   wasn't re-announced. Added an `sr-only` `role=status`
   `aria-live="polite"` region per card
   ([Content.tsx](../../frontend/src/pages/Content.tsx)). Errors were
   already announced by react-toastify's own live region.

2. **No global keyboard-focus baseline (SC 2.4.7 Focus Visible)
   — FIXED.** Focus rings were defined per-component; a new component
   could ship without one. Added a specificity-0 `:where(...):focus-visible`
   baseline in [global.css](../../frontend/src/styles/global.css) using
   `var(--accent)`, which resolves to a clearly-visible color in every
   theme (indigo / sky / amber / **yellow in high-contrast** / sienna).
   Component-specific focus styles still win (specificity 0 baseline).

3. **Contrast in the 4 new themes (SC 1.4.3) — VERIFIED.** ocean,
   forest, high-contrast, and sepia were authored to AA and pinned by
   contrast.test.ts alongside light/dark. High-contrast is the
   accessibility-first theme (pure black/white + signal colors, white
   hairline-ring card separation).

## No new violations of note

axe-core surfaced no critical/serious violations on the audited routes
in dev (the established C6 dev integration). The exercise, lesson,
badge-gallery, and missions surfaces built since v1.24.0 follow the
existing accessible patterns (real buttons, labelled controls,
progressbar roles, reduced-motion guards).

## Net

The post-v1.24.0 surface was already largely accessible (it reused the
Phase 39 patterns). This phase closed two concrete gaps (download status
announcement, global focus baseline) and verified AA contrast holds in
all 6 themes — the theme system did not regress accessibility, and the
high-contrast theme strengthens it.
