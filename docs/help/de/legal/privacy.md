## GitHub-Funktionen mit eigenem Zugangstoken

Einige Funktionen nutzen die GitHub-API (`api.github.com`) mit einem
persönlichen Zugangstoken, das Sie selbst eintragen, in den Einstellungen unter
Integrationen oder für ein einzelnes Repository. Das Token wird in Ihrem
Browser gespeichert und nur an GitHub gesendet. Mit ihm handelt die App in
Ihrem Namen:

- Die App prüft das Token und liest dabei Ihren GitHub-Benutzernamen.
- Die App liest private Repositorys, die Sie verbunden haben, auch bei der
  automatischen Prüfung oben.
- Die App teilt eine Lektion mit der Community: als Pull Request an das
  öffentliche Repository `astrapi69/adaptive-learner-content` des Betreibers,
  über eine Kopie (Fork) in Ihrem Konto.
- Die App reicht Ihr eigenes Inhalte-Repository für die Suche ein, ebenfalls
  als Pull Request an `astrapi69/adaptive-learner-content`.
- Die App exportiert ein Set in ein neues Repository in Ihrem Konto, das
  standardmäßig privat ist.
- Für Coaches legt sie Einladungscodes im Ordner `codes/` des eigenen
  Repositorys an, listet und deaktiviert sie.

Ohne Token öffnet "Mit der Community teilen" stattdessen die
Bearbeitungsseite von GitHub (`github.com`); passt die Lektion in die Adresse
dieser Seite, steht ihr Inhalt darin. "Einreichung vorbereiten"
(Einstellungen > Daten > Eigenes Repository registrieren) fragt bei
`api.github.com` den letzten Stand des Repositorys ab, das Sie angeben, mit
dessen Token, falls Sie eines gespeichert haben.

GitHub erhält dabei das Token, Ihre IP-Adresse, übliche Browserdaten, die
Namen der Repositorys und Dateien und alles, was Sie teilen oder exportieren:
die Lektion oder die Dateien des Sets, Commit-Nachricht, Titel und
Beschreibung des Pull Requests mit den Angaben zur Lektion, den
Registereintrag und, wenn Sie ihn angeben, Ihren Namen als Autorin oder Autor.
Ein Einladungscode enthält Code, Repository, Branch, maximale Nutzungen,
Ablaufdatum, Notiz und, falls Sie es einbetten, ein Lese-Token; dieses Token
kann jeder lesen, der die Code-Datei lesen kann.

Was Sie an `astrapi69/adaptive-learner-content` schicken, wird ein öffentlicher
Pull Request mit Ihrem GitHub-Benutzernamen und, falls angegeben, Ihrem
Autorennamen. Der Betreiber erhält ihn, prüft ihn und übernimmt den Beitrag
gegebenenfalls in die Inhalte (Art. 6 Abs. 1 lit. b und f DSGVO). Der Pull

## Fehlerberichte

Einen Fehlerbericht bereiten Sie über die Schaltfläche einer Fehlermeldung
("Problem melden"), über "Fehler melden", wenn sich eine Ansicht nicht laden
ließ, oder mit "Fehlerbericht erstellen" in den Einstellungen unter "Diagnose &
Support" vor. Sie sehen den Bericht vorher. Erst wenn Sie auf "Auf GitHub
öffnen" klicken, öffnet die App in einem neuen Tab ein vorausgefülltes Formular
für ein neues Issue im Repository `astrapi69/adaptive-learner` auf
`github.com`. Der Bericht steht in der Adresse dieser Seite, deshalb erhält
GitHub ihn schon beim Öffnen des Tabs, bevor Sie dort etwas abschicken. Bei
einer internen Fehlermeldung beim Erstellen einer Lektion öffnet "Problem
melden" ein solches Formular direkt, nur mit dieser Fehlermeldung.

Der Bericht enthält die Fehlermeldung mit technischen Angaben (etwa
Statuscode, Endpunkt, Zeitpunkt oder Stacktrace) und Ihre eigene
Beschreibung. Umgebungsangaben (App-Version, Browser, Betriebssystem, aktuelle
Seite) und den Aktionsverlauf (siehe Speicherung auf Ihrem Gerät) fügt die
App nur hinzu, wenn Sie das jeweilige Kästchen ankreuzen; beide sind zunächst
nicht angekreuzt.

Schicken Sie das Issue auf GitHub ab, ist es öffentlich und mit Ihrem
GitHub-Konto verbunden. Der Betreiber erhält es und nutzt es, um den Fehler zu
beheben (Art. 6 Abs. 1 lit. f DSGVO); es bleibt gespeichert, solange das Issue
besteht. Empfänger ist die GitHub, Inc. (siehe oben).
