# デスクトップランチャーを起動する

!!! tip "ほとんどのユーザーにランチャーは不要です"
    Adaptive Learner はブラウザで直接動作します。インストールも、
    Docker も、ランチャーも不要です：
    **[astrapi69.github.io/adaptive-learner](https://astrapi69.github.io/adaptive-learner/)**。
    デスクトップランチャーが必要なのは、アプリを自分でホストしたい
    場合や、バックエンド機能（サーバーモード、ローカル同期）を
    ローカルで動かしたい場合だけです。

デスクトップランチャーは、あなた自身のマシンで **独自のバックエンド
とともに** Adaptive Learner を動かす最も簡単な方法です。これは
小さなウィンドウで、それ以外のすべてを代わりに行います。Docker が
実行されているかを確認し、初回起動時にアプリのイメージを
ダウンロードしてビルドし（一度だけ、5-10 分が普通です）、コンテナを
起動し、そして `http://localhost:8501` でブラウザにアプリを開きます。
同じウィンドウから、アプリの停止、ポートの変更、すべての
アンインストールも行えます。

ポートはデフォルトで **8501** で、ランチャーのウィンドウから変更
できます。使用中の場合、ランチャーは空いているポートに切り替えます。

## 誰がアプリにアクセスできるか

アプリは既定では**このコンピューターからのみ**アクセスできます
(`127.0.0.1`)。これは意図的です。アプリにはログインがなく、あなたの
AI プロバイダーの鍵が入っているからです。ネットワークから見える状態
だと、同じネットワークにあるどの機器でも - 職場の LAN、ホテルや
カンファレンスの WLAN でも - そのまま開いて使えてしまいます。

ほかの機器から、たとえば自宅の WLAN のスマートフォンからアクセス
することは引き続き可能ですが、意図的な選択になります。`.env` に
`ADAPTIVE_LEARNER_BIND_ADDRESS=0.0.0.0` を設定してください。信頼できる
ネットワークでのみ行い、そのネットワークにいる全員があなたと同じ
アクセス権を持つことを忘れないでください。

## 前提条件：Docker - ランチャーが自分で確認します

ランチャーは実行中の Docker を必要とします。アプリ自体が
コンテナ群として動作するためです。ただし、手動で何かを確認する
必要は**ありません**。ランチャーは起動時に、Docker が
インストールされ実行されているかを自分で確認し、別の Docker
コンテキストで動作している Docker（Docker Desktop for Linux や
rootless Docker など）も見つけ出し、何かが欠けている場合には解決策
付きの明確なメッセージを表示します。Docker がまだ一切
インストールされていない場合は：[Docker Desktop をインストールする](docker-desktop.md)。

ランチャーのメッセージとその意味：

| メッセージ | 意味 | 解決策 |
|---------|---------|-----|
| 「Docker がインストールされていません（docker が PATH にありません）。」 | `docker` コマンドが見つかりませんでした。 | [Docker Desktop をインストールする](docker-desktop.md)。ランチャーはインストール用リンクを直接表示します。 |
| 「Docker はインストールされていますが、起動していません。」または「Docker が実行されていません。確認したコンテキスト '...'（...）：...」 | Docker サービスが今は実行されていません。詳細形式では、確認したコンテキスト、ソケット、および Docker の元のエラーが示されます。 | ランチャー内の **「Docker を起動」** ボタンをクリックする（Linux）か、Docker Desktop を開く（macOS/Windows）、その後 **「再確認」**。 |
| 「Docker はインストールされていますが、権限がありません。」 | あなたのユーザーが `docker` グループに属していません（Linux）。 | ランチャーが正確なコマンドを表示します。その後、一度ログアウトして再度ログインしてください。 |
| 「Docker が応答しません。」 | Docker はおそらくまだ起動中です（Docker Desktop を開いた直後によくあります）。 | 少し待ってから **「再確認」**。 |
| 「Docker はコンテキスト '...' 経由で実行されています - アクティブなコンテキストに到達できなかったため、ランチャーが自動的に接続しました。」 | 情報のみ：Docker は別のコンテキストで実行されており、ランチャーがそれを見つけて使用しています。 | 何もする必要はありません。 |
| 「Docker Desktop はインストールされていますが、PATH にありません。」 | Docker Desktop アプリは存在しますが、そのコマンドラインツールが（まだ）到達可能になっていません。 | ランチャーのボタンから Docker Desktop を起動し、少し待ちます。 |

詳細メッセージ付きのコンテキスト検出は、docker-app-launcher#26 に
続くランチャーバージョンから搭載されています。それより古い
バージョンでは、同じ表にある短いメッセージが表示されます。

## ダウンロード

3 つのランチャーはすべて、各リリースに同梱されています。
[github.com/astrapi69/adaptive-learner/releases](https://github.com/astrapi69/adaptive-learner/releases)：

| プラットフォーム | ファイル | チェックサム |
|----------|------|----------|
| Linux | `adaptive-learner-launcher` | `adaptive-learner-launcher.sha256` |
| macOS | `adaptive-learner-launcher-macos.zip` | `adaptive-learner-launcher-macos.zip.sha256` |
| Windows | `adaptive-learner-launcher.exe` | `adaptive-learner-launcher.exe.sha256` |

### 検証済みの内容とそうでない内容

これらのプログラムはいずれも、ビルド時に対象の
オペレーティングシステム上で一度起動されます。これにより、起動する
ことは実証済みです。Linux で、Windows で、そして Apple Silicon の
macOS で。アプリのイメージはリリースごとに検証されます。匿名の
ダウンロード（ログインなし）と、ヘルスチェック付きの実際の起動を、
2 つのプロセッサータイプ（Intel/AMD と ARM)ごとに、その種類の
マシン上で個別に行います。まだ測定されていないのは、非常に古い
Docker エンジン（20.10 世代）でのレジストリからのダウンロードです。
エンジンのチェーン自体はそのようなエンジン上で別のレジストリに
対して実証済みで、GitHub レジストリに対する測定は upstream で
追跡されています。

実証されていないのは、**ダウンロードした**ファイルにあなたの
オペレーティングシステムがどう反応するかです。プログラムは有償の
署名を持たないため、macOS は初回起動時に警告し（「開発元を確認
できません」）、Windows は SmartScreen の通知を表示します。これは
警告であって欠陥ではありません。一度だけ承認する方法は下の
[macOS](#macos) と [Windows](#windows) にあります。その前に
チェックサムを確認してください。どのダイアログよりも信頼できる
証拠です。

## Linux

1. チェックサムを検証します（両方のファイルを同じフォルダーに）：

    ```bash
    sha256sum -c adaptive-learner-launcher.sha256
    ```

2. 実行権限を設定します。ブラウザのダウンロードは常にバイナリから
   実行権限を取り除くため、この手順は**必ず**必要です：

    ```bash
    chmod +x adaptive-learner-launcher
    ```

3. 起動します。ターミナルからが最も簡単です：

    ```bash
    ./adaptive-learner-launcher
    ```

    環境によっては、ファイルマネージャーでのダブルクリックでも動作
    します。GNOME/Nautilus では、プロパティ > アクセス権で
    「ファイルをプログラムとして実行できるようにする」を設定する
    必要があります。ターミナルからの起動には、エラーメッセージを
    直接確認できるという利点があります。

既知の落とし穴：

- **「Permission denied」**：手順 2（`chmod +x`）が抜けています。
- **起動時の GLIBC エラー**：このバイナリは Ubuntu 22.04 上で
  ビルドされており、glibc 2.35 以降が必要です（Ubuntu 22.04+、
  Debian 12+、Fedora 36+）。より古いディストリビューションでは、
  代わりに `install.sh` または Docker Compose で直接アプリを
  実行してください。
- **アプリにブラウザから到達できない**：ブラウザが自動的に開かない
  場合は、`http://localhost:8501`（またはランチャーのウィンドウに
  表示されているポート）を手動で開いてください。既定ではアプリは
  `127.0.0.1` でのみ待ち受けるため、このコンピュータからのみ到達
  できます。他のデバイスから到達できるのは、ネットワークアクセスを
  意図的に有効にした場合だけです - 上の「誰がアプリにアクセス
  できるか」を参照してください。

## macOS

1. チェックサムを検証し、ZIP を展開します：

    ```bash
    shasum -a 256 -c adaptive-learner-launcher-macos.zip.sha256
    unzip adaptive-learner-launcher-macos.zip
    ```

2. 初回起動時、**macOS はプログラムをブロックします**。macOS の
   バージョンによっては、ダイアログに「ゴミ箱に入れる」と「完了」
   しかなく、開くボタンがありません。これはエラーでもプログラムの
   不具合でもありません。Adaptive Learner は **Apple の公証を受けて
   いない**からです。公証には有料の開発者アカウントが必要です。

   それでも開く手順:

    1. ダイアログを **完了** で閉じます（ゴミ箱に入れないでください）。
    2. **システム設定 > プライバシーとセキュリティ** を開き、下まで
       スクロールします。
    3. そこにプログラムがブロックされた旨と **このまま開く** ボタンが
       表示されます。クリックし、次のダイアログで確認します。

   以降の起動では確認なしで開きます。

   この場合、手順 1 のチェックサムがあなたの本当の安全確認です。
   システムはファイルの出所を保証できませんが、一致するチェックサムは
   保証できます。

## Windows

1. チェックサムを検証します（PowerShell、両方のファイルを同じ
   フォルダーに）：

    ```powershell
    Get-FileHash .\adaptive-learner-launcher.exe -Algorithm SHA256
    Get-Content .\adaptive-learner-launcher.exe.sha256
    ```

    2 つのハッシュ値が一致している必要があります。

2. `adaptive-learner-launcher.exe` をダブルクリックします。初回
   起動時に SmartScreen が警告します（「Windows によって PC が
   保護されました」）：**詳細情報** をクリックし、続いて
   **実行** をクリックします。

## うまくいかないときは

- Docker が実行されていない場合、ランチャー自体が通知ダイアログを
  表示し、Docker Desktop の起動を提案します。
- 初回起動ではアプリのイメージをダウンロードしてビルドします。
  ランチャーのウィンドウにあるステップのチェックリスト
  （Check Docker / Download / Build / Start / Ready）が進捗を
  示します。以降の起動は高速です。
- アプリの実行中は、いつでも `http://localhost:8501`（または変更した
  ポート）で到達できます。ランチャーの「ブラウザで開く」ボタンも
  同じことを行います。
