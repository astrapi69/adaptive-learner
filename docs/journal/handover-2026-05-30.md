## 3. Cross-source dedupe (commit `37cf4dc`) — how it works

### The problem it solves

Bundled pilot content (offline fallback, shipped in the GH-Pages
build) **and** the external GitHub repo both advertise
`language-fr-a1` / `language-es-a1` with the **same `set_id`**. The
Set Browser listed each set **twice** — once tagged bundled, once
from GitHub.

### The rule (identical in both storage modes)

1. List from ALL configured sources (unchanged).
2. Dedupe by `set_id`:
   - **Higher version wins** (numeric semver compare).
   - **Tie → prefer external (GitHub)** over `bundled:` — the
     bundle is build-time-frozen, GitHub is likelier current.
   - **GitHub unreachable → only bundled/cached survives** (falls
     out for free: no GitHub entry is added, bundled wins by
     default). Offline fallback stays intact.
3. User-generated "My Lessons" rows (`source: "user-generated"`,
   unique ids) are appended **after** dedupe — never collapsed.

The winning entry **keeps its own `source`**, so the UI badge shows
real provenance.

### Where the code lives

| Mode | File | Helpers |
|---|---|---|
| Dexie (GH-Pages) | `frontend/src/storage/content-loader-dexie.ts` | `dedupeContentEntries`, `compareVersions`, `isBundledSource` — applied at the end of `listSetsDexie` |
| API | `plugins/adaptive-learner-plugin-content-loader/adaptive_learner_content_loader/service.py` | `_dedupe_content_entries`, `_compare_versions`, `BUNDLED_SOURCE_PREFIX` — applied in `list_sets` |

`bundled:` prefix detection: `BUNDLED_PREFIX = "bundled:"`
(TS, already existed) / `BUNDLED_SOURCE_PREFIX = "bundled:"`
(Python, new). API mode has **no bundled sources today** (only the
GitHub repo in `content-loader.yaml`), so the tie-break is a no-op
there now but correct for future multi-repo configs — and it
realizes the "first source wins for a given set_id" contract the
config comment already promised.

### UI badge

Subtle pill on each downloaded set card:
`content-set-${id}-source` testid, label "Bundled" / "GitHub".
- i18n: `content.source.bundled` (translated 8 langs) +
  `content.source.github` (verbatim "GitHub" everywhere — brand
  name, and it's in the i18n-audit `EN_ALLOWED_TOKENS` allowlist so
  it does NOT trip the passthrough audit).
- CSS: `.content-set-source` in `global.css` (uses
  `var(--bg-secondary)` + `var(--border)` + `var(--fg-muted)` —
  all canonical tokens; do **not** use `--bg-subtle`, it is
  referenced-but-undefined).

### Tests added

- TS `Content.test.tsx`: 2 badge pins (GitHub badge / Bundled badge).

## 4. The content repo (`astrapi69/adaptive-learner-content`)

Local clone: `/home/astrapi69/dev/git/hub/astrapi69/adaptive-learner-content`

### Final, working structure

```
manifest.yaml                       # root ContentManifest: lists both sets
sets/
  language-fr-a1/
    manifest.yaml                   # per-set: carries metadata.lessons (filenames)
    lessons/NN-slug.json            # 10 French A1 lessons
  language-es-a1/
    manifest.yaml                   # per-set: carries metadata.lessons
    lessons/NN-slug.json            # 5 Spanish A1 lessons
```

### The 3 problems found + fixed (commit `005b080`) — do not regress

1. **Root `manifest.yaml`** had a non-schema `repository:` shape;
   sets lacked required `version`/`domain` → failed
   `ContentManifest` validation → sets never listed. **Fixed:**
   rewrote as a valid `ContentManifest`.
2. **Dir names** were `sets/fr-a1` / `sets/es-a1`, but the per-set
   manifest ids + bundled content + the app all use
   `language-fr-a1` / `language-es-a1`. The loader fetches
   `sets/{set_id}/…`, so the dirs MUST be named for the `set_id`.
   **Fixed:** `git mv` to `sets/language-fr-a1` / `language-es-a1`.
3. **Per-set manifests lacked `metadata.lessons`** → loader fell
   back to the `NN.json` convention → 404 on the real
   `NN-slug.json` filenames. **Fixed:** installed per-set manifests
   carrying the actual filename list under `metadata.lessons`.

### Path contract (memorize this)

```
root manifest.yaml  (ContentManifest, sets[].id)
   → sets/{set_id}/manifest.yaml  (per-set; metadata.lessons = filenames)
      → sets/{set_id}/lessons/{filename}
```

`set_id` MUST equal the directory name. If `metadata.lessons` is
absent the loader assumes `01.json … NN.json` — which 404s on
slug-named files. Always ship `metadata.lessons`.

## 5. Known open items / gotchas

### Already-known, not yet actioned

- **No tag for the 4 post-release commits.** See §1 "Decision
  pending". Likely `v1.43.0`.
- **API-mode badge is always "GitHub".** API mode has no bundled
  sources, so every set card shows "GitHub". Correct, but if a
  future config adds a non-GitHub external source the label is
  still literally "GitHub" (it only distinguishes `bundled:` vs
  everything-else). If a third source type appears, generalize the
  label logic in `Content.tsx` (currently a binary
  `source.startsWith("bundled:")`).

### Landmines (will bite if forgotten)

- **`apiCall` already JSON.stringifies `opts.body`.** Pass a raw
  object, NOT `JSON.stringify(...)`. Double-stringify = HTTP 422.
  This was the v1.42.1 `saveUserSet` bug (`7c40fe8`). Regression
  test exists in the api-client suite.
- **i18n placeholders must not contain English stopwords.** The
  translation audit (`test_i18n_translation_audit.py`) scans for
  EN markers; a `{theory}` placeholder once tripped it because it
  contains "the". The Phase-59 fix renamed it to `{steps}`. When
  adding placeholders, avoid substrings like "the", "and", "for".
- **Brand tokens in i18n** ("GitHub", "OpenAI", …) must be in
  `EN_ALLOWED_TOKENS` in `test_i18n_translation_audit.py` or the
  passthrough audit fails. "GitHub" is already there.
- **Run Vitest from `frontend/`, never repo root.** Root run →
  wrong env → `document is not defined` across ~100 files. Tells:
  `setup: 0ms`. Use `make test-frontend` or
  `cd frontend && npx vitest run …`.
- **Dexie-mode is part of the contract.** Any feature whose default
  path calls the API must route through `getStorage()` or degrade
  gracefully in Dexie mode, **same commit**. Gate:
  `make test-dexie-smoke` (walks every nav route against the
  GH-Pages-shape build, no backend). This session's dedupe passed
  19/19.
- **CSS tokens:** `--bg-subtle` is referenced-but-undefined. Use
  `--bg-secondary` / `--bg-surface` / `--bg-elevated`. The
  `no-hardcoded-colors` + `contrast` + `themes` pins will catch a
  bad token.
