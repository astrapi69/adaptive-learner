## 5. GOTCHAS (read before touching these areas)

### 5a. Scroll-direction algorithm (the auto-hide P1)
The auto-hide header shipped in the first v1.60.0 cut **but did not hide
in production**. Root cause was NOT the CSS (the user's first guess):
- `-translate-y-full` / `transition-transform` ARE in the built CSS, and
  `.app-nav` (`position: sticky; top: 0`) sets no competing
  `transform`/`transition`, so the layered Tailwind transform applies.
- `#root` IS the scroll container (`global.css`: `#root { overflow-y:
  auto; height: 100% }`; `html`/`body` only set `overflow-x: hidden`).
  The lesson page has no inner scroll container; the footer is
  `sticky bottom-0`.

The real bug: `useScrollDirection` advanced its reference (`lastScrollY`)
**on every scroll event**, so the 10 px threshold compared two
*consecutive* events. Real momentum scrolling fires many small deltas
(a few px each) → the per-event delta never crossed the threshold → the
direction never flipped to "down". The unit tests passed only because
they dispatched single large jumps (`scrollTop = 100`), masking it.
**Fix:** only advance the reference when a direction is actually
committed (accumulate movement since the last commit). **Lesson:** for
scroll/gesture hooks, a unit test that jumps in one step does NOT prove
real incremental input — add an incremental-delta test AND a real-browser
E2E that drives the actual scroll container.

### 5b. ShareWizard loads lessons ASYNC → useState initializers see no lesson
`Content.handleShare` mounts `ShareWizard` with an empty `lessons` array
and fetches the lessons asynchronously. So any `useState(() => …)` that
derives from `lessons`/`primary` runs before the data is there. The
domain-content pair fix needed a `useEffect` to re-apply the inherited
pair once the knowledge-domain lesson lands (guarded by a ref so it runs
once, before user interaction). **Lesson:** Vitest passes `lessons`
synchronously at mount, so it can't catch this class of bug — the Dexie
E2E did. When a wizard/modal derives state from async-loaded props,
test the async-arrival path (rerender with the loaded data).

### 5c. user-generated sets overload `domain` to store the ORIGIN
`saveUserSetDexie` stores `domain: input.origin` ("analysis" / "adaptive"
/ "imported") on the SET. So the SET's domain is NOT a content domain for
user sets. The content domain for a same-language lesson is carried on
the LESSON (`ContentLesson.domain`, schema v1.3) instead, and
`getLessonDexie` returns `parsed.domain ?? cached.domain`. The ShareWizard
checks the LESSON domain first. Don't "fix" the set domain to "knowledge"
— it would break the My-Lessons origin badge.

### 5d. Help glossary: English is EAGER, the rest are LAZY
`help-glossary.ts` eager-globs only `*.en.json` (keeps the getters
synchronous + never-null via EN fallback) and lazy-globs the other 7
languages (negative pattern `!../data/help/*.en.json`). `useGlossary(lang)`
triggers the per-language load and re-renders. Because EN is always
present, the existing en/de component tests pass unchanged (de falls back
to EN synchronously). Only `help-glossary.test.ts`'s German-specific
assertions need a `beforeAll(loadGlossaryLanguage('de'))`. If you add a
new glossary consumer, call `useGlossary(lang)` in it.

### 5e. Release commit + the `plugin-lock-paired` pre-commit hook
`make sync-versions` bumps every `plugins/*/pyproject.toml` version, but a
version bump does NOT change the plugin `poetry.lock` (the lock doesn't
record the root version). The `plugin-lock-paired-with-pyproject`
pre-commit hook blocks staged plugin pyprojects without a paired lock — a
**false positive** for a release version bump. Commit the release with
`SKIP=plugin-lock-paired-with-pyproject git commit ...` (keeps every other
hook active). Do NOT run `make lock-all-plugins` just to satisfy it — that
can pull risky transitive bumps.

### 5f. Tag re-cut (moving an already-published v1.60.0)
v1.60.0 was published, then PR #33 (the auto-hide fix) needed to land in
it. The clean re-cut sequence:
1. `git push origin main` (push the new commits first).
2. `gh release delete v1.60.0 --cleanup-tag --yes` (removes the published
   release AND the remote tag; notes survive in
   `changelog/releases/v1.60.0.md`).
3. `git tag -d v1.60.0` (delete local tag if still present).
4. `make release-tag VERSION=1.60.0` (verifies pins, re-creates the tag at
   HEAD, pushes main + tag).
5. `gh release create v1.60.0 --title "Adaptive Learner v1.60.0"
   --notes-file changelog/releases/v1.60.0.md`.
**Costs of moving a published tag:** launcher CI artifacts attached to the
old release are gone and rebuild on the moved tag's `release: created`
event; anyone who fetched the old `v1.60.0` resolves to a different
commit. Fine for a fresh solo-dev release; in general prefer a v1.x.(y+1)
patch for post-release fixes.

### 5g. GitHub GraphQL rate limit in gh-heavy sessions
After many `gh pr`/`gh release` calls, the **GraphQL** quota (5000/hr,
shared) exhausts while **core REST** stays healthy. `gh release create`
and `gh release view` use GraphQL and will fail with "API rate limit
already exceeded". Workaround used: create the release via the REST
endpoint —
`gh api repos/astrapi69/adaptive-learner/releases --method POST
--raw-field tag_name=v1.60.0 --raw-field name="…" --raw-field body="$(cat
changelog/releases/vX.Y.Z.md)"`. Check `gh api rate_limit --jq
.resources` before a burst.

### 5h. Run Vitest from `frontend/`, never the repo root
`cd frontend && npx vitest run …` (or `make test-frontend`). From the repo
root vitest finds no config → `node` env → `document is not defined` on
every DOM test. (Documented in lessons-learned; bit me historically.)

### 5i. The `~57 h` / `270 lessons` figures are stale
Use the live counts: `find ../adaptive-learner-content/sets -name '*.json'
-path '*/lessons/*' | wc -l` (271) and sum `estimated_minutes` (~66 h).
The numeric-claims rule: verify by running, don't echo draft numbers.
