# Adaptive Learner v2.1.0

A polish release on top of the v2.0.0 public launch. The headline is that
**removing a content repository no longer leaves ghost progress behind** - the
Dashboard, review queue, and paused-lessons only ever show content the app can
actually load. Alongside it: a Settings page reorganised around a clear causal
order, three Learning Path fixes, a discoverable "Ask AI" button, and two
content-sync robustness fixes so a public repo is read over raw URLs and a
network blip never marks a good repo unverified, plus a hardened UI-language
fallback. No schema, API, or data-model change against v2.0.0.

## Added

- **Only loadable content is surfaced after a repo is removed (#1445 /
  #1446).** Removing a content repository used to leave its lesson-progress and
  spaced-repetition rows behind, so the Dashboard and reviews kept surfacing
  started lessons and due reviews that could no longer be opened. A new
  availability oracle now filters Continue Learning, Paused Lessons, the Review
  Queue, Focus Areas, and the reviews badge to content the app can actually
  load. The orphaned progress is **hidden, not deleted** - re-adding the
  repository brings it back - and removal now offers an **opt-in delete** for
  learners who want it gone for good.

## Changed

- **Settings split into per-tab panels (#1447 / #1448).** The 865-line
  `Settings` page is decomposed into one panel per tab
  (General / Learning / Plugins / Data / Integrations / Help / About). Purely
  mechanical: no behaviour change, every deep link and test id preserved.

## Fixed

- **Settings, ordered by cause and effect.** The Data tab is reordered into a
  fixed causal sequence - content sources, then sync, then results, then
  backup, then reversible cleanup, with the irreversible danger zone last and
  visually separated (#1451 / #1452). "Install app" moves out of Data and into
  General, where it belongs with the other PWA controls (#1455 / #1456). The
  16-section Learning tab gains the same ordering principle - foundation, then
  in-lesson flow, then practice and follow-up, then motivation, then reminders,
  with rare housekeeping last (#1459 / #1462).
- **Two Settings sections regain their card container (#1465 / #1466).** The
  "Install app" and "Learning Repository" sections rendered on the bare page
  background instead of inside the card their neighbours use; both are now
  wrapped in the standard token-backed settings card, flush with the sibling
  sections.
- **Learning Path (#1453 / #1454).** The "Only mine / All sets" filter now
  actually filters the main set list; the Map tab no longer shows a
  catalog-wide progress bar whose number dropped whenever the app gained a set,
  while the Personal tab gains a bar computed only over started sets; and the
  page always opens on the Personal ("where am I?") view instead of the last
  tab you left on.
- **Search icons no longer overlap the field (#1458 / #1463).** A cascade bug
  where a global form-control padding rule defeated authored padding utilities
  is fixed at the layer level, so the search icon in the Curriculum lesson
  picker (and the clear/search icons in other search fields) no longer sits on
  top of the text. An empty curriculum path now offers an "add lesson" action
  instead of a dead progress bar and a disabled Continue button.
- **A discoverable "Ask AI" button (#1443 / #1444).** Without an AI key the
  "Ask AI" action used to disappear entirely behind a loose paragraph of hint
  text. The same button is now always shown, greyed and focusable, and reveals
  a short BYOK "optional" hint with a link to the AI settings on tap, hover, or
  focus - so the feature is visible and never a dead tap-target on iPhone/iPad.
- **A network blip no longer marks a good repo "unverified" (#1441 / #1442).**
  "Sync all" could demote a freshly-downloaded, structurally-valid repository
  to unverified when a re-validation fetch failed transiently (rate-limit or
  network, more likely under the sync-all burst). Transient I/O failures now
  preserve the existing trust; only a real structural failure demotes.
- **Public repos are read over raw URLs, never the throttled contents API
  (#1438 / #1440).** The "add repository" validation path forced a public user
  repository onto the rate-limited authenticated GitHub contents API (and could
  bleed the shared community-PR token onto it), producing intermittent
  "access denied" errors. Public repositories - official or user - are now read
  over raw URLs; the shared token stays an authoring-only credential and private
  repositories keep using their own per-repo token.
- **Hardened UI-language fallback (#1457 / #1464).** The startup language
  resolution gains a `navigator.language` step - saved choice, then the
  browser language, then the app default, then German - so a fresh install
  follows the browser's language instead of silently defaulting, and a stored
  choice is never lost.
- **Readable status toasts (#1474).** Success / error / warning / info toasts
  now use fixed, semantic background colours that meet WCAG AA contrast with
  their white text in every theme, instead of a theme accent that could be too
  light to read.

## Internal

- **Refactor-candidates audit (#1449).** An analysis-only pass producing a
  prioritized, assignment-ready list of single-concern refactor targets (the
  `Settings` split above was its first item). No code change.
- **`global.css` analysis + growth guard (#1467 / #1468).** An analysis-only
  pass over the stylesheet plus a line-count "inflow-stop" guard (script +
  CI step) so `global.css` - invisible to the existing size gates - can no
  longer grow unchecked. The stylesheet itself is unchanged.
- **Dexie-smoke release gate stabilised (#1469 / #1470, #1471, #1472).** The
  gate now seeds the UI language to German so it runs under the app's
  default-language assumption regardless of the CI browser locale, and two
  E2E specs were realigned to behaviour that changed this cycle — the content
  repo remove now goes through a confirm dialog, and the personal Learning
  Path "Only mine" filter now shows only started sets. Test-infrastructure
  only; no app or product change.

No schema, API, or data-model change against v2.0.0.

## Before you install

Adaptive Learner runs in Docker. You need Docker Desktop installed and running before starting the launcher.

- [Docker installation guide (English)](https://github.com/astrapi69/adaptive_learner/blob/main/docs/help/en/install/docker-desktop.md) - includes a "Is Docker safe to install?" section
- [Docker-Installationsanleitung (Deutsch)](https://github.com/astrapi69/adaptive_learner/blob/main/docs/help/de/install/docker-desktop.md) - mit Abschnitt "Ist Docker sicher zu installieren?"

The launcher detects Docker, downloads Adaptive Learner automatically, and opens it in your browser. The first launch takes 5-10 minutes (Docker images build, ~2 GB disk space).

## Download

| Platform | File |
|----------|------|
| Windows | `adaptive-learner-launcher.exe` |
| macOS (Apple silicon) | `adaptive-learner-launcher-macos.zip` |
| Linux | `adaptive-learner-launcher-linux` (ELF binary) |

Each platform also ships a `*.sha256` checksum next to the binary.

## Verifying downloads

```bash
# macOS / Linux
shasum -a 256 adaptive-learner-launcher-<platform>
cat adaptive-learner-launcher-<platform>.sha256
```

```powershell
# Windows
Get-FileHash -Algorithm SHA256 .\adaptive-learner-launcher.exe
Get-Content .\adaptive-learner-launcher.exe.sha256
```

The hashes must match.

If your operating system warns about an unsigned binary, see the [Adaptive Learner installation overview](https://github.com/astrapi69/adaptive_learner/blob/main/docs/help/en/installation.md).
