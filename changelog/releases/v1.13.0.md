# Adaptive Learner v1.13.0

**Released**: 2026-05-21

Phase 26 — **PT/TR/JA Native Translations.** The three
EN-passthrough catalogs are now fully translated. Brazilian
Portuguese (informal "você" form), Turkish (informal "sen"
form), and Japanese (polite ``desu``/``masu``) replace the
English placeholders across every UI string AND every
assessment question + answer. Each YAML carries an
"AI-translated, pending native speaker review" header so the
follow-up native review stays targeted. Closes BL-11
(implementation half; native review remains an open
follow-up).

## Added

### 26A — Portuguese (pt-BR)

- ``backend/config/i18n/pt.yaml`` rewritten end-to-end:
  app + common + nav + import + curriculum + landing +
  onboarding + assessment + dashboard + session + progress +
  settings + methods + cycle_steps + errors + toast +
  install + about + backup + export + sync namespaces all
  translated to Brazilian Portuguese.
- Style: informal "você" form throughout. Common UI verbs
  use the imperative ("Salvar", "Cancelar", "Voltar",
  "Próximo"); learning-method nouns use standard Portuguese
  pedagogy terms ("Dedutivo", "Indutivo", "Dialógico",
  "Contextual").
- Assessment plugin's ``QUESTIONS`` list gains ``text_pt``
  on every one of the 12 question texts AND each of the 48
  answer texts. ``_LANG_TO_KEY`` adds ``"pt": "text_pt"``.

### 26B — Turkish (tr)

- ``backend/config/i18n/tr.yaml`` rewritten end-to-end with
  the same scope as 26A.
- Style: informal "sen" form throughout. Verbs in the
  second-person singular ("Kaydet", "Onayla", "Konuyu zaten
  bilen biriyle konuşurum"). YZ ("yapay zekâ") used as the
  Turkish abbreviation for AI in user-facing labels.
- 60 assessment ``text_tr`` translations + ``_LANG_TO_KEY``
  row added.

### 26C — Japanese (ja)

- ``backend/config/i18n/ja.yaml`` rewritten end-to-end with
  the same scope.
- Style: polite ``desu``/``masu`` form throughout, NOT
  keigo. Learning-method labels use standard pedagogical
  Japanese ("演繹的", "帰納的", "対話的", "文脈的", "AI 適応型").
- Two ``field_*_hint`` values quoted explicitly because
  their content contains a colon (``例: スペイン語 B1``) that
  YAML would otherwise interpret as a mapping separator.
- 60 assessment ``text_ja`` translations + ``_LANG_TO_KEY``
  row added.

### 26D — Translation quality audit

- New ``backend/tests/test_i18n_translation_audit.py`` (12
  tests) pins the v1.13.0 translation surface against
  drift:
  - ``test_no_en_passthrough_markers`` heuristically flags
    obvious English words ("the", "with", "from", etc.) as
    standalone tokens in pt/tr/ja values, with a small
    allowlist for brand names + technical tokens
    (Adaptive Learner, OpenAI GPT, ChatGPT, JSON, etc.).
    Tokens are replaced longest-first so "OpenAI GPT"
    matches before "openai" alone.
  - ``test_values_are_not_identical_to_en`` caps EN-identical
    values at 10% of each catalog (proper nouns + technical
    identifiers only).
  - ``test_assessment_questions_carry_text_lang_field``
    asserts every one of the 12 + 48 entries has a non-empty
    ``text_<lang>`` field for pt / tr / ja that differs
    from the EN counterpart.
  - ``test_lang_registered_in_assessment_lang_to_key``
    pins that the new languages are registered in the
    resolver map.

## Behaviour notes

- Translations are AI-authored by Claude using the model's
  own language knowledge — NOT through Google Translate,
  DeepL, or any external translation API. The header
  comment in each YAML records this and asks for native
  review.
- The resolver behaviour is unchanged: if a YAML key is
  missing for a given language, the frontend ``useI18n``
  hook still falls through to (1) hardcoded inline
  fallbacks for DE/EN/ES/FR/EL, then (2) the caller's
  supplied fallback, then (3) the dot-notation key itself.
  The new PT/TR/JA YAMLs are now complete, so nothing
  falls through under normal conditions.
- Assessment fallback semantics are unchanged: any code
  outside ``_LANG_TO_KEY`` (Korean, Hindi, etc.) still
  resolves to EN. The pin lives in
  ``test_partial_translation_falls_back_per_field``.

## Migration

No breaking changes. The wire shape of every endpoint is
unchanged. Users whose UI language is set to PT / TR / JA
will see translated strings on the next page load; users on
DE / EN / ES / FR / EL see no change.

## Closes

- **BL-11** (PT/TR/JA translations) — implementation half.
  Native speaker review remains a separate follow-up,
  filed under P3 in the ROADMAP. Any awkward phrasings
  reported by native users can be patched in-place; the
  audit tests will continue to catch regressions toward
