# Adaptive Learner v1.82.0

A learner-experience + infrastructure release on top of the v1.81.0 gamification
wave. It makes hints **cost something** (a hint economy with XP price, SRS
impact and statistics), rebuilds the **review queue** around real weakness
signals (weakness tiers, attempt history, cross-lesson mix, capped), adds a
discreet **PWA update prompt** so returning users get the newest build, and —
on the engineering side — introduces **Test Impact Analysis** so PR CI runs
only the tests an actual change can break (full suite stays on nightly +
release), plus an **architecture-documentation audit** that captures the Dexie
data-integrity and Settings-navigation patterns as rules. Backend gains two
additive Alembic migrations (`0030`, `0031`) on `element_errors`; the Dexie
schema is unchanged (new fields are schemaless).

6 substantive commits, 81 files.

## Added

- **Hint economy (#611, Refs #594).** Hints are no longer free: each revealed
  hint now has an **XP cost**, feeds back into the **SRS** (a hinted answer
  counts differently toward mastery), and is **tracked in statistics** so the
  learner sees how much they leaned on hints. Backed by additive
  `element_errors` columns (Alembic **0030**); both storage modes.
- **Smart review queue (#612, Refs #603).** The review flow is rebuilt around
  real weakness signals: errors are bucketed into **weakness tiers**, the queue
  carries **attempt history** per element, mixes items **across lessons**
  instead of replaying one lesson, and is **capped at 20** items per session so
  a review stays finishable. Backed by additive `element_errors` columns
  (Alembic **0031**); both storage modes.
- **PWA update prompt (#614, Refs #613).** The app now detects when a newer
  build has been deployed (a polled `version.json` plus a service-worker prompt
  mode) and offers a discreet "update available" prompt, so returning
  GitHub-Pages / PWA users stop running a stale cached build.

## Changed

- **Test Impact Analysis on PR CI (#617, Refs #615).** Pull-request CI now runs
  only the tests an actual change can affect — frontend via
  `vitest run --changed origin/<base>`, backend via `pytest --testmon` (with the
  `.testmondata` DB cached). Push to `develop`/`main`, the **nightly** run, and
  `make release-test` always run the **full** suite — the safety net against
  false negatives. Fallback to the full suite is automatic (unresolvable base
  ref / testmon cache-miss), never a silent skip. Plugin tests stay full
  (~37s).

## Docs

- **Architecture-documentation audit (#620, Refs #619).** Audited the
  architecture-doc set against the recent architectural decisions and closed the
  genuine gaps in `.claude/rules/architecture.md`: the **Dexie namespace module
  split**, the **Dexie data-integrity / read-modify-write discipline** (atomic
  `table.modify()` / `db.transaction("rw")`, unique indexes, additive forward
  migrations), and the **Settings navigation pattern** (one `SidebarGroup[]`
  model, two renderers, `?tab=` deep links). All other audited decisions were
  already documented.

## Tests

- **Manual test plan automated (#621, Refs #616).** 52 Playwright specs across
  7 sessions (onboarding, learning flow, content + repos, settings + backup,
  mobile, a11y, keyboard shortcuts) under `e2e/manual-automation/`, with page
  objects + helpers, an `playwright.manual.config.ts`, a Makefile target, and a
  scheduled `manual-automation.yml` workflow (nightly + `release/**` + manual
  dispatch). 50 scenarios run automated; the genuinely manual ones (iOS Safari
  zoom, "feel" of the flow, colour-blind checks) stay `skip`-marked by design.
- **recommended-repos discovery E2E reactivated (#610, Refs #547).** Un-`fixme`d
  the Dexie-smoke spec for the curated recommended-repository discovery flow.

## Before you install

AdaptiveLearner runs in Docker. You need Docker Desktop installed and running before starting the launcher.

- [Docker installation guide (English)](https://github.com/astrapi69/adaptive_learner/blob/main/docs/help/en/install/docker-desktop.md) - includes a "Is Docker safe to install?" section
- [Docker-Installationsanleitung (Deutsch)](https://github.com/astrapi69/adaptive_learner/blob/main/docs/help/de/install/docker-desktop.md) - mit Abschnitt "Ist Docker sicher zu installieren?"

The launcher detects Docker, downloads AdaptiveLearner automatically, and opens it in your browser. The first launch takes 5-10 minutes (Docker images build, ~2 GB disk space).

## Download

| Platform | File |
|----------|------|
| Windows | `adaptive-learner-launcher.exe` |
| macOS (Apple silicon) | `adaptive-learner-launcher-macos.zip` |
| Linux | `adaptive-learner-launcher-linux` (ELF binary) |

Each platform also ships a `*.sha256` checksum next to the binary.

## Verifying downloads

```bash
# macOS / Linux
shasum -a 256 adaptive-learner-launcher-<platform>
cat adaptive-learner-launcher-<platform>.sha256
```

```powershell
# Windows
Get-FileHash -Algorithm SHA256 .\adaptive-learner-launcher.exe
Get-Content .\adaptive-learner-launcher.exe.sha256
```

The hashes must match.

If your operating system warns about an unsigned binary, see the [AdaptiveLearner installation overview](https://github.com/astrapi69/adaptive_learner/blob/main/docs/help/en/installation.md).
