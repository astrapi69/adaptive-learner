# Adaptive Learner v1.36.0

**Released**: 2026-05-28

Phase 53 — **EXP-013 Adaptive Lesson Generation**. THE core
promise of the application: the system now ADAPTS to the
learner. Reads the per-element error history, identifies
weakness patterns, classifies them in language-specific
terms, and synthesises a personalised lesson on demand —
all rule-based, deterministic, no AI calls, works offline
on GitHub Pages.

## Why this release

v1.30.0–v1.35.0 built the foundation: element-level error
tracking, the SRS review queue, the cloze generator that
turns a mistake into a fill-in-the-blank, the token-diff
that visualises exactly what went wrong. Each piece on its
own is a partial solution to the "make practice targeted"
problem. v1.36.0 wires them together: a single
``/adaptive-lesson/:setId`` route that takes
``ElementError[]`` + cached content + the user's learning
profile and emits a synthetic ``ContentLesson`` the existing
viewer renders unmodified.

Before this release: the learner worked through
pre-authored lessons in a fixed sequence. After this
release: the system produces a personalised lesson
targeting the learner's specific weaknesses, using varied
exercise types, at appropriate difficulty.

The generation is rule-based for v1.36.0. AI-augmented
generation (EXP-013 Stufe 3: P-150–P-152) is deferred to a
future phase — the rule-based generator is sufficient for
the headline promise AND keeps the GitHub Pages deployment
working without an API key.

## Added

### Error analyzer with priority scoring + cluster detection (53A)

- **``frontend/src/lib/adaptive/error-analyzer.ts``** — pure
  function ``analyzeErrors(errors, opts?) → ErrorAnalysis``
  with:
  - ``prioritized_elements``: sorted by
    ``error_count × recency_weight``
  - ``error_clusters``: 3+ errors sharing element_type OR
    lesson_id
  - ``weakness_profile``: per-type share of total errors
  - ``suggested_focus``: top-N (default 3) for the Dashboard
- Recency bands per spec: <1d → 1.0, 1–2d → 0.8, 2–7d →
  0.5, older → 0.3
- Mastered + zero-error rows excluded
- Python mirror at ``backend/app/services/adaptive_lesson.py``
  — same algorithm, parity-pinned by a new JSON-fixture +
  golden suite at ``tests/fixtures/adaptive-lesson-parity/``
  (8 cases). Python is canonical; regen via
  ``ADAPTIVE_LESSON_PARITY_REGEN=1``

### Exercise pool builder (53B)

- **``frontend/src/lib/adaptive/exercise-pool.ts``** —
  ``buildExercisePool(targetElements, {lessons,
  errorsByElementKey?})`` walks every cached lesson for
  exercises that target the prioritized elements via
  card.front literal OR card.token_roles match. Same
  predicate the cloze generator uses, so pool semantics
  stay consistent with v1.35.0 review-synthesis behavior.
- Optionally augments with deterministically-generated
  cloze candidates (one per ``ElementError``) so the
  generator has shape-variant material.
- Difficulty estimates: picture_choice=1, matching=2,
  cloze-select=2, cloze-type=3, free_text=4, word_tiles=4.
- Deterministic: lessons walked in sorted lesson_id order
  regardless of Map insertion order.

### Rule-based lesson generator (53C)

- **``frontend/src/lib/adaptive/lesson-generator.ts``** —
  ``generateAdaptiveLesson(analysis, pool, opts) →
  ContentLesson``. Walks ``prioritized_elements`` cycling
  until ``max_exercises``, picking per-element the
  candidate whose type currently has the largest deficit
  against the configured ``exercise_type_mix``. Sorts by
  ``difficulty_curve`` (ascending / descending / mixed).
  Prepends a theory step REUSED from the dominant cluster's
  source lessons (no generation — pulls authored content).
- Default ``GeneratorConfig``: max_exercises 10,
  exercise_type_mix {matching:0.2, picture_choice:0.1,
  free_text:0.3, word_tiles:0.2, cloze:0.2},
  difficulty_curve ascending, variation_factor 0.7.
- Lesson id: ``adaptive-{set_id}-{ISO timestamp}`` — same
  schema as authored lessons, same viewer, same progress
  bar, same exercises. The viewer doesn't need to know it's
  a synthetic lesson.

### Variation logic (53D)

- Extends the lesson generator with:
  - **Literal-replay filter**: candidates whose
    ``(source_lesson_id, exercise.id)`` match the source
    ``ElementError`` are excluded. Generated cloze
    (synthetic id) survives so the cloze IS the variation.
  - **Type-deviation penalty**: same-source-type candidates
    pay ``variation_factor`` units of effective deficit, so
    fresh-shape candidates win over same-shape candidates
    at equal mix-deficit. ``variation_factor=0`` disables
    the penalty; ``variation_factor=1`` strongly prefers a
    different shape.

### Language-specific error classifier (53E)

- **``frontend/src/lib/adaptive/error-classifier.ts``** —
  maps each ``ElementError`` to zero or more semantic tags:
  - ``article_gender``: swap within a closed article set
    (FR le/la/les, ES el/la/los/las, DE der/die/das, EN
    the/a/an), OR card.token_roles tags element as
    ``article``
  - ``spelling_accent``: NFD-normalised diacritic-strip
    equality
  - ``verb_conjugation``: card.token_roles tags element as
    ``verb``
  - ``word_order``: source exercise is type ``word_tiles``
- Helpers: ``classifyError`` (single row),
  ``classifyClusters`` (cluster enrichment),
  ``focusAreaTags`` (chips for the Dashboard widget).
- **P-140 tag persistence** (Alembic + Dexie schema bump +
  sync surface) is **deferred** — tags are deterministic
  from existing fields, so storage is an optimisation, not
  correctness. When the persistence track lands, this
  classifier becomes the canonical assignor.

### Dashboard FocusAreasCard (53F / F-114)

- New ``frontend/src/components/dashboard/FocusAreasCard.tsx``
  reads active ``ElementError`` rows, runs the analyzer,
  classifies focus tags, renders the user's top focus
  elements with mastery progress (correct_streak / 3) and a
  primary CTA "Start adaptive lesson" linking to
  ``/adaptive-lesson/{set_id}``.
- States: loading / empty (returns null, parallel to
  ReviewQueueCard) / ready. Failure-tolerant.
- i18n keys in all 8 catalogs under ``dashboard.focus_areas.*``
  + ``dashboard.focus_areas.tag.*``.
- Mounted in Dashboard.tsx above ReviewQueueCard.

### Adaptive lesson page + flow (53G / F-115, F-116)

- New route ``/adaptive-lesson/:setId`` and matching
  ``useAdaptiveLesson`` hook. The hook pipelines: storage
  ``elementErrors.list`` → ``analyzeErrors`` →
  ``contentLoader.listSets`` → ``contentLoader.getLesson``
  per referenced lesson → ``buildExercisePool`` →
  ``generateAdaptiveLesson`` (with variation logic).
- **Transparency display (F-115)**: before the first step
  the user sees a chip row of tagged focus areas + a
  human-readable count of source errors. Never a black box.
- **Improvement indicator (F-116)**: the summary screen
  reads ElementError again after the session ends and shows
  "+N elements mastered this session!" when the mastery
  delta is positive.
- Five status branches: loading, empty (no active errors),
  not-cached (set not downloaded), error, ready. Same
  layout shell as the Review page; ExerciseDispatcher
  renders the steps unchanged.

## Architectural notes

### Why rule-based for v1.36.0

The Phase 53 spec explicitly defers AI-augmented generation
(EXP-013 Stufe 3: P-150–P-152) to a later phase. Reasons:

1. **GitHub Pages must work without an API key**. The
   public deployment at
   ``https://astrapi69.github.io/adaptive-learner/`` is the
   first impression for prospective users; gating the
   headline feature behind a paid API key would lock most
   visitors out of the core value proposition.
2. **Deterministic generation is testable**. Same inputs +
   same now-timestamp produce the same lesson. Cross-language
   parity (Python + TypeScript) is pinned by JSON goldens.
3. **The rule-based generator is sufficient**. The
   pedagogical signal — "this learner struggles with
   article_gender; here are 10 exercises drilling articles
   in varied forms" — doesn't need AI to produce. AI is
   most valuable in EXP-013 Stufe 3 for *explaining* the
   pattern to the learner in natural language, not for
   *generating* the practice itself.

When AI-augmented generation lands in a future phase, the
existing pipeline doesn't need to change — only the pool
gains an optional "AI-generated alternative" branch and the
classifier gains an optional "AI-deduced pattern" branch.
The synthetic lesson keeps the same shape.

### What's deferred

- **P-140 (Tag-Schema persistence)**: error_tags column on
  ElementError + Alembic migration + Dexie schema bump +
  sync surface entry. Tags are deterministic from existing
  fields so storage is an optimisation, not correctness.
- **P-150–P-152 (AI-augmented generation)**: AI pattern
  analyzer, AI explanation generator, AI-generated
  exercise variants for new contexts. EXP-013 Stufe 3.
- **Per-exercise difficulty ratings** authored on the
  content side (the generator estimates from
  ``exercise.type`` today; explicit ratings would tune
  this).
- **``related_cards`` cross-references** between cards in
  different lessons.
- **Sentence-context variation** from card.notes example
  sentences.

These all become natural follow-ups once the v1.36.0
foundation is in production.
