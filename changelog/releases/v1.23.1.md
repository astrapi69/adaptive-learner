# Adaptive Learner v1.23.1

**Released**: 2026-05-23

Patch release. Fixes two manual-test regressions reported
against v1.23.0 plus three UX improvements that landed on
the same user-feedback thread.

## Fixed

### Bug 6 — Contextual tooltips were missing on every post-onboarding route

v1.23.0 shipped the Phase 38 help system (`HelpTooltip` +
`HelpDrawer` + `HelpProvider` + glossary content) but
mounted `HelpTooltip` only on the Onboarding page. Every
post-onboarding route (Dashboard, Session, Curriculum,
Settings, Progress, Import, ImportDetail, Anki,
Pronunciation) had zero tooltip mounts. Users who skipped
the Onboarding form (the most common path) never saw a
single dotted-underline term and reported "tooltips
missing".

Fix: wrap key glossary terms in card titles + headings.
Dashboard (5 cards): Learning profile, Sessions, XP & Level,
Method distribution, Spaced practice. Session h1, Curriculum
h1. Each tooltip-wrapped term coexists with the existing
HelpLink "?" icon — the icon stays as the obvious-affordance
fallback per the HelpLink docstring.

### Bug 7 — "Continue session" felt like a wizard/setup screen even after the resume plumbing fix

a781c59 (the original v1.23.0 fix) wired the resume path
correctly at the API + state-machine level: clicking
"Sitzung fortsetzen" navigated to `/session?session=<id>`,
fetched the existing session record + chat history, and
skipped the `start()` call that would have created a fresh
session. The Vitest pin added in this patch (`Session.tsx
> "resume mode: ?session=<id> fetches the existing
session, no new start"`) proves this works end-to-end at
the component level.

What remained: the **system-prompt message** was still
rendered as the first chat bubble in every session — both
fresh and resumed. The system prompt is metadata for the
AI orchestrator (`"Du bist ein deduktiver Lernbegleiter..."`),
not user-facing content. Users saw an instruction-text
bubble they never wrote and didn't expect to see; on a
resumed session with no prior message exchanges (or where
the exchange history was very short) the chat looked
indistinguishable from a fresh "wizard" setup screen.

Fix: filter messages with `role === "system"` out of the
rendered list (`visibleMessages = messages.filter(m =>
m.role !== "system")`). The underlying `messages` array
still carries the system entry so the next `/message`
POST sees the chronological history; only the rendered
list changes. When `visibleMessages` is empty but
`messages` is non-empty (just-started or resumed-
pre-first-exchange), a welcome empty-state surfaces:
"Ready to learn! Write your first message." /
"Bereit zum Lernen! Schreibe deine erste Nachricht."

## Added

### Issue 3 — Help in navigation menu

The contextual help system shipped the drawer + the
HelpProvider + glossary content but never exposed a
top-level "Help" affordance — discovery was entirely
incidental (hover a HelpTooltip on a dotted-underline
term). Users who landed on Dashboard without spotting a
tooltip had no way to reach help.

Added: a `nav-help` button in the main Navigation
(desktop top bar + mobile hamburger drawer), positioned
after Settings, marked with the lucide `HelpCircle` icon.
Click opens the HelpDrawer in-place on the broadest
glossary entry (`learning_project`), which exposes the
related-concept chips so the user can navigate to other
entries. NO route change.

i18n: `nav.help` added to all 8 catalogs (DE: "Hilfe",
EN: "Help", ES/FR/EL/PT/TR/JA translated).

### Issue 4 — API-key guard before AI-dependent actions

Pre-v1.23.1 every AI-dependent action (Analyze, Start
Session, Extract Anki, Generate Pronunciation phrase,
Dashboard Quick Start) shipped without a pre-flight key
check. Users clicked, the API returned 400 "User has no
stored API key for provider 'X'", and the error surfaced
as a generic toast. New users who skipped Onboarding and
users who switched providers without keying the new one
both hit this consistently.

Added:

- `hooks/useApiKeyStatus.ts`: module-level cache + subscriber
  notification keyed by `learnerState` userId. Fetches
  `GET /settings/{uid}` once, reads `has_<provider>_key`
  for the active provider, exposes `{ready, hasKey,
  activeProvider, refresh}`. `ready=false` means we
  don't yet know — buttons stay disabled. Failure path
  returns `ready=true + hasKey=false`. The imperative
  `refreshApiKeyStatus()` lets Settings drop the cache
  after a save and notify every mounted hook.

- `components/ApiKeyRequiredNotice.tsx`: inline warning
  component (default + compact modes) with a direct
  "Open Settings" link. Used above every gated button.

- Pages gated: ImportDetail (Analyze + Start Session
  when no activeSession + Extract Anki), Dashboard
  (Quick Start), Pronunciation (Generate phrase).

- Skip-onboarding banner on Dashboard: persistent
  (until-dismissed via
  `localStorage["adaptive-learner.api_key_banner_dismissed"]`)
  banner above Quick Start surfaces the next step
  with "Open Settings" + "Dismiss" CTAs.

i18n: `ui.api_key.*` block (required, open_settings,
skip_banner, skip_banner_dismiss, 5 feature sentinels)
in all 8 catalogs. DE handwritten, EN handwritten,
ES/FR/EL/PT/TR/JA EN-passthrough.
