# Adaptive Learner v1.44.0

**Released**: 2026-05-30

Minor release. **Phase 60 — Content Validation Pipeline +
Language-Pair Tree.** Content sets now know who they are *for*: a
French course written with English explanations is a different set
from one written with German explanations, and the Content Browser
shows each learner only the sets they can actually read. Sharing a
lesson now runs a quality gate (with an optional AI review), and the
community content repo gets CI that enforces the same rules.

## Added

- **Language pairs on every content set.** A set declares
  `target_language` (what the learner is LEARNING) and
  `source_language` (what they already SPEAK — the language the card
  backs, notes and theory are written in). Set ids encode the pair
  (`fr-a1-from-de`); an optional `title_native` carries the
  target-language title and an optional `path` points at the set's
  source-language directory. Schema bumped 1.1 → 1.2.
- **First German-source content.** New `de/fr-a1` and `de/es-a1`
  pilot sets — French and Spanish A1 explained entirely in German
  (greetings, numbers, articles / ser-estar).
- **Source-language Content Browser tree.** `/content` groups
  downloaded sets by source language → target language → CEFR level.
  Your app language is the primary source language (its sets show
  expanded under an "I speak: …" heading); every other source
  language collapses under "Other source languages". A new
  Settings → Learning control lets multilingual learners add extra
  source languages they also read.
- **Two-layer content validation before sharing.** *My Lessons →
  Share with Community* now runs a rule-based quality check first
  (schema, language pair, and minimums: ≥5 exercises, ≥2 exercise
  types, ≥1 theory step, free-text ≥2 accepted answers + distractors,
  matching ≥3 pairs, no empty cards). Below any minimum, the set
  can't be shared and the modal lists exactly what to fix.
- **Opt-in AI content review.** When the rule-based check passes and
  an AI key is configured, you can choose to have the AI check
  translation accuracy, distractor plausibility, grammar, level fit
  and cultural sensitivity. It is never automatic, requires explicit
  consent (lesson content is sent to your configured provider), shows
  per-suggestion **Apply** auto-fixes for translation/grammar issues,
  and never blocks sharing — the rule-based pass is the gate. A
  passing review adds an `AI-validated` line to the shared GitHub
  issue. Works in both storage modes (browser-direct in Dexie,
  `POST /api/content/validate-lesson` in API mode).
- **Content-repo CI.** A `validate-content.yml` workflow + a
  self-contained `validate_content.py` (mirrored in
  `docs/ci/adaptive-learner-content/`) re-run the same checks on every
  pull request to the content repo, so manual contributions can't
  bypass the in-app gate.
- New `content.tree.*`, `content.validation.*`,
  `content.ai_validation.*` and `settings.source_languages.*` strings
  in all 8 languages.

## Changed

- The bundled pilot content and the external content repo are
  reorganised into a single `sets/{source}/{target-level}/` tree,
  mirrored 1:1. The GitHub Pages build ships the whole tree under one
  bundled source so it matches the external repo exactly.
- The content authoring guide (EN + DE) documents language pairs, the
  source-language tree, and the two validation layers.

## Compatibility

- Backward compatible. Pre-v1.2 content without the new fields still
  loads: the old `language` key is accepted as `target_language` and
  `source_language` defaults to `en`. Dexie schema **v22** backfills
  the language pair onto already-cached set rows in place.
- Existing set ids changed from `language-fr-a1` to `fr-a1-from-en`;
  the live external content repo migration is pushed alongside this
  release.
