# Adaptive Learner v1.12.0

**Released**: 2026-05-21

Phase 25 — **Backup Compare UI.** Two backup files (or one
file plus the current state) can now be diffed in a visual
side-by-side view. Pre-restore previews replace the v0.7.0
row-count table with the full per-table delta — including
field-level diffs on every changed record — so users see
exactly what will change before clicking Restore. Closes
BL-10.

## Added

### 25A — Client-side diff engine

- ``frontend/src/lib/backup-diff.ts`` — UUID-keyed matching
  between two parsed ``BackupPayload`` objects produces
  per-table ``added`` / ``removed`` / ``changed`` /
  ``unchanged`` counts. Append-only tables
  (``learning_sessions``, ``session_messages``,
  ``progress_commits``, ``step_evaluations``,
  ``imported_*``, etc.) surface only added + removed;
  mutable tables additionally surface field-level diffs on
  rows present in both sides.
- ``HIGH_VOLUME_TABLES`` set (``session_messages``,
  ``imported_messages``, ``step_evaluations``) flags rows
  the renderer should collapse to a count summary instead
  of one-liner-per-record — otherwise a single import would
  fill the report with 5 000 noisy lines.
- Field blacklist drops ``updated_at`` from change
  detection so a fresh re-export of the same logical state
  doesn't surface every row as "changed".
- Chunked async processing yields between 1 000-row chunks
  via ``requestIdleCallback`` (with a ``setTimeout(0)``
  fallback for happy-dom + Safari) so 10 000+ record
  backups stay responsive. Optional ``onProgress`` callback
  per table for progress UI.
- Per-table previews: each table has a one-liner template
  (Spanish project → ``"Spanish (45 min/day)"``, session →
  ``"2026-05-18 deductive (step 4)"``, message →
  ``"[user] hello world"``); fallback to the raw id.

### 25B — BackupCompare component

- ``components/BackupCompare.tsx`` is the shared rendering
  surface for every compare entry point. Renders the diff
  as a sortable + filterable card list per table; each card
  expands to show added / removed / changed records; each
  changed record expands to a field-level diff table with
  old → new format. Green / red / amber / grey colour
  coding via the existing ``--success`` / ``--danger`` /
  ``--warning`` tokens.
- Controls: "Hide unchanged tables" filter (on by default —
  no point showing the long tail of zero-delta tables) and
  a sort selector ("Most changes first" vs "Alphabetical").
- Loading + error + empty states all rendered explicitly.
- ``BackupSection`` gained a "Compare Backups" sub-section
  with two file pickers + a "Use current state" shortcut so
  users can compare an old export against the live data
  without exporting twice.

### 25C — Pre-restore diff preview

- The existing restore flow's v0.7.0 row-count comparison
  table stays as the fast at-a-glance overview; the new
  ``BackupCompare`` view renders directly underneath it
  with ``hideExport`` set, surfacing the full per-table
  + field-level delta the user is about to commit.
- The Restore button label becomes
  ``"Restore ({{added}} added, {{updated}} updated)"`` once
  the diff completes — drawn from ``totals.added`` and
  ``totals.changed`` via a new ``onDiffReady`` callback on
  the BackupCompare component.
- The snapshot fetch (``storage.backup.export``) is
  fire-and-forget so a hanging network call never pins the
  Confirm button as disabled.

### 25D — Auto-backup slot comparison

- ``getAutoBackupPayload(id)`` helper in
  ``storage/auto-backup.ts`` returns the full backup
  payload for any rotated slot.
- Each auto-backup row in the Dexie-mode Auto-backup
  section gained "Compare as A" + "Compare as B" buttons.
  Clicking either feeds that slot into the Compare Backups
  surface above; the page scrolls into view so the user
  sees the slot fill in.
- Compare Backups is the single rendering surface — no
  per-mode forks — so the auto-backup compare reuses the
  same chips, expand behaviour, filter, sort, and Markdown
  export as the standalone compare.

### 25E — Markdown diff export

- "Export as Markdown" button on the Compare view (hidden
  when the component is embedded in the pre-restore
  preview).
- Output format pinned to the spec: header with
  ``Date`` / ``Backup A`` / ``Backup B`` / ``Delta``
  lines, summary table (zero-delta tables OMITTED),
  per-table sections (zero-delta also omitted) with
  Added / Removed / Changed subsections, field-level
  ``field: old → new`` lines, high-volume tables
  collapsed to a count summary, version watermark
  footer (``*Generated by Adaptive Learner v1.12.0*``).
- String values quoted + escaped for pipe characters;
  long strings + objects truncated at 80 chars so a
  single huge field doesn't dominate the report.

## Behaviour notes

- Diff is **read-only**. No data ever changes during a
  comparison; the engine compares two in-memory
  ``BackupPayload`` objects and produces a structured
  result for rendering.
- The pre-restore preview triggers a fresh
  ``storage.backup.export(userId)`` call to build a
  current-state snapshot — this is a real backup
  serialisation, not a stub. On networks where the export
  hangs (offline mode, slow API), the preview silently
  doesn't render and the legacy row-count table remains as
  the fallback view.
- Auto-backup slots that have been rotated out between the
  list render and the compare click surface an inline
  error ("Auto-backup is no longer available — it was
  rotated out.") rather than silently failing.
- ``session_messages`` and the other high-volume
  append-only tables stay flagged as ``high_volume: true``
  in the diff structure even though their UI rendering
  collapses to a summary — downstream consumers of the
  ``BackupDiff`` shape (future analytics? CI reports?) can
  still walk the full ``added`` array if they want to.

## Migration

No breaking changes. The ``BackupPayload`` wire shape is
unchanged. The legacy row-count comparison table in the
restore flow is preserved as the at-a-glance overview; the
new diff view renders below it. The auto-backup section's
Restore + Delete buttons are unchanged.
