# Adaptive Learner v1.76.0

Maintenance release: an exercise-renderer refactor that removes ~300 lines
of duplicated lifecycle code, a security-relevant consolidation of the
per-user backup/sync ownership check, two user-facing fixes (backup-button
unification, TTS Markdown stripping), and the CI fix that makes the
Dexie-mode gate reliable again. Frontend + backend-internal + CI; no schema,
API, or data-model change.

## Changed

- **Exercise renderers share one controlled-input lifecycle (#322).** A new
  `useControlledExercise` hook and a shared `ExerciseFooter` replace the
  hand-rolled answer/check/advance state that each of the five exercise
  renderers (FreeText, PictureChoice, Cloze, WordTiles, Matching) carried
  its own copy of. ~300 lines of lifecycle duplication and ~50 lines of
  footer duplication removed, zero behaviour change, zero test changes —
  confirmed by the visual-regression and axe a11y suites. Shipped as six
  individually-mergeable PRs (#323-#328).

- **Per-user ownership check deduplicated (#329 / #330).** `sync_service`
  and `backup_service` each carried a private copy of the "does this row
  belong to this user" check (plus a dict-record variant in backup), and the
  copies had drifted — a security-directional risk, since the check gates
  which rows a sync push accepts and which rows a restore inserts (a wrong
  `True` leaks a row across users; a wrong `False` drops a legitimately-owned
  row). Both are consolidated into one canonical pair in `sync_service`
  (`row_belongs_to_user` + `record_belongs_to_user`); backup imports them.
  The one real divergence (a present-but-`None` `user_id`) is resolved toward
  "trust the parent FK" — the safe direction for restore — and is latent on
  real data anyway (every mapped `user_id` column is non-nullable). New
  `test_ownership_check.py` pins every scope. Behaviour-preserving on all
  reachable data.

## Fixed

- **Both backup buttons now produce the identical file via one save path
  (#331 / #332).** The Danger-Zone "Backup erstellen" button used the
  low-level `triggerBackupDownload` (silent auto-download) while Settings >
  Daten > "Sicherung erstellen" used `saveBackupToDisk` (native save dialog +
  fallback). Both already fetched the same payload from the same endpoint, so
  the file content matched — but the two buttons behaved differently, and the
  split was an easy place for a real divergence to creep in. Danger-Zone now
  calls the same `saveBackupToDisk` helper. A new cross-component parity test
  (`backup-buttons-parity.test.tsx`) clicks both buttons and asserts identical
  output plus that neither uses the divergent download path, so the two can
  never silently drift again.

- **TTS no longer reads raw Markdown syntax aloud (#320 / #321).** The
  read-aloud feature stripped nothing, so it spoke `**`, `#`, list markers,
  and link syntax verbatim; the text is now cleaned before it reaches the
  speech engine.

- **Content-set download no longer 400s on the content repo's `domain_label`
  field (#333).** A set whose manifest carries a human-readable
  `domain_label` (e.g. `domain: psychology` + `domain_label: Psychologie`)
  was rejected wholesale by the `extra="forbid"` `ContentSet` model
  (`1 validation error for ContentManifest ... domain_label ... extra_forbidden`),
  failing the download with "Set konnte nicht heruntergeladen werden". The
  model now accepts `domain_label` as an optional display field. Long-standing
  (the field predates v1.75.0; surfaced when downloading the psychology set,
  the first to carry it), not a v1.76.0 regression. The Dexie/frontend parser
  already tolerated the field.

## Infrastructure

- **Dexie-mode E2E smoke gate runs in the Playwright container (#317 /
  #319).** The gate had been timing out: the Playwright browser download from
  `cdn.playwright.dev` hung from the GitHub runner (zero bytes, killed at the
  8-minute timeout on every retry), and a cache + retry approach could not
  help because the cache only fills after one successful download. The job now
  runs inside `mcr.microsoft.com/playwright:v1.59.1-noble` (browsers
  pre-baked, pulled from a registry the runner reaches reliably), with Node 24
  installed for engines parity. No CDN browser download at all.

- **Misconfigured `prettier-frontend` pre-commit hook removed (#316 / #318).**
  The `frontend/` tree has no prettier config, so the hook ran prettier
  *defaults* (2-space) against a 4-space codebase and rewrote whole files on
  every touch; CI already skipped it. Removed so a local commit no longer
  produces spurious whole-file reformats.

## Notes

- No schema / Alembic / Dexie migration. No API change. The backup wire
  format (`BACKUP_VERSION` 1.3.0) is unchanged; the ownership-check
  consolidation is behaviour-preserving on all reachable data and the backup
  Export -> Import round-trip was verified on real data per
  BACKUP-AKZEPTANZTEST.
