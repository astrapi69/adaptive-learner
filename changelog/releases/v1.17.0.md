# Adaptive Learner v1.17.0

**Released**: 2026-05-22

Phase 30 — **Anki Deck Export.** A new
``adaptive-learner-plugin-anki`` plugin extracts flashcard
candidates from completed sessions + imported conversations
via the existing ``ai_complete`` hook, surfaces them on a
new ``/anki`` page where the user reviews + accepts + edits
each card, and bundles the accepted set into an
Anki-compatible ``.apkg`` file CLIENT-SIDE (sql.js + jszip,
lazy-loaded). Closes BL-21.

## Added

### 30A — .apkg generator (client-side)

- ``frontend/src/lib/anki/apkg-builder.ts`` builds the
  Anki ``collection.anki2`` SQLite DB via sql.js + bundles
  it with the manifest into a ``.apkg`` ZIP via JSZip.
- ``apkg-schema.ts`` carries the DDL + the Basic and Cloze
  model definitions (derived from a known-good Anki 2.1
  export).
- sql.js + JSZip are **lazy-loaded via dynamic import** —
  the ~1 MB WASM blob is NOT in the main bundle and only
  downloads when the user clicks "Export as .apkg" for
  the first time.
- Cloze detection: scans ``{{cN::...}}`` markers and emits
  one Anki card per distinct ord; deduplicates repeated
  c-numbers; sorts ords ascending.
- Anki-compatible note checksum (FNV-1a 31-bit) +
  tag-string formatter (``" tag1 tag2 "`` with internal
  whitespace replaced by underscores).

### 30B — AI card extraction + AnkiCardSuggestion model

- ``AnkiCardSuggestion`` model + Alembic 0012 + Pydantic
  schemas (``AnkiCardSuggestionOut``, ``Create``, ``Update``).
- Sync surface: ``anki_card_suggestions`` MUTABLE direct
  scope (27 synced tables).
- ``card_extraction.py``:
  - ``build_prompt`` renders a JSON-emitting prompt against
    the user's content (8000-char cap so a long session
    transcript still fits any modern LLM's context).
  - ``parse_response`` tolerantly parses the AI output:
    strips ``json``-fenced code blocks, skips invalid card
    types + empty fronts, normalises tags to lowercase
    strings, returns empty list on JSON-parse failure
    rather than crashing the route.
  - ``extract_from_session`` + ``extract_from_conversation``
    inject the AI caller (route-resolved with active
    provider + decrypted key + model) so the extraction
    service stays framework-free + testable.
- ``AnkiPlugin`` with routes under
  ``/api/plugins/anki/cards/*``:
  - ``GET /cards/{user_id}`` (filter by project + accepted
    + include_rejected)
  - ``POST /cards`` (manual insert)
  - ``PATCH /cards/{id}`` (inline edit + accept/reject;
    mutually exclusive)
  - ``DELETE /cards/{id}``
  - ``POST /cards/extract/session/{session_id}``
  - ``POST /cards/extract/conversation/{conversation_id}``
  - ``POST /cards/mark-exported`` (bulk)
- Extraction is **user-triggered** (per spec: "AI card
  extraction is a SUGGESTION — user always reviews
  before accepting") — no auto-fire on session-end.

### 30C — Export UI

- New ``/anki`` route + ``AnkiPage`` component:
  - Card list with type badges (Basic / Cloze)
  - Filter by project + accepted-only
  - Per-card actions: Accept / Unaccept / Edit (inline
    front/back/type) / Reject / Delete
  - Tag chips
  - Stats line ("{accepted} of {total} accepted")
  - Export button: lazy-imports ``apkg-builder``,
    generates the .apkg, triggers browser download,
    bulk-marks the exported cards with ``exported_at``,
    surfaces success toast with card count + filename.
- Navigation gets an "Anki" link (``nav.anki`` i18n key).
- CSS for the page + card grid + accepted-tile accent +
  tag pills.
- 3 Vitest smoke tests (empty state, accept flow,
  accepted-only filter) running against the Dexie backend.

### 30D — Vocabulary extraction for language learners

- ``_cards_from_vocabulary`` in both Python (backend)
  and TypeScript (frontend) — byte-compatible transform
  of ``[{word, translation, example, phonetic, tags}]``
  entries:
  - With example containing the word → cloze card
    (``{{c1::word}}`` in the example).
  - Without example → basic card (word / translation).
  - Phonetic, if present, appended to the back.
  - Auto-adds the ``vocabulary`` tag.
- ``ConversationAnalysisResult.vocabulary?: VocabularyEntry[]``
  added to the TypeScript domain types so callers can
  consume the field directly.
- ImportDetail page gets an "Extract Anki cards" button
  next to the existing Re-analyze + Create-curriculum
  buttons; non-fatal toasts on success / empty / failure.
- The conversation extractor PREFERS the vocabulary
  path (no AI call, no provider key needed) and falls
  through to the AI extractor only when vocabulary is
  absent.
- 6 plugin-side tests pin the vocabulary transform
  (cloze + basic + phonetic + malformed + case
  insensitivity).

## Migration notes

Alembic 0012 is a clean-add of the
``anki_card_suggestions`` table (4 indexed FKs,
ondelete=SET NULL on the conversational FKs so a
deleted conversation doesn't take its suggestions
with it).

Existing installs run ``alembic upgrade head`` once.
No backfill needed. Users see an empty Anki page until
they trigger their first extraction.
