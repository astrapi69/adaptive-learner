# Adaptive Learner v1.35.0

**Released**: 2026-05-28

Phase 52 — **EXP-007 Token-Diff + Cloze Exercise Type**.
Wires token-level visual feedback into every existing
exercise feedback surface, adds a fifth exercise type (Cloze
/ fill-in-the-blank) that auto-generates from a learner's
specific mistakes, ships a lesson-end correction round that
drills exactly the words the learner missed, and extends
review sessions to vary the shape (cloze for free-text +
word-tiles errors) instead of pure replay.

## Why this release

v1.30.0–v1.34.0 built the content + SRS engine: per-element
error tracking, the review queue, lesson-XP parity, the
Learning Repository, pilot content. The infrastructure
recorded WHAT the learner got wrong with high fidelity but
the wrong-answer surface was thin — a bare "the expected
answer was X" line, with no visible diff between user input
and canonical. Review sessions replayed the same exercise
verbatim, exercising memory of the format more than the
underlying knowledge. The end-of-lesson summary celebrated
progress but offered no targeted practice on the specific
mistakes.

v1.35.0 turns those three thin spots into a learning loop:
- See exactly what you got wrong (Phase 52A + 52B + 52C —
  token-diff + visual highlighting).
- Drill exactly that specific mistake at the end of the
  lesson (Phase 52F — correction round).
- See the same knowledge in a different shape next time it
  comes up in review (Phase 52G — cloze in review).
- Author hand-tuned cloze content with optional grammatical
  role hints (Phase 52D + 52I + 52H — schema + pilot
  content).

## Added

### Token-diff + visual feedback (52A + 52B + 52C)

- **Token-diff algorithm** (``frontend/src/lib/exercises/token-diff.ts``).
  Word-level diff between two strings using LCS + collapse-
  to-replace, NFC-normalized + case- and accent-sensitive,
  with a "completely different / no anchor → emit raw
  deletes + inserts" branch that keeps "foo bar" vs "baz
  qux" from collapsing into nonsensical replace pairs.
- **DiffHighlight component** (``frontend/src/components/exercises/DiffHighlight.tsx``).
  Inline renderer with four-signal accessibility (colour +
  icon + decoration + aria-label) so the surface stays
  usable for colourblind + screen-reader users. WCAG 2.1
  SC 1.4.1.
- **Wired into 4 feedback surfaces**: FreeTextExercise +
  WordTilesExercise render the diff below the wrong-answer
  result paragraph; LessonSummary's per-exercise breakdown
  renders the diff against the canonical for any free-text
  or word-tiles attempt where the stored ``user_answer`` is
  available. Matching + picture-choice keep their existing
  visual feedback (a diff between left/right tiles or image
  choices isn't a meaningful token-level abstraction).
- **8 i18n catalogs** updated: the wrong-answer
  ``result_wrong`` strings drop the ``{answer}`` interpolation
  and become a short headline (``"Not quite."`` etc.). The
  diff visualization conveys the canonical without the
  inline string.

### Cloze exercise type (52D)

- **Schema version 1.0 → 1.1**. ``ExerciseType.CLOZE = "cloze"``
  extends the closed enum; ``Exercise`` gains optional
  ``sentence`` / ``blanks`` / ``cloze_mode`` fields.
- **ClozeBlank model**: per-marker ``accept`` list (reuses
  free-text's NFC + Levenshtein-≤-1 matcher) + optional
  ``hint`` + ``placeholder``.
- **ClozeExercise renderer** with two modes: ``"type"``
  (default — ``<input>`` per blank) and ``"select"``
  (``<select>`` per blank, options shuffled by stable seed).
  Marker-based author convention: the sentence carries
  visible ``___`` tokens; ``blanks[i]`` provides the
  metadata for the i-th marker. Validator pins
  ``sentence.count("___") === blanks.length`` at
  schema-validate time.
- **Per-blank SRS fan-out** via ``deriveClozeAttempts`` —
  one ElementAttempt per blank, ``element_key =
  blank.accept[0]``, so per-blank mastery tracking lights
  up cleanly when one blank is consistently missed and
  another is consistently fluent.
- **Dispatcher** routes ``ex.type === "cloze"`` to the new
  renderer; the defensive coming-soon placeholder still
  fires for further future types.

### Cloze generator (52E)

- ``generateClozeFromError(error, sourceExercise, sourceCard)``
  in ``frontend/src/lib/exercises/cloze-generator.ts``.
  Synthesises a Cloze exercise from a recorded
  ElementError + (optional) source card. Deterministic —
  same inputs produce byte-identical output. No
  randomness, no AI, no async.
- **Algorithm precedence**:
  1. Card-based with ``token_roles`` match — highest
     fidelity, the author explicitly annotated the role.
  2. Card-based literal — ``sourceCard.front`` contains the
     correct answer exactly once.
  3. ``free_text`` prompt — the source prompt contains the
     answer exactly once.
  4. Null — caller falls back to replay.
- Single-marker invariant: rejects haystacks where the
  target appears more than once (the i↔i blank mapping
  would be ambiguous).

### Lesson-end correction round (52F)

- ``CorrectionBlock`` mounts inside the LessonSummary
  between the score / breakdown and the action buttons.
  On mount it loads ElementError rows for the just-
  finished lesson, generates a cloze for each non-
  mastered failure (cap 5, configurable), and walks the
  user through them.
- Each completed cloze writes fresh ``ElementAttempt`` rows
  against the same element_key the original failure was
  recorded against, so SRS streak + mastery advances.
- Self-hides on perfect score / no errors / no
  cloze-constructable errors / anonymous run. Best-effort
  IO: any failure silently degrades the block.
- 7 new i18n strings per language in all 8 catalogs.

### Cloze in review sessions (52G)

- ``synthesizeReviewLesson``'s per-item branch
  (``_buildReviewStep``) now picks: free_text or word_tiles
  source → try cloze, replay on null; matching /
  picture_choice / cloze → always replay. Cloze step ids
  start with ``review-cloze-``; replay step ids start with
  the existing ``review-`` prefix for traceability.

### Token-roles on cards (52I)

- Optional ``token_roles: list[{token, role}]`` annotation
  on Card. Closed enum of seven roles: article / verb /
  noun / adjective / preposition / gender_marker /
  tense_marker. The cloze generator uses these to target
  semantically-meaningful blanks instead of relying on
  substring matching. Adding a role is a minor
  schema_version bump.

### Pilot content (52H)

- Three hand-authored cloze exercises added to existing
  pilot lessons (no new lesson files):
  - **FR A1 L03** (Articles): "Je vois ___ chat dans le
    jardin." (un)
  - **FR A1 L04** (Être/Avoir): "Elle ___ une amie." (a)
  - **ES A1 L04** (Ser/Estar): "Yo ___ estudiante." (soy)
- Set manifest versions bumped: fr-a1 1.1.0 → 1.2.0,
  es-a1 1.0.0 → 1.1.0. ``schema_version`` bumped to 1.1
  in both. Content-loader's version-reconciled cache
  invalidates old copies on the next refresh.

## Fixed

- **AI session chat now renders Markdown** (UX-critical fix
  folded into this release per the v1.35.0 commit train).
  Pre-fix, AI responses showed raw asterisks for ``**bold**``,
  raw pipes for tables, raw hyphens for lists, raw ``###`` for
  headings — the assistant bubble was a ``<pre>`` block. Now
  wraps the assistant-bubble content in the existing
  react-markdown + remark-gfm pipeline (the same one HelpDrawer
  + LessonViewer use); user messages stay as-typed in ``<pre>``
  so the user sees their input verbatim. GFM tables wrap in a
  horizontally scrollable container so wide tables don't push
  the bubble off-screen on narrow viewports.

## Changed

- Frontend ``LessonStepResult`` / ``LessonStepResultStored``
  schema gains optional ``user_answer: string | null``. The
  Dexie and API storage paths persist it for free-text +
  word-tiles (the two types where the user's whole answer
  is a coherent text string). Backend Pydantic
  ``StepResultIn`` mirrors. Backward-compatible — old rows
  surface as ``undefined`` and the summary falls back to
  the canonical-only line.
- ``CURRENT_SCHEMA_VERSION``: 1.0 → 1.1 in
  ``plugins/adaptive-learner-plugin-content-loader/
  adaptive_learner_content_loader/models.py``. Major-version
  match keeps v1.1 lessons loadable on v1.0 apps at the
  manifest level; per-exercise rejection by the closed
  ExerciseType enum is the intended clean break for cloze
  steps.
- Backend service ``lesson_progress.upsert`` now merges
  ``user_answer`` into the ``step_results`` JSON map when
  the client sends one. Backward-compatible — the
  ``LessonProgressOut`` shape stays ``dict[str, Any]``.

## Configuration

No new environment variables. No new YAML keys. No new
plugin settings. The cloze feature ships entirely on top of
the existing content-loader plumbing.

## Upgrading

- **From v1.34.0**: drop in the new release. ``make sync-versions``
  has propagated 1.35.0 across the 18 version-bearing files.
  Existing lessons stay v1.0 — no migration needed; the
  optional fields are opt-in. The lesson-summary diff
  display gracefully degrades on pre-v1.35.0 rows (no
  ``user_answer`` recorded → canonical-only fallback).
- **From v1.30.0+**: same. The ElementError schema is
  unchanged; the v1.35.0 cloze generator + correction
  round consume the existing rows.

## Known issues

- The Phase 52G review-branch only generates cloze for
  free_text + word_tiles items. matching + picture_choice
  always replay. A future phase could explore inverse-cloze
  (turning a cloze into a matching exercise for variety),
  but that's out of scope for v1.35.0.
- The Phase 52F correction round caps at 5 clozes. Users
  with many wrong attempts will see the same 5 every time
  until they master them. The deferred review queue at
  ``/review`` is the path for "drill the rest" — by
  design.
- Cloze generation is offline-deterministic only. No AI
  augmentation, no semantic understanding, no synonym
  expansion. Authoring tools with AI generation are a
  separate track.
