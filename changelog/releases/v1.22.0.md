# Adaptive Learner v1.22.0

**Released**: 2026-05-22

Phase 37 — **Error-Toast + GitHub Issue Report Framework**.
User-facing failure path: error toasts now carry a "Report Issue"
button that opens a Radix dialog with a pre-filled GitHub issue
URL containing the error, optional environment info, and an
opt-in sanitized action history. No new domain features; one
extension to the existing exception-handler chain (5xx in DEBUG
mode now embeds stacktrace + endpoint + method in the response
body) plus a new in-memory event recorder on the frontend.

## Why this release

v1.21.1 stabilized the import + analysis surface from real
manual smoke-testing. The next gap surfaced by that round of
testing was the failure path itself: when something broke, the
user saw a generic toast and had no actionable way to file a bug
report. v1.22.0 closes that gap. The framework is borrowed from
Bibliogon's canonical implementation, adapted to adaptive-learner's
conventions (existing `AdaptiveLearnerError` hierarchy, the Phase 36
`{persistent: true}` toast option, the 8-language i18n catalog,
the project's CSS variable palette, the existing centralized
`apiCall` helper).

## What changed

### Backend — DEBUG-gated 5xx stacktrace (commit 7d7dc33)

`AdaptiveLearnerError` handler in `backend/app/main.py` now
embeds `stacktrace` + `endpoint` + `method` in the JSON response
when `ADAPTIVE_LEARNER_DEBUG=true` AND the status is >= 500.
4xx responses stay clean (no stacktrace — they are not bugs and
the extra payload would only add noise to the toast). The
Phase 36 `extra` merge (e.g. `existing_id` on a 409 duplicate
import) continues to work alongside the new fields.

The generic `Exception` handler already carried these fields;
this commit aligns the typed-domain-error path so a 5xx
`ExternalServiceError` (Anthropic / OpenAI / Gemini timeout,
plugin crash) lands with the same actionable context as an
uncaught exception.

### Frontend — Error-report framework (commit 0c71ef5)

Four new modules + three extensions to existing ones:

- **`utils/eventRecorder.ts`** (new). 100-entry RAM-only ring
  buffer for clicks, navigation, API calls, API errors, toasts,
  uncaught errors, and unhandled rejections. Sanitizer redacts
  values for fields matching `password|token|api.?key|secret|`
  `license|credential`, strips URL query parameters from
  endpoint + navigation `to` fields, and truncates text +
  messages at 200 characters with a `"..."` marker. Nothing is
  persisted; nothing leaves the tab without explicit user
  consent via the dialog's opt-in checkbox.
- **`utils/clipboard.ts`** (new). Safe boolean-returning
  wrapper over `navigator.clipboard.writeText` so callsites can
  surface a success/failure badge instead of try/catch.
- **`utils/notify.ts`** (extended). `notify.error` now renders
  an `ErrorContent` React element with an inline "Report Issue"
  button. The button dispatches an
  `adaptive-learner:open-error-report` custom event carrying
  the error message and optional `ApiError`. Phase 36's
  `{persistent: true}` option is preserved; the new
  `{apiError}` field rides on the same options object so
  existing callers keep working unchanged. Toast text uses
  `overflow-wrap` + `word-break` + `maxWidth: 100%` so long
  SQL errors or stacktraces never blow out the container
  width (mandatory layout contract).
- **`components/ErrorReportDialog.tsx`** (new). Radix-Dialog
  modal with three opt-in checkboxes (error + stacktrace
  always-on, environment info default-on, action history
  default-on), a free-text "steps to reproduce" textarea, a
  preview toggle, copy-to-clipboard, and a URL-length trim loop
  that drops the report body in 20% steps until the encoded
  GitHub URL fits below ~8000 chars. Submit opens
  `github.com/astrapi69/adaptive-learner/issues/new` in a new
  tab with `labels=bug`.
- **`components/EventRecorderSetup.tsx`** (new). Invisible
  component mounted once at the App root. Captures button + link
  clicks (label + testid), route changes via `useLocation`,
  uncaught errors, and unhandled promise rejections.
- **`api/client.ts`** (extended). `ApiError` gains an auto-set
  ISO 8601 `timestamp` field (set in the constructor; the
  dialog embeds it in the issue body so developers can
  correlate against backend logs). `apiCall` now records an
  `api_call` event on every successful + non-2xx response
  (method, endpoint, status, durationMs) and an `api_error`
  event on network failures. Recorder loads via dynamic import
  to keep the module graph one-way.
- **`App.tsx`** (extended). State + custom-event listener
  wired around the existing route tree. `EventRecorderSetup` +
  `ErrorReportDialog` mount alongside the existing
  `ToastContainer` (no duplicate).

### i18n — 17 new keys × 8 catalogs (commit 7900062)

Every UI string in the error-report dialog is i18n'd under
`ui.error_report.*` (17 keys covering title, intro, the
"steps to reproduce" label + placeholder, the three checkbox
labels, the "view" toggle, privacy note, preview / hide /
copy / copied / failure states, "Open on GitHub" submit
label, close, and the URL-truncation marker).

- **EN + DE**: handwritten. German uses real umlauts
  (`Schließen`, `Beschreibe`, `Schlüssel`, `Längenbegrenzung`,
  ...) per the project's rules/lessons-learned.
- **PT + TR + JA**: native translations. The Phase 26
  `test_i18n_translation_audit` blocks EN-passthrough in these
  three; the strings were translated rather than left as
  English to stay green.
- **ES + FR + EL**: EN-passthrough (project pattern; these
  catalogs are on the deferred diacritic-coverage track and
  are not in `PHASE26_LANGS`).

`make sync-i18n` propagated the YAML changes to the matching
`frontend/src/data/i18n/*.json` bundles.

## Privacy contract (load-bearing)

Documented at length in `.claude/rules/lessons-learned.md` and
on every test file:

- Ring buffer is RAM-only, capped at 100 entries, cleared on
  tab close. No localStorage, no IndexedDB, no network egress.
- No keyboard input, textarea content, or editor content is
  ever recorded.
- Sensitive-named fields are redacted to `[REDACTED]` before
  entering the buffer (the sanitizer fires inside `add(...)`,
  not on read — so a future change that moves redaction to
  `getAll()` would fail the round-trip test).
- URL query parameters are stripped from both `endpoint` and
  navigation `to` before entry.
- The "include action history" checkbox in the dialog is
  OPT-IN. The user sees the formatted log via the "View"
  toggle before submission.
- The privacy note in the dialog is always visible.

## Migration

No schema changes. No new dependencies for end users (the two
new npm packages ship inside the static frontend bundle). No
Alembic migration. Existing dev databases work unchanged.

## Storage modes

Both API mode (FastAPI backend) and Dexie mode (browser
IndexedDB) work for every change. The error-report framework
sits above the storage layer; the only backend touch was the
DEBUG-gated stacktrace addition to the exception handler.
