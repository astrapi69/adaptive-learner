# Adaptive Learner v1.71.0

Minor release — clearer Matching result feedback, an Enter shortcut in
the lesson-end correction round, a systematic dark-theme button-contrast
fix, and two test-isolation/flake fixes. Frontend + test infrastructure;
no schema, API or data changes.

## Added

- **Matching results spell out your answer vs the correct one** (#191).
  After checking, a wrong pair no longer relies on colour alone: it
  shows **"Deine Antwort: …"** (red, with an X icon) and **"Richtige
  Antwort: …"** (green, bold, with a check icon) on separate, clearly
  readable lines; a correct pair confirms the link as a single
  **"A → B"** line (Lucide arrow, not a Unicode glyph) with a green
  check, and the number badge stays on both tiles. All colours route
  through the existing, WCAG-AA-pinned Matching feedback tokens across
  all 12 themes. The new strings (`your_answer`, reworded `correct_hint`)
  are translated in the eight supported languages (DE, EN, ES, FR, EL,
  PT, TR, JA).

## Fixed

- **Enter now works in the lesson-end correction round** (#187). The
  "Korrektur-Runde" (`CorrectionBlock`) ignored the Enter key: it ran
  its cloze uncontrolled with no shortcut wiring, and the parent lesson
  runner's listener is inert on the summary screen. The correction round
  now runs the cloze controlled with an external "Antwort prüfen" button
  and the shared `useLessonEnterKey` hook, so Enter checks the answered
  cloze exactly like the main runner and the error-replay runner — the
  three surfaces can no longer drift.
- **Buttons no longer go invisible in dark themes (systematic)** (#185).
  Earlier per-surface fixes (#146 / #148 / #177 / #179) each repaired one
  component; this addresses the architectural root cause. With Tailwind
  preflight off, a raw `<button>` with no author `color` fell back to the
  UA `buttontext` (≈ black) instead of the page foreground, so any
  un-coloured raw button read black-on-dark. A single `base`-layer
  default (`button { color: inherit }`) fixes the whole class while
  losing to every explicit `text-*` utility, so shadcn `<Button>`
  variants and intentionally-coloured buttons are untouched.
- **Cloze answer "7 ± 2" can now be typed without the ± glyph**
  (content #33). The Miller short-term-memory cloze accepted only the
  exact `±` form or a bare `7`; a learner typing a `+/-` form was marked
  wrong. The accepted-answer list is broadened with keyboard-typeable
  equivalents.
- **No more Chrome "password field not in a form" warning on the content
  repository token** (#119). The content-repo settings token input (a
  `type="password"` field added after the earlier #120 sweep) is now
  wrapped in a form.

## Tests / infrastructure

- **Content-loader cache is isolated between tests** (#164). The backup
  cross-identity round-trip test flaked under random ordering because the
  session-shared content cache leaked across tests; an autouse fixture
  now resets it before and after each test.
- **The lesson read-aloud Dexie-gate spec is stabilised** (#165). Its
  heavy setup (bundled-set download + lesson render) could exceed the
  30 s per-test cap on a loaded headless runner; the spec gets more
  headroom and an extra retry. The TTS engine itself is unchanged.
