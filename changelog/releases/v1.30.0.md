# Adaptive Learner v1.30.0

**Released**: 2026-05-27

Phase 46 sub-phases A-D — **Element-Level Error Tracking +
SRS Review Sessions** (EXP-007 / P-129). The first half of
the original Phase 46 spec; sub-phases E-F-G (gamification
+ session unification + docs) split to v1.31.0 per the
two-release plan agreed at sub-phase decision time.

The "adaptive" in "Adaptive Learner" now actually means
something. v1.30.0 closes the loop from "you got this
wrong" → "the app remembers WHICH word you struggled with"
→ "the app schedules it for review later" → "you re-see
it in a focused mini-lesson".

## Why this release

Before v1.30.0, lesson completion just recorded a per-step
score and stopped. The app had no concept of "Aster
struggled with 'merci' specifically" — only "Aster scored
6/10 on lesson 1 of the French set". That made the
expensive Content-Loader + viewer + exercise infrastructure
of v1.27.0-v1.29.0 less useful: a learner who repeated a
lesson would face exactly the same exercises in the same
order, with no signal about which elements deserved
attention.

v1.30.0 ships the missing ingredient: **per-element error
tracking with spaced-repetition scheduling**. Every wrong
answer in every exercise type writes an ``ElementError``
row keyed by the specific word / pair / phrase the user
missed. The Dashboard surfaces a "X elements due for
review" card. Clicking it opens a synthesised mini-lesson
that re-plays just those exercises in priority order. Get
the element right 3 times in a row → mastered → removed
from the queue. Get a mastered element wrong → demoted
back into the queue.

After v1.30.0 the next architecturally distinct unit is
v1.31.0 (Phase 46 E-F-G): hook lesson completions into
the XP / streak / badge / ProgressCommit surface so the
adaptive loop also feeds the gamification loop.

## What changed

### Added

#### Sub-phase 46A — Expanded Lesson Summary Screen

- ``computeStars(correct, total)`` utility: 0-3 star
  rating with bands at 50%, 75%, 90%. Mobile-friendly
  star row with ARIA semantics, ``data-earned`` per
  star, ``data-stars`` on the summary section.
- ``buildExerciseBreakdown(lesson, progress)`` projects
  per-step results into a per-exercise list: title +
  score + canonical-answer reveal for wrong rows + a
  ``fullyCorrect`` flag that's defensive against the
  unattempted 0/0 false-positive.
- LessonSummary component rewritten with three new
  affordances: per-exercise breakdown list, visual
  score bar, "Next lesson" / "Repeat" / "Back to
  content browser" buttons.
- 3-star CSS keyframe celebration animation that
  staggers across the three stars; respects
  ``prefers-reduced-motion``.

#### Sub-phase 46B — Element-Level Error Tracking

- New ``ElementError`` SQLAlchemy model + Alembic
  migration 0019. Composite UNIQUE on
  ``(user_id, set_id, lesson_id, exercise_id,
  element_key)``. Lesson-scoped element keys per D2
  decision (same word in two different lessons = two
  rows).
- Service module
  ``app/services/element_errors.py`` with the upsert
  transition matrix + ``MASTERY_THRESHOLD=3`` constant.
  Mastered → wrong demotes the element back into the
  review queue (a failed master is a forgotten
  master).
- POST + GET ``/api/users/{user_id}/element-errors``
  routes (bulk upsert + list).
- Dexie schema v18 + ``element-errors-dexie.ts``
  mirroring the backend service 1:1 so GH-Pages users
  get the same SRS feedback loop without a backend.
- ``IElementErrorsNamespace`` on IStorageService;
  ApiStorage + DexieStorage both wired.
- Per-exercise element-attempt derivers in
  ``lib/element-attempt.ts``: matching fans out one
  attempt per pair; picture / free-text / word-tiles
  produce a single attempt each. Element-type heuristic
  (vocabulary vs grammar_rule).
- All 4 exercise components updated to call the
  matching deriver and pass attempts via the extended
  ``onComplete({correct, total, attempts})`` contract.
- Lesson viewer's recordStepResult now persists element
  attempts alongside step results — failures wrapped
  in try/catch so SRS recording can't block step
  advancement.

#### Sub-phase 46C — SRS Review-Queue Scheduling

- ``app/services/element_srs.py`` with interval policy:
  streak 0 → 1d, 1 → 3d, 2 → 7d (mastered excluded).
  Priority sort: overdue first → error_count desc →
  last_error_at desc.
- GET ``/api/users/{user_id}/element-errors/review-queue``
  endpoint + ``ReviewQueueItemOut`` Pydantic schema.
- Dexie-side parallel via ``computeReviewQueueDexie``
  in ``element-errors-dexie.ts``.
- Dashboard widget ``<ReviewQueueCard>`` showing total +
  overdue counts + "Open review session" CTA. Hidden
  for users with empty queues so the dashboard grid
  stays tidy.

#### Sub-phase 46D — Review Session

- Pure utility ``synthesizeReviewLesson(queue, lessons,
  opts)`` builds an in-memory ``ContentLesson`` from
  the top-N due elements + their source lessons. Per
  D3 decision: replays the original exercises (no
  generation, no cloze, no AI). Items whose source is
  evicted from cache are silently dropped.
- ``useReviewLesson`` hook composes queue fetch + set
  resolution + lesson fetches + synthesis +
  session-score tally. Same discriminated-union
  status pattern as ``useLesson`` (loading / empty /
  not-cached / error / ready).
- ``/review/:setId`` route + page. Reuses the
  ExerciseDispatcher (extracted to its own module so
  both pages share it) so review exercises render
  identically to lesson exercises.
- Dexie-mode release gate extended to cover the new
  route (18 → 19 specs).

### Changed

- ``ExerciseDispatcher`` + ``ExerciseStepPlaceholder``
  + ``SUPPORTED_EXERCISE_TYPES`` moved from
  ``pages/Lesson.tsx`` into
  ``components/exercises/ExerciseDispatcher.tsx`` so
  the Review page can reuse them. Zero behaviour diff.
- Exercise component ``onComplete`` contract extended
  from ``{correct, total}`` to ``{correct, total,
  attempts: ElementAttempt[]}``. The 4 existing
  exercise test files migrated to
  ``expect.objectContaining({correct, total})`` so
  they don't break on the new ``attempts`` field.
- Lesson viewer page now reads ``learnerUserId`` via
  ``readLearnerState`` and runs
  ``elementErrors.recordBulk`` on every exercise
  submit.

### Decisions confirmed in this release

- **D1 (pseudo-project unification)**: NOT applied in
  v1.30.0; deferred to v1.31.0. ElementError stays
  decoupled from LearningSession (no FK).
- **D2 (lesson-scoped element keys)**: same word in
  two lessons = two rows. Cross-lesson element sharing
  is a future-phase concern.
- **D3 (review = replay)**: review sessions re-play
  the original exercises. No generation, no cloze, no
  AI in this release.
- **D4 (mastery threshold = 3)**: hardcoded
  ``MASTERY_THRESHOLD=3`` constant in both the backend
  service and the Dexie service. Documented as
  intrinsic to the SRS semantics, not a config knob.
- **D5 (no on_lesson_complete hook yet)**: follows
  D1's deferral — gamification + tracking integration
  ships with v1.31.0's session-unification work.

### What's deferred to v1.31.0 (Phase 46 E-F-G)

- **46E Gamification integration**: XP awards on lesson
  completion, new badge predicates ("First Lesson",
  "Review Master", "3-Star Streak"), the
  ``on_session_complete`` hook firing for lessons via
  the pseudo-project route.
- **46F LessonProgress ↔ LearningSession unification**:
  "Content Lessons" pseudo-project model + lessons
  appear in RecentSessions / Progress timeline / streak
  calendar.
- **46G Documentation + verification + full release**.

## Upgrade notes

- **Alembic 0019_element_errors** adds the
  ``element_errors`` table. A fresh ``make dev``
  picks it up automatically; deployed backends should
  run ``alembic upgrade head``.
- **Dexie schema bump v17 → v18** adds the
  ``elementErrors`` table. Existing GH-Pages users get
  the transparent schema upgrade on first load; no
  data loss.
- **No breaking changes** to existing namespaces,
  routes, or storage shapes. The extended
  ``onComplete`` contract on the 4 exercise components
  is additive — the new ``attempts`` field defaults
  to derived-from-content; tests that assert with
  ``objectContaining`` survive the change.
- ``ElementError`` is intentionally decoupled from
  ``LearningSession``. v1.31.0's pseudo-project
  unification adds a session row on lesson completion
  but does NOT change the element-tracking schema.
