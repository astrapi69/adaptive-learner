# Adaptive Learner v1.45.1

**Released**: 2026-05-30

Patch release. Documentation-sync and test-hardening only — no
runtime code changed, no schema or API change. Aimed at closing
the drift between the docs and the shipped reality after the
rapid Phase 43-61 release cadence.

## Added

- **Cross-language badge-catalog parity golden.** A new shared
  fixture `tests/fixtures/badge-catalog/catalog.json` (28 canonical
  entries: key + category + `base_tier` + `tier_thresholds`,
  generated from `badges.yaml`) is now asserted by BOTH the Python
  side (`badges.yaml`, in
  `plugins/.../tests/test_badge_catalog_parity.py`) and the
  TypeScript side (`BUNDLED_BADGES` in `badges-data.ts`, in
  `frontend/src/storage/badge-catalog.parity.test.ts`). Tier
  *evaluation* was already pinned cross-language
  (`tests/fixtures/badge-tier-parity/`); this pins the *catalog*
  itself, so a badge added — or a `base_tier`/threshold changed —
  on one side without the other fails the build instead of
  silently diverging API-mode and Dexie-mode users. (+1 backend
  test, +2 Vitest tests.)

## Changed

- **`docs/ROADMAP.md` refreshed.** The phase-history table had
  stopped at Phase 42 / v1.26.0 — 19 phases behind reality. Added
  rows for Phases 43-61 (v1.27.0 - v1.45.0) with title, date, and
  a one-line description each, and rewrote the stale "Next phases
  (planned)" section (which still named "Phase 43 candidate" and
  "BL-30 (Phase 42 candidate)") to point at the v1.46.0 candidate
  (Matching-exercise visibility + Word-Tiles drag-to-reorder).
  Phases 47-48 were never assigned (numbering jumped 46 -> 49);
  this is now noted in the table.

## Fixed

- Nothing in code. Two backlog items turned out to be already
  shipped and were archived (see below).

## Housekeeping

- **BL-23** (settings race condition) archived as already fixed in
  commit `bdb0696`: `get_or_create_settings` catches the
  `IntegrityError` from a concurrent first-access insert, rolls
  back, and re-reads the winner's row. Regression-pinned by
  `test_get_or_create_settings_survives_concurrent_first_access`.
- **BL-24** (E2E `GET /api/imports/{id}` matcher) archived as
  already fixed in commit `abc0d94`: the dev Service Worker's
  `NetworkFirst` rule was intercepting `GET /api/*` before
  Playwright; `test.use({serviceWorkers: "block"})` on
  `conversation-import.spec.ts` lets the GET mock fire and the
  spec now asserts the `analysis-results` card renders.
- Both moved from `docs/backlog.md` to
  `docs/roadmap-archive/2026-05.md`.
