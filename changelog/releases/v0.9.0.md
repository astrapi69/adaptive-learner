# Adaptive Learner v0.9.0

**Released**: 2026-05-20

Phase 12 — **Chat-history import and AI analysis**. Most
learners arrive at Adaptive Learner with a conversation history
already accumulated in ChatGPT, Claude, or Gemini. v0.9.0 makes
that history first-class: paste or upload, and the system
extracts structured learning insights — topic, strengths,
weaknesses, error patterns, recommended method, and a
suggested curriculum the user can spin up with one click.

## Added

### 12A — Import format parsers
- `frontend/src/chat_import/` module with four parsers and
  auto-detection:
  - **ChatGPT**: walks the `mapping` tree from `current_node`
    via `parent`, reverses, joins multi-part text content
    (including multimodal `{text}` blocks). Cycle-safe.
  - **Claude**: array or single-conversation shape with
    `chat_messages` + `sender` (human/assistant) + `text` or
    `content` blocks.
  - **Markdown / paste**: role-marker detection across
    `**You:**`, `Name:`, `## Name`, `> Name:` shapes
    including German Frage/Antwort. Always falls back to a
    single user-message so shapeless paste still produces
    analysis surface.
  - **Generic JSON**: `{messages: [...]}` envelope or bare
    array, with role aliases (human/claude/model normalised).
- `parseChatImport(input)` auto-detects via cheap shape sniffs
  and dispatches. `detectFormat(input)` lets the UI label the
  file before parsing.
- Defensive: malformed entries in a bulk import yield warnings,
  not aborts.

### 12C — Data model
- Two new SQLAlchemy models in `backend/app/models/`:
  `ImportedConversation` (user_id, project_id soft-FK with
  SET NULL, source, title, message_count, imported_at,
  analyzed, analysis_result JSON-as-text, topic_tag, model,
  source_created_at) and `ImportedMessage` (conversation_id
  CASCADE, role, content, timestamp, order_index).
- Alembic migration `0004_imported_conversations`.
- Pydantic schemas: `ImportedConversationCreate / Update /
  Analysis / Out / Detail`, `ImportedMessageCreate / Out`.
- Service module + router (`/users/{id}/imports`,
  `/imports/{id}` + `/imports/{id}/analysis`) with the
  cross-user-project guard pattern matching other routers.
- Dexie schema v2: `importedConversations` +
  `importedMessages` tables with indexes on `user_id`,
  `project_id`, `imported_at`, `source`, `analyzed`.
- New `IImportsNamespace` on the storage layer; both
  ApiStorage (thin delegator) and DexieStorage (full local
  implementation with cross-user-project guard) satisfy the
  same contract.

### 12D — AI analysis engine
- `chat_import/analysis.ts` ships
  `analyzeConversation({provider, apiKey, modelOverride,
  messages, title})` returning a structured
  `ConversationAnalysisResult`.
- System prompt requests strict JSON: topic, subtopics,
  user_level (beginner/intermediate/advanced), strengths,
  weaknesses, error_patterns, recommended_method (one of the
  six), recommended_focus, suggested_curriculum (lessons with
  priority 1-5), summary.
- Long transcripts chunk at `MAX_CHUNK_CHARS` (16 000 chars ≈
  4 000 input tokens) with 2-message overlap between
  consecutive chunks.
- `mergeAnalyses` folds chunk results: strings stay
  first-non-empty, arrays concat-and-dedupe, user_level keeps
  the highest seen (beginner → intermediate → advanced),
  curricula dedupe by title.
- `parseAnalysisResponse` strips markdown fences, extracts
  the first `{...}` block, clamps invalid enum values,
  returns null on any structural problem.
- `deterministicFallback` returns a valid result with
  `fallback_used=true` on any provider / parse failure so the
  UI never has to handle a bare-error path.

### 12B — Import page (/import)
- **Quick Analysis** (the primary surface): large textarea +
  Analyze button. Format detection runs as the user types
  (chatgpt / claude / generic / markdown / unknown). The
  button persists the conversation, fires the AI analysis
  against the active provider, navigates to the detail page.
- **File upload**: drag-and-drop + file-picker for
  `.json`, `.md`, `.txt`. Bulk ChatGPT / Claude exports
  produce multiple conversations from one file; the page
  imports them all and toasts the count.
- **Imports list**: source icon (🤖 / 🟣 / ✨ / ✍ / 📄), title,
  message count, date, Analyzed badge. Click row to open
  detail.

### 12E — Conversation detail (/import/:conversationId)
- Full transcript with user vs AI styling.
- Top action bar: Analyze / Re-analyze, Create curriculum,
  Start session.
- Analysis results render as tone-coded cards: Topic with
  level badge, Recommended method with focus, Strengths
  (green border), Weaknesses (red), Error patterns (amber),
  Subtopics, Suggested curriculum (wide card with priority +
  description).
- **"Create curriculum"** auto-builds a Curriculum + sorted
  LearningTopics from the `suggested_curriculum` list, then
  navigates to `/curriculum`. One click to go from "I had
  this chat" to "here is the structured learning plan".
- Fallback notice surfaces when the AI couldn't be parsed
  cleanly (`fallback_used`).

### 12F — Quick-paste as primary UX
- /import opens directly on the Quick Analysis paste box
  rather than a file-import wizard. The 80% case (paste a
  conversation, get insights) is one click; the file upload
  and existing-imports surface below for the 20% case.

## Notes
- The analysis call uses the same AI provider configured for
  learning sessions — no separate config. The user just
  needs an API key set in Settings.
- API keys live in IndexedDB in Dexie mode (browser-direct
  AI provider calls). ApiStorage cannot read cleartext keys,
  so the analysis trigger surfaces a "set an API key" hint
  on that path.
- Imported conversations carry the optional `project_id`
  soft-FK so users can later assign a conversation to a
  specific learning project. Project deletion sets the FK
  to NULL — the user's history outlives a single project.
