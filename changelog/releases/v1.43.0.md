# Adaptive Learner v1.43.0

**Released**: 2026-05-30

Minor release. The official community content repository
(`astrapi69/adaptive-learner-content`) now exists and is validated
end-to-end against the loader, so this release brings the Content
Browser online with it: same-id sets from the bundle and from GitHub
collapse into a single row, each card shows where its content came
from, and Share with Community is back.

## Added

- **Cross-source set dedupe.** The bundled pilot content (shipped in
  the GitHub Pages build) and the external GitHub content repo both
  advertise `language-fr-a1` / `language-es-a1` under the same set id,
  so the Set Browser used to list every set twice. Both storage modes
  now collapse same-id sets to one row: the higher version wins; on a
  version tie the external (GitHub) source is preferred over the
  build-time-frozen bundle; and when GitHub is unreachable only the
  bundled or cached entry survives, so the offline fallback stays
  intact. User-generated "My Lessons" entries are never collapsed.
- **Source badge on set cards.** Each downloaded set card now shows a
  small **Bundled** / **GitHub** pill so the origin of the surfaced
  version is visible at a glance. New `content.source.*` i18n in all 8
  catalogs.

## Changed

- **Share with Community re-enabled.** Now that the content repo
  exists, the **Share with Community** button on My Lessons cards is
  back. It opens a pre-filled GitHub issue on the content repo so a
  maintainer can review and add the lesson - no cloud backend, no
  account, no auto-publish.

## Fixed

- **Graceful handling when the content source is unavailable.** A
  per-source fetch failure (404 / network) on the Content Browser
  falls back to that source's cached rows and continues instead of
  throwing - `/content` shows the bundled pilots and a friendly empty
  state, never an error toast. (This degradation already worked; this
  release hardens and pins it, and removes the dead-repo 404 that the
  Share button used to hit before the repo existed.)

## Developer-facing

- **Documentation verification system.** New `scripts/verify_docs.py`
  drift verifier (version badges, plugin/test counts, theme-token
  parity, mkdocs orphan + dead-link checks, en/de help parity, i18n
  key parity) plus a `make verify-docs-discipline` aggregate. Releases
  and CI now gate on it: a stale README / ROADMAP / CLAUDE.md blocks
  the tag the same way a failing test does. New
  `scripts/generate_docs_checklist.py` prints a post-release docs
  to-do list from the changelog. Full reference in
  `docs/development/docs-verification.md`.
