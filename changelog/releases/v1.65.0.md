# Adaptive Learner v1.65.0

Minor release — **resumable assessment**, an **Enter-key lesson
shortcut**, **clearer matching exercises**, and a **design-token
architecture** pass that routes the last hardcoded colors through
tokens and enforces it with tests. No schema change; both storage modes
(API + Dexie / GitHub-Pages) carry everything.

## Added

- **Resumable assessment** (#106): abandoning the assessment partway no
  longer loses the work. The in-flight progress (current question,
  answers so far, start time) is persisted, the learner resumes exactly
  where they left off, and the Dashboard actively invites them to
  "Continue learning profile" (or "Create" when none exists). Settings >
  Learning offers a single context-aware action — resume / retake /
  create. Progress is project-scoped in localStorage (mode-agnostic, no
  backend round-trip) and cleared the moment the profile is computed.
- **Enter-key shortcut in lessons** (#103): Enter drives the two-phase
  lesson button — it checks an answered exercise, then advances to the
  next step; in free-text and cloze fields Enter submits the answer
  instead of inserting a newline. It steps aside for controls that own
  Enter (buttons/tiles, textareas), so there are no double-actions.
  Toggle in Settings > Learning > Interaction ("Lesson keyboard
  shortcuts", default on; off = buttons only).

## Changed

- **Design-token architecture** (#101): the remaining color literals in
  `global.css` (the danger-button text, the highlighter mark, the
  highlight.js syntax palette, a toast shadow) now route through design
  tokens, so a contributor re-themes the app by editing one
  `theme-*.css` file and touching no component. The `no-hardcoded-colors`
  guard is extended to non-theme CSS and to fixed-palette Tailwind
  utilities; new docs at `docs/DESIGN-TOKENS.md` + a `.claude` rule.
- **Matching exercises distinguish the two sides** (#108): the term and
  definition columns shared one background, so learners couldn't tell
  which side they were pairing (worst in the stacked mobile layout). The
  two sides now carry subtle, theme-derived tints (blue / green) plus an
  aria-hidden A / B letter chip, so the distinction is not colour-only.
  The tints are `color-mix()` over existing tokens, auto-adapting across
  all 12 themes; WCAG AA verified computationally.

## Fixed

- **Assessment profile layout overlap** (#105): on the result screen the
  radar chart's summary and "show data as table" link overlapped the
  "Preferred method" badge. `ProfileRadar`'s fixed-height container now
  lets the summary flow below the chart instead of overflowing, so the
  radar, badge, and actions stack cleanly — mobile included.
