# Adaptive Learner v1.6.0

**Released**: 2026-05-20

Phase 19 — **Streaming Learning Response.** The deferred 18D piece
from v1.5.0 ships in three parts: a new `ai_complete_stream` hook
in the plugin contract, a new `POST /message/stream` SSE endpoint
in the session plugin, and browser-direct streaming for Dexie
mode. The chat surface now renders tokens as they arrive instead
of waiting for the full completion — the biggest remaining
perceived-performance win after the v1.5.0 async work.

## Added

### 19A — `ai_complete_stream` hookspec + orchestrator

- New `ai_complete_stream` hookspec in `backend/app/hookspecs.py`.
  Same signature as `ai_complete_async`; returns an async
  iterator yielding text deltas. `firstresult=True` — exactly
  one provider plugin answers per call.
- `call_ai_complete_stream` in
  `adaptive_learner_session.ai_orchestration` normalises the
  `awaitable | iterator` shape, surfaces provider exceptions as
  None so the caller can fall back to `call_ai_complete_async`.
- All three provider plugins implement streaming via their SDK's
  native async streaming API:
  - **ai-anthropic** — `AsyncAnthropic.messages.stream()` +
    `text_stream` iterator.
  - **ai-openai** — `AsyncOpenAI.chat.completions.create(stream=True)`,
    consumes `delta.content` from each `ChatCompletionChunk`,
    drops role-only / null-content markers.
  - **ai-gemini** — `client.aio.models.generate_content_stream`,
    consumes `.text` from each chunk.
- Each hookimpl wraps SDK exceptions as `ExternalServiceError`
  so the SSE channel reports a stable shape on mid-stream
  failures.

### 19B-1 — Backend SSE route + frontend reader + streaming UI

- New `POST /api/plugins/session/{id}/message/stream` returns
  `text/event-stream`. Three event types:
  - `start`: `{user_message}` — server-side persistence confirmed.
  - `chunk`: `{delta}` — repeated; concat = assistant text.
  - `done`:  full exchange (`session`, `assistant_message`,
              `ai_error`, `step_evaluation`, `topic_transition`,
              `timings`) — same shape POST `/message` returns.
- Tries `ai_complete_stream`, falls back to
  `call_ai_complete_async` and emits the full string as a single
  chunk so the client never has to branch on capability.
- Step-evaluation + topic-transition fire AFTER the stream
  completes; the v1.5.0 parallel-gather optimisation is
  intentionally not used (nothing to overlap once the stream
  has finished).
- Setup errors (no provider, no key, no model) surface as
  `done.ai_error` inside the SSE wire, not as HTTP 4xx — same
  contract as `/message`.
- Frontend `lib/sse-reader.ts` — inline fetch +
  `ReadableStream` SSE parser. No external dependency. Handles
  partial frames split across reads, comment lines, multi-line
  data, leading-space stripping.
- `IStorageService.session.streamMessage(sessionId, body, handlers)`
  added to `storage/types.ts`. `api-storage` delegates straight
  to the new SSE endpoint; `dexie-storage` is wired to the
  browser-direct path in 19B-2.
- `ChatMessage` grows an optional `streaming: true` flag.
  `SessionChat` renders a trailing cursor (▍) inside the bubble
  while it streams; testid switches to
  `chat-message-assistant-streaming` so consumers can pin the
  in-flight bubble.
- `Session.tsx#handleSend` swapped from `message` to
  `streamMessage`. The "Thinking…" placeholder is gone — the
  streaming bubble fills with real tokens immediately.

### 19B-2 — Dexie-mode browser-direct streaming

- New `aiStream(opts)` dispatcher in `storage/ai-providers.ts`
  mirroring `aiComplete`. Per-provider implementations consume
  the provider's SSE wire directly:
  - Anthropic: `/v1/messages` + `stream: true` + the same
    browser-CORS header.
  - OpenAI: `/v1/chat/completions` + `stream: true`; reads
    `data: [DONE]` as the end-of-stream sentinel.
  - Gemini: `:streamGenerateContent?alt=sse` (the `alt=sse`
    flag flips Gemini from newline-delimited JSON to the SSE
    wire both other providers use).
- `sendMessageStream(opts)` in `storage/session-flow.ts`
  mirrors `sendMessage` but pipes deltas through `onChunk`
  while accumulating the full text for persistence + the step
  evaluator.
- `dexieStorage.session.streamMessage` swapped from the
  19B-1 stub (call non-stream + emit one chunk) to
  `sendMessageStream`. Dexie users now see real per-token
  rendering identical to API mode.
- AbortSignal piped through the dispatcher to the underlying
  fetch so callers can cancel mid-stream.

### 19C — Performance metrics (carried over from 18E)

- The `timings` block on the SSE `done` event carries
  `learning_ms` (the stream duration), `evaluation_ms`,
  `topic_transition_ms`, `total_ms`, and the v1.5.0
  `parallel_saved_ms` placeholder (null in the streaming
  path because eval/transition still run sequentially after
  the stream finishes).

## Notes

- The non-streaming `POST /message` route is untouched.
  External integrations that don't want streaming keep working.
- The streaming hook is additive — providers that don't
  implement it fall through to `ai_complete_async` via the
  orchestrator. No provider-side break.
- Mid-stream provider exceptions land in `done.ai_error` (the
  partial assistant text is discarded; the user message stays
  persisted). Same shape the v0.2.0 non-stream route established.
- `AbortSignal` handling: passing `signal: AbortController.signal`
  to `streamMessage` aborts the underlying fetch on the next
  read. The route doesn't currently react to client disconnect
  (the post-stream eval/transition still fires); that's a
  follow-up if user signal surfaces.

## Migration notes

- No breaking changes. Existing `POST /message` callers see no
  contract change. Existing Dexie-mode users see their chat
  surface render token-by-token automatically — no opt-in
  needed.
- Provider plugins that don't implement `ai_complete_stream`
  silently fall back. The default plugin set (anthropic,
  openai, gemini) implements it; third-party providers can
  opt in by adding the hookimpl, or skip it and rely on the
  async fallback.
