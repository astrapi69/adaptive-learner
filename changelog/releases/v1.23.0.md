# Adaptive Learner v1.23.0

**Released**: 2026-05-23

Phase 38 — **In-App Contextual Help System**. Educational
glossary of 22 core concepts (curriculum, learning project,
learning profile, learning session, the six learning methods,
the seven cycle steps, and five app features), surfaced
in-app via subtle dotted-underline tooltips and a slide-over
drawer with full Markdown articles. Help icons live next to
key terms throughout the UI; a Settings > Help section lets
users browse and search the whole glossary. Two manual-test
bugs fixed alongside.

## Why this release

The MkDocs documentation explains **how to use** Adaptive
Learner. v1.23.0 closes the gap on **what the app's concepts
mean**. A new user landing on the Dashboard sees "Lernprofil"
or "Methodenverteilung" without knowing what either of those
things is; the help system now puts a 1-2 sentence
explanation at hover-distance, with a "Learn more" link that
opens the full educational article in a slide-over drawer.

## What changed

### Glossary content (Phase 38A — four commits)

**22 entries × DE + EN**, all handwritten, ~12k words of
educational content total:

- **4 core concepts** (38A.1): Curriculum (built on the
  pedagogical foundation provided by the user — 4 core
  questions, four dimensions, Lehrplan distinction —
  adapted for the Adaptive Learner context), Learning
  project, Learning profile, Learning session.
- **6 learning methods** (38A.2): Deductive, Inductive,
  Error-based, Dialogic, Contextual, AI-adaptive. Each
  article covers when the method fits, how a session flows
  inside the method, what the AI does, and when the system
  recommends switching away.
- **7 cycle steps** (38A.3): Input, Attempt, Error, Feedback,
  Adapt, Repeat, Integrate. Each article explains what the
  AI does, what the user does, and what happens if the step
  is skipped.
- **5 features** (38A.4): Method switch (three-condition
  trigger), Auto-loop (cycle counter + max_cycles guard),
  Spaced repetition (6-band schedule), Conversation analysis
  / Import (4 extraction targets), Gamification (XP / badges
  / streaks with the explicit "mirror not target" framing).

Authoring lives in ``backend/config/help/{category}.{lang}.yaml``;
``make sync-help`` regenerates the matching
``frontend/src/data/help/*.json`` bundles consumed by the
tooltip + drawer at runtime (no API roundtrip required in
either storage mode).

### HelpTooltip + HelpContext (Phase 38B)

- ``utils/help-glossary.ts`` — bundled-JSON loader with EN
  lingua-franca fallback + region-code resolution
  (``de-DE`` -> ``de``).
- ``contexts/HelpContext.tsx`` — global ``useHelp()`` with
  ``openHelp(key)`` / ``closeHelp()``. Falls back to a no-op
  shape when used outside the provider so unit tests can
  render isolated components.
- ``components/help/HelpTooltip.tsx`` — subtle dotted
  underline wrapper. Hover (desktop) or tap (mobile) reveals
  a Radix HoverCard with the entry's short text + a
  "Learn more" button that opens the drawer.

### HelpDrawer (Phase 38C)

- ``components/help/HelpDrawer.tsx`` — Radix Dialog as a
  slide-over from the right
  (``min(640px, 100vw)``, full-screen on mobile).
  ``react-markdown`` + ``remark-gfm`` + ``rehype-slug`` +
  ``rehype-autolink-headings`` render the long Markdown
  content with linkable heading anchors. A
  related-concepts footer scans the article for mentions of
  other glossary titles and surfaces them as click-through
  chips.

### Help icons throughout the UI (Phase 38D)

``components/help/HelpLink.tsx`` — subtle grey
``?`` icon that opens the drawer on a specific entry. Wired
into 12 callsites across the app:

- Dashboard: 4 icons (Learning profile, XP & Level, Method
  distribution, Spaced practice).
- Curriculum / Session / Import / ImportDetail page
  headings.
- Session method-badge (dynamic — maps the active method to
  the matching glossary key).
- CycleProgress current-step label (dynamic — tracks the
  cycle).
- Onboarding topic field.
- MethodSwitchBanner.

CSS rule in ``global.css`` bumps the touch target to 12px
padding on viewports ≤ 720px.

### Settings > Help section (Phase 38E)

``components/help/HelpBrowser.tsx`` — browse all 22 glossary
entries grouped by category (Concepts / Methods / Steps /
Features), with a search input that filters by title /
short / long content (case-insensitive substring). Clicking
a row opens the drawer on that entry. Mounted at the top of
the Settings page, above the Language section.

### EN-passthrough bundles for the 6 secondary languages (Phase 38F)

ES / FR / EL / PT / TR / JA each get byte-identical copies
of the EN authoring YAMLs with only the ``language:`` field
stamped to the target locale. Native translation is filed as
``HELP-CONTENT-TRANSLATIONS-01`` in ``docs/backlog.md``
(P3) — 264 distinct text blobs (~10k words per language) is
genuine translator's work, not a passthrough swap. The Phase
26 i18n audit only scans ``backend/config/i18n/*.yaml``, NOT
``backend/config/help/*.yaml``, so the passthrough bundles
do not fail any test.

### Bug 7 — "Continue session" actually resumes now

Phase 36 Bug 4 added the ``activeSession`` lookup on
ImportDetail so the button reads "Sitzung fortsetzen" when an
active session exists. The navigation, however, sent the user
to ``/session?id=<existing>`` and ``Session.tsx`` ignored the
id — always calling ``session.start()`` and creating a fresh
session. The chat appeared empty, which the user reported as
"opens a wizard".

Fix:
- Two new backend endpoints in the session plugin:
  ``GET /api/plugins/session/{id}`` (fetch the session record)
  and ``GET /api/plugins/session/{id}/messages`` (chat history
  oldest-first, including the system prompt).
- ``ISessionNamespace`` gains ``get(id)`` + ``getMessages(id)``;
  both ApiStorage and DexieStorage implement them (Dexie reads
  from the local ``learningSessions`` + ``sessionMessages``
  tables).
- ``Session.tsx`` checks ``?session=<id>`` on mount: if
  present, it takes a RESUME path that fetches the existing
  record + history instead of calling ``start()``. The fresh
  session path (no ``?session=``) is unchanged.
- ``ImportDetail.tsx`` navigates with ``?session=`` instead
  of ``?id=`` so the resume path activates.

### Bug 6 — Tooltips actually visible now

Phase 38B shipped ``HelpTooltip`` but ``grep -rln HelpTooltip
frontend/src --include='*.tsx' | grep -v .test.`` returned
only the component file and the context. Zero callsites in
real pages — the user reported tooltips missing during manual
testing.

Fix: a concepts-explainer paragraph below the Onboarding
intro wraps three core terms (Learning project, Learning
profile, Learning session) in ``<HelpTooltip>``. This is the
first screen a new user sees, so the tooltip pattern lands
immediately. i18n strings added in all 8 catalogs (EN + DE
handwritten; PT/TR/JA translated to clear the audit;
ES/FR/EL passthrough).

## Storage modes

Both API mode (FastAPI backend) and Dexie mode (browser
IndexedDB) work for every change. The help system reads from
bundled JSON in both modes (single source of truth via
``make sync-help``). The session-resume endpoints have
matching DexieStorage implementations that read from the
local tables.

## Migration

No schema changes. No new dependencies for end users (the
five new npm packages ship inside the static frontend
bundle). No Alembic migration. Existing dev databases work
unchanged.

## Privacy contract (unchanged)

The Phase 37 privacy contract (event recorder RAM-only,
sanitized, opt-in for the issue report) continues to apply.
The help drawer issues no network requests, logs nothing to
the event recorder beyond the global click-listener entry
that Phase 37 already captures for every button. Glossary
content is bundled in the frontend; no analytics, no
telemetry.
