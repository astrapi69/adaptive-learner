# Adaptive Learner v1.28.0

**Released**: 2026-05-26

Phase 44 — **Lesson Viewer + Matching + Picture-Choice
Exercises** (EXP-002 Sprint 3 parts A-D). The v1.27.0
Content-Loader pivot now has a viewer: users can open a
downloaded set, walk through theory steps, complete matching
and picture-choice exercises, and see their score on a
summary screen. The GitHub Pages deployment is, for the
first time, a usable language-learning app **without an API
key**.

## Why this release

v1.27.0 shipped the Content-Loader (downloads + cache + Set
Browser + pilot lessons) but had no way to actually USE the
lessons — the "Open" button on installed sets led nowhere
because the lesson route didn't exist yet. v1.28.0 closes
that loop. The full no-API-key flow:

  /content → download French A1 set → tap "Open" →
  /lesson/.../... → theory steps render as Markdown →
  matching exercises score in real time → picture-choice
  exercises with graceful text fallback → summary screen
  shows score + time → "Mark as complete" persists progress
  → /content.

Free-text and word-tiles exercises remain in the pilot
lessons but render as a "Coming in v1.29.0" placeholder per
Decision 2B (auto-skip with friendly notice). Phase 45 wires
those two renderers.

## What changed

### Added

- **`LessonProgress` data model**: SQLAlchemy + Alembic
  migration 0018 + Pydantic schemas + service +
  `/api/users/{user_id}/lesson-progress` router. Per-user
  × per-lesson row with a JSON-encoded `step_results` map,
  aggregate score, time spent, and status. Parallel to
  `LearningSession` (the session plugin's 7-step AI flow);
  Phase 46 will unify them when SRS lands.

- **`IStorageService.lessonProgress` namespace** with both
  ApiStorage + DexieStorage implementations. Dexie schema
  v17 adds the `lessonProgress` table; composite key
  `{user_id}#{source-slug}#{set_id}#{filename}` matches the
  backend uniqueness contract so multi-device sync converges
  on the same row per lesson.

- **`useLesson` hook** combines lesson fetch + progress
  load + step navigation + step-result persistence. Returns
  a discriminated union (`loading` / `not-cached` /
  `ready` / `error`) so the viewer renders the right state
  without crashing on missing data. Resume logic walks the
  saved `step_results` to land the user on the
  next-uncompleted step.

- **Theory anchor resolution**
  (`frontend/src/lib/lesson-anchors.ts`): content authors
  cross-reference steps via `[link](theory.md#step-id)`;
  the rewriter maps these to in-app anchors
  (`#lesson-step-{id}`) that the viewer's Markdown link
  handler intercepts to navigate to the target step.

- **Lesson viewer page** at
  `/lesson/:setSlug/:setId/:filename`:
  - 4 load-state branches with stable testids (loading /
    not-cached / error / ready).
  - Step-by-step navigation with prev/next + a progress
    bar ("Step N of M" / "Summary").
  - Theory steps render via the existing react-markdown
    pipeline (`remark-gfm` + `rehype-slug` +
    `rehype-autolink-headings`).
  - Exercise dispatcher routes to MatchingExercise or
    PictureChoiceExercise based on `step.exercise.type`.
    Unsupported types show a "Coming in v1.29.0"
    placeholder with a Skip button so the lesson stays
    completable.
  - Summary screen surfaces score + time + mark-complete /
    start-over / back-to-browser buttons.
  - Mobile-first: nav buttons stretch full-width below
    600px so 44px touch targets hold.
  - Lazy-loaded behind React.lazy() per the v1.26.1
    bundle-size discipline.

- **MatchingExercise component**: two-column tap-to-pair.
  Deterministic shuffle of the right column. Submit checks
  index equality; correct tiles get a green border + check
  icon, wrong get red + X. ARIA-live counter announces
  pair progress. Mobile-first: columns collapse to single
  column below 600px.

- **PictureChoiceExercise component**: 4-column grid of
  image tiles (2-column on mobile). Exactly one tile has
  `is_correct: "true"`; submit reports {correct: 0|1,
  total: 1}. Graceful text-only fallback when an image
  fails to load — every pilot picture-choice step lands in
  text-only mode for now because the Phase 43 download
  orchestrator doesn't yet fetch the `assets/` directory.
  Asset fetching is a future phase; the exercise stays
  playable since each image carries a textual label.

- **Set Browser "Open" button** on installed sets in the
  /content page. Clicking calls `listLessons` and navigates
  to the set's first cached lesson.

- **Lesson smoke gate**: the Dexie-mode release gate now
  walks the `/lesson/...` route in addition to /content,
  pinning that a first-visit GH Pages user lands on the
  friendly "not cached" notice rather than a crash.

## i18n

- New `lesson.*` namespace + `lesson.exercise.matching.*`
  + `lesson.exercise.picture.*` (50+ new keys per
  catalogue). All 8 catalogues translated natively
  (DE / EN / ES / FR / EL / PT / TR / JA).

## What's deferred

- **Phase 45** — free-text + word-tiles exercise
  renderers; the pilot lessons already use them as Skip
  placeholders.
- **Phase 46** — lesson summary + SRS integration; the
  current summary shows score + time but does NOT award
  XP / advance streaks / commit progress to the session
  plugin's tracking surface. That unification is the right
  shape for the SRS work.
- **Asset fetching** — picture-choice tiles currently
  fall back to text-only because the cache stores only
  lesson JSON. Adding the `assets/` directory to the
  download orchestrator is the obvious next step.

## Upgrade notes

- **Dexie schema bump v16 → v17**: existing GH Pages
  users get an automatic schema upgrade on first load.
  No data loss; the new `lessonProgress` table starts
  empty.
- **Alembic 0018 migration** adds `lesson_progress` on
  the backend. A fresh `make dev` picks it up
  automatically; deployed backends should run
  `alembic upgrade head`.
- **No breaking changes** to existing namespaces,
  routes, or storage shapes.
