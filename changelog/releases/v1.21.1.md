# Adaptive Learner v1.21.1

**Released**: 2026-05-22

Phase 36 — **Import + Analysis Bugfixes from Manual Testing**.
Five regressions in the import + analysis surface, surfaced by
the user's manual smoke-test of the v1.21.0 release, fixed
atomically. No new features; no API removals; one new column
each on three core tables (imported_conversations, curriculums,
learning_sessions) plus the matching Dexie schema bumps.

## Why a patch release

The v1.21.0 manual test against the real Claude.ai per-
conversation Markdown export found that the import + analysis
flow had five concrete bugs that broke the user-facing
experience: analysis came back in the wrong language, the same
transcript could be imported twice silently, the curriculum and
session CTAs always created duplicates instead of resuming, and
the Anki extraction silently failed with no diagnostic the user
could see. None of these were caught by the existing test suite
because the suite mocks the AI providers; the bugs all live at
the seams between the import surface and downstream features.

## What changed

### Bug 2 — Analysis language passthrough (commit 8781a0c)

`User.language` now reaches the analysis system prompt. The
prompt's body stays English (JSON keys + enum values are machine
identifiers); a new LANGUAGE directive at the end tells the AI
which language to write the free-text fields in. Both engines
(backend `app.services.conversation_analysis` and frontend
`chat_import/analysis.ts`) gained a `build_system_prompt(lang)`
function and a `lang` parameter on `analyze_conversation*`.
ImportDetail reads `settings.language` and threads it through.
Supports all 8 i18n languages (DE / EN / ES / FR / EL / PT /
TR / JA); unknown codes fall back to English.

### Bug 1 — Duplicate-detection + delete button (commit b6d2f8b)

`ImportedConversation` gained a `content_hash` column (Alembic
0014 + Dexie schema v12) — SHA-256 of role-prefixed, content-
stripped messages joined by `\n`. Title-independent so re-
imports under a fresh title still detect as duplicates. The
algorithm is identical across backend (`hashlib`) and frontend
(`SubtleCrypto`), and the Alembic migration back-fills every
existing row.

On collision, the import endpoint returns HTTP 409 with
`extra.existing_id` carrying the UUID of the original. The
ApiError type now ships `extra` so frontend handlers can act on
the structured field. Import.tsx catches the 409 and navigates
to the existing detail page with a clear toast instead of
leaving the user stranded.

Every row in the imports list now has a Delete button that
calls the existing `DELETE /api/imports/{id}` endpoint after a
confirm prompt.

`notify.error` gained a `{persistent: true}` option so failure
toasts can stay until the user dismisses them, per the Phase 36
spec that error toasts must not auto-dismiss.

### Bug 3 — Curriculum per-conversation link (commit 677e81c)

`Curriculum.imported_conversation_id` added (Alembic 0015 +
Dexie schema v13). Children-side FK with `SET NULL` on delete
so removing the source conversation does not wipe the derived
curriculum. New endpoint `GET /api/imports/{id}/curriculum`
returns the linked curriculum or `null`. ImportDetail flips
the CTA: "Create curriculum" → "Go to curriculum" (with a
distinct `data-testid`) when a curriculum already exists. The
handler defends against double-click via a state re-check
before persisting.

### Bug 4 — Session resume per conversation (commit cedc31c)

`LearningSession.imported_conversation_id` added (Alembic 0016
+ Dexie schema v14). Same `SET NULL` on delete contract. Both
the API path (session plugin `POST /start`) and the Dexie path
(`session-flow.ts`) now resume an existing active session for
the same conversation instead of always creating new. New
lookup `GET /api/imports/{id}/active-session` lets ImportDetail
flip "Start session" → "Continue session" before the user
clicks.

### Bug 5 — AI provider system=None handling (commit dcb0b87)

Root cause of the Anki-extract HTTP 400 the user reported: the
ai-anthropic wrapper passed `system=None` to
`client.messages.create` when the transcript had no system
message, which the Anthropic API rejects with "system: Input
should be a valid array". Fix builds the SDK kwargs dict
conditionally so `system` is only attached when there is a real
value. Same symmetric fix landed in ai-gemini (its config
object now omits `system_instruction` when None) and a
regression test pins that ai-openai never grows a phantom
`system` kwarg either.

## Migration

Existing dev databases pick up the three new columns + indexes
on the next startup via Alembic. If a dev DB was created before
v1.21.1's Alembic 0014/0015/0016 and the start-up auto-migration
chain is broken, `rm backend/adaptive_learner.db` rebuilds with
the new schema (test-only DBs are not affected — `make test`
uses in-memory SQLite).

Dexie databases (browser-side, Dexie mode) bump from v11 to v14
with three discrete schema versions. Each upgrade is idempotent
and the v12 upgrade back-fills `content_hash` by reading each
conversation's messages and computing the digest in the browser.

## Storage modes

Both API mode (FastAPI backend) and Dexie mode (browser
IndexedDB) work for every fix. The same content-hash algorithm,
the same resume semantics, and the same dedup error shape on
the frontend side regardless of mode.

## Carry-over from v1.21.0

v1.21.1; the next docs sweep will land alongside Phase 37 when
the next feature wave starts.
