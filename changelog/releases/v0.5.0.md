# Adaptive Learner v0.5.0

**Released**: 2026-05-18

Phase 8 — the **dual-prompt architecture**. Cycle-step
transitions are no longer deterministic +1: every successful
`/message` round-trip now fires a SECOND AI call against the
same provider that returns a structured JSON verdict, and the
route applies the suggestion based on a configurable confidence
threshold. Backward, skip-ahead, and repeat transitions are all
supported — the 7-step cycle is now a framework, not a conveyor
belt.

## Added

### Step Evaluator module (8A)
- New `plugins/adaptive-learner-plugin-session/adaptive_learner_session/step_evaluator.py`.
- English system prompt (`EVALUATION_SYSTEM_PROMPT`) that
  instructs the model to return ONLY a JSON object matching
  `{advance, confidence, reason, suggested_step}`. Cross-
  provider JSON reliability won the prompt-language debate
  (Q3); the `output_language` parameter steers ONLY the
  `reason` field for natural tooltip rendering downstream.
- Per-method readiness hints (`METHOD_EVAL_HINTS`) parameterise
  a single template by the active learning method —
  deductive judges rule comprehension, dialogic judges exchange
  quality, contextual judges application in the learner's own
  situation, etc. One template, six method variants.
- Robust JSON parsing: strips markdown fences (```json...```
  and bare ```), snips the first balanced `{...}` if the model
  leaks prose, clamps `suggested_step` into `[1, 7]`, clamps
  `confidence` into `[0.0, 1.0]`, truncates long `reason`.
- Deterministic fallback on any parse failure / None hook
  return / provider exception (`+1` advance, capped at 7).
  Never raises — the route caller never has to wrap this in
  try/except.
- `EVALUATION_DEFAULT_MAX_TOKENS = 256`: tight cap on the
  evaluator's output (JSON typically 80-120 tokens), the
  learning call still uses the provider's full default.

### Dual-call route integration (8B)
- `POST /api/plugins/session/{id}/message` now does two
  sequential AI calls per round-trip:
  1. Learning response (existing) — assistant text.
  2. Step evaluator (new) — JSON verdict.
- The verdict applies iff:
  - real evaluation: `advance ∧ confidence ≥ threshold` (0.7
    default), OR
  - fallback path: `advance` (the deterministic-+1 fallback
    IS the v0.4.x compat path; threshold does not gate it).
- Backward (`current=4 → suggested=2`) and skip-ahead
  (`current=1 → suggested=4`) transitions both apply when
  confidence holds. The cycle is pedagogical, not linear (Q4).
- `ai_complete` hookspec extended with
  `max_tokens: int | None = None` kwarg. Three provider plugins
  (anthropic, openai, gemini) updated to accept and forward it.
- Response shape gains `step_evaluation:
  StepEvaluationVerdict | null`: `advance`, `confidence`,
  `reason`, `suggested_step`, `fallback_used`, `applied`,
  `from_step`. `null` when the route short-circuits before the
  evaluator runs (no API key, role≠user) OR when
  `step_evaluation.enabled` is `false` in config.
- New `backend/config/plugins/session.yaml` carries the
  defaults: `enabled: true`, `confidence_threshold: 0.7`,
  `max_tokens: 256`. User-overlayable per the existing plugin
  config chain.
- Cap at step 7 — no auto-loop in v0.5.0 (Q2 — deferred to
  v0.6.x where it needs its own topic-selection prompt).

### Frontend step-evaluation feedback (8C)
- `CycleProgress` pulse animation on the new current step on
  any cycle transition. Direction-agnostic — backward (Q4),
  forward, and skip-ahead all use the same eye-catch. Honors
  `prefers-reduced-motion: reduce` (animation dropped under
  that media query).
- "Why this step?" tooltip — italic reason line under the
  cycle caption when the evaluator's reason is real. Fallback-
  path reasons (diagnostic placeholders) are explicitly NOT
  surfaced.
- `notify.info` toast ("Moving to: {step}") on applied
  transitions where the step actually moved. Stay-on-step is
  silent.
- New TypeScript type `StepEvaluationVerdict`.

### StepEvaluation persistence + analytics (8D)
- New SQLAlchemy `StepEvaluation` model + Alembic 0003. Fields:
  `from_step`, `to_step`, `advance`, `confidence`, `applied`,
  `fallback_used`, `reason`, `evaluated_at`. Cascading FK to
  `learning_sessions`.
- `to_step` records where the session ACTUALLY went (not just
  what the AI suggested), so the analytics layer can answer
  "what did this session do" without re-running the gate.
- New `aggregate_step_evaluations` in tracking summary
  produces: `total_evaluations`, `average_confidence`,
  `advance_count`, `repeat_count`, `backward_count`,
  `fallback_count`, `evaluations_per_step`,
  `time_seconds_per_step` (per-session evaluated_at deltas;
  gaps >2h excluded as idle).
- `GET /api/plugins/tracking/progress/{project_id}` adds a
  `step_evaluation` namespace alongside `tracking`. The
  StepEvaluation→LearningSession join scopes evaluations to
  the project.
- New `StepEvaluationInsights` component on Progress.tsx —
  metric tiles for avg confidence / repeats / advances (+
  optional backward) + "Most time on: {step} ({duration})"
  stickiest-step line. Empty-state when no evaluations yet.

## Configuration knobs

```yaml
# backend/config/plugins/session.yaml (v0.5.0 defaults)
step_evaluation:
  enabled: true              # false → v0.4.x deterministic +1
  confidence_threshold: 0.7  # below this, AI suggestion ignored
  max_tokens: 256            # cap on evaluator output
```

## Decisions encoded in the architecture

- **Q1 Sequential calls.** Learning first (user-visible),
  evaluator second. Total latency ≈ T(learning) + ~500ms.
  Async/parallel refactor deferred — premature optimisation
  next to the 2-5s learning latency.
- **Q2 Cap at 7.** Evaluator can suggest 7 repeatedly when
  the learner is integrating; no auto-loop to step 1 with
  fresh content. v0.6.x adds the topic-selection prompt for
  that flow.
- **Q3 English prompt, localised reason.** Better cross-
  provider JSON adherence than non-English variants.
- **Q4 Backward transitions allowed.** The cycle is a
  framework, not a conveyor belt. Confidence in
  "needs to re-attempt" is pedagogically correct.

## What's NOT in v0.5.0

- Auto-loop to step 1 after step 7 (deferred to v0.6.x — needs
  fresh topic-selection prompt + UX).
- Parallel learning / evaluator AI calls (deferred — current
  500ms additional latency is invisible next to 2-5s learning
  latency).
- Per-method evaluator threshold (single global threshold for
  v0.5.0; methods that need stickier transitions can override
  via the existing plugin config overlay if needed later).
