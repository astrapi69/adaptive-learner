# Adaptive Learner v1.4.0

**Released**: 2026-05-20

Phase 17 — **Auto-Loop: Continue Learning After Step 7.**
Sessions no longer cap at step 7 when the learner has integrated
the topic. The AI assesses readiness, picks a natural next
subtopic, resets the cycle to step 1, and the same session
continues with fresh content. Same provider, same conversation
history, method preserved. Hard cap on cycles per session
(default 5) prevents runaway loops; the user can end any time.

## Added

### 17A — Topic-transition evaluator

- New ``plugins/.../session/topic_transition.py``. Mirrors the
  step-evaluator's design: ``build_transition_messages`` composes
  a structured prompt asking whether the learner integrated the
  topic + what the next subtopic should be;
  ``parse_transition_response`` decodes the JSON;
  ``evaluate_topic_transition`` orchestrates the end-to-end call.
- Output schema: ``{cycle_complete, summary, next_topic,
  next_topic_rationale, difficulty_adjustment,
  continue_recommended}`` — see ``TRANSITION_SYSTEM_PROMPT`` for
  field semantics.
- Deterministic fallback: ``cycle_complete=False`` +
  ``continue_recommended=False`` keeps the v0.5.0 cap-at-7
  behaviour when the AI response is unparseable / errors.
- Config block in ``config/plugins/session.yaml``:
  - ``auto_loop.enabled: true``
  - ``auto_loop.max_cycles: 5``
  - ``auto_loop.topic_transition_max_tokens: 256``
- 17 new pytest cases in ``test_topic_transition.py`` covering
  the prompt structure, the parser, well-formed / malformed
  responses, and the orchestrator (including provider exception
  -> fallback).

### 17B — Session cycle counter + loop state

- New columns on ``learning_sessions`` (Alembic migration 0005):
  - ``cycle_count`` (default 1, increments on each loop)
  - ``cycle_topics`` (TEXT, JSON array of completed-cycle
    summaries)
- ``LearningSessionOut`` carries both. ``cycle_topics`` decodes
  with a tolerant ``field_validator`` so partial / empty / null
  DB state never raises.
- Session ``/message`` route now reads the auto_loop config,
  fires ``evaluate_topic_transition`` when the step evaluator
  advances to step 7 with advance=true, and on
  ``cycle_complete ∧ continue_recommended`` resets
  ``cycle_step`` to 1 + increments ``cycle_count`` + appends
  the completed cycle to ``cycle_topics``.
- ``max_cycles`` cap stops the loop once the hard limit is hit.
- New ``_TopicTransitionOut`` on the message-exchange response
  so the frontend can render the cycle-transition card.

### 17C — Frontend auto-loop UX

- ``LearningSession`` + ``SessionMessageExchangeResult`` types
  carry the new fields (``cycle_count``, ``cycle_topics``,
  ``topic_transition``).
- ``ChatMessage`` extended with optional ``kind:
  "cycle_transition"`` + ``cycleNumber`` + ``nextTopic``.
  SessionChat renders these as a dashed-border, accent-coloured
  card with a "Cycle N" badge, italic summary, and next-topic
  line — distinct from regular speech bubbles.
- Session page appends the transition card to the chat when the
  message route returns ``topic_transition.looped=true`` and
  fires a success toast.
- Session header gains a "Cycle N" badge next to MethodBadge
  when ``cycle_count > 1``.
- i18n keys ``cycle_label`` / ``cycle_advanced`` / ``next_topic``
  / ``cycles_completed`` across all 8 catalogs (DE + EN
  translated, six others EN passthrough).

### 17D — Multi-cycle session summary

- ``RatingDialog`` grows optional ``cycleCount`` + ``cycleTopics``
  props; when present (``cycleCount > 1``) it prepends a
  "Cycles completed: N" block with the per-cycle topic + summary
  list before the rating questions.
- Session page passes the values through; the dialog stays
  unchanged for single-cycle sessions.

## Notes

- Dexie-mode auto-loop is deferred to a future phase. The
  ``sendMessage`` flow in ``storage/session-flow.ts`` returns
  ``topic_transition: null`` so the chat UI still renders
  correctly; the cycle simply caps at 7 in Dexie mode.
- Method is preserved across cycles unless the user explicitly
  switches via the existing method-switch path.
- Conversation history is preserved across cycles (the same
  ``learning_session`` row, the same ``session_messages``).
