# Adaptive Learner v1.77.0

Architecture release. Four threads, no schema / API / data-model change:
a three-phase data-integrity hardening of the Dexie storage layer, the
completion of the god-file decomposition across both backend and frontend,
three warn-only CI watchers (cohesion, security, complexity), and the Vibe
Coding Policy. Plus backend parameter-dataclasses, a feature-state policy,
the gitflow branching model, and a dependency-security fix. 43 commits, no
user-facing behaviour change beyond the two small fixes below.

## Changed

- **Dexie read-modify-write data-integrity remediation (#390, three
  phases).** Almost every mutating `DexieStorage` method did
  `get(id) -> modify -> put(id)` with the read and the write in separate
  implicit transactions, so two concurrent callers on the same `(table, id)`
  silently lost one update. Fixed with Dexie-native primitives, each phase
  red-tested before the fix:
  - **Phase 1 — atomic increments (#393 / #395).** `persistXP`,
    `updateStreakState`/`setWeekendMode`, `recordElementAttemptsDexie` use
    `table.modify()`; `upsertLessonProgressDexie` (autosave-timer vs
    step-click) and the `session.end` award fan-out use a `db.transaction`
    with an idempotent status-guard; `evaluateBadgesForUser` uses a
    compute-then-apply transaction so concurrent runs can't double-insert a
    badge or double-award XP.
  - **Phase 2 — create-race + unique indexes (#397 / #398).** The
    check-then-insert ensure helpers (`ensureSettings`, the XP/streak
    `getOrCreate`, the badge-catalog seed) are transaction-wrapped, backed by
    new unique indexes (Dexie v25 → v27): `&user_id` on
    userXp/userStreaks/userSettings, `&key` on badges, and the compound
    `&[user_id+badge_id]` on userBadges. A v26 dedup migration runs first so
    the index creation can't abort `db.open` on a duplicate-laden database.
  - **Phase 3 — full-replace last-writer-wins (#399 / #402).** The 13
    full-replace `update` methods (lessons, curricula, topics, projects,
    users, subjects, tags, settings ×4, imports ×2) wrap their
    get+spread+put in a `db.transaction`, so two concurrent edits to
    different fields of the same row both survive — the realistic case being
    the TipTap debounced autosave racing a manual lesson save.

- **God-file decomposition completed (backend + frontend).** A sustained
  cohesion pass under #341 / #353 / #354, every split behaviour-preserving
  with tests green throughout:
  - *Backend:* the session `append_message` god-method decomposed into a
    `MessageContext` carrier + `persist_user_message` + a `session_runner`
    module (#342 / #343 / #352); the triplicate `_build_ai_caller`
    consolidated into `app.services` (#340); `backup_service` split into
    export + restore modules (#353); startup/lifespan extracted into
    `app/startup.py`, the layered config loader into `app/config.py`, sync
    push + conflict-resolution into `sync_push.py`, and the content-loader
    `SourceRef`/settings parsers into `sources.py` (#353 / #355).
  - *Frontend:* `api/client.ts` split into a core + per-domain namespace
    modules (#396); the storage layer split — `types.ts` into per-namespace
    modules (#364), the Dexie row shapes into `db-rows.ts` (#392), and the
    `DexieStorage` god-object into per-domain namespace modules with the root
    under 800 lines (#360 / #365 / #366); and the Settings AI panel (#387),
    `BackupSection` (#385), `ShareWizard` (#389), the Content page (#403),
    and the Lesson page (flow-control + navigation hooks + sub-components +
    TTS hook, #356 / #358 / #406) all extracted from their god-files.

- **Backend parameter-dataclasses.** Wide positional signatures replaced by
  typed context carriers: `upsert_progress`'s 14-parameter signature becomes
  a `ProgressUpdate` dataclass (#375 / #376), and `create_conversation` +
  `create_lesson_pr` take context dataclasses (#380 / #382).

## Added

- **Three warn-only CI watchers (defense-in-depth; visibility first, hard
  gate later).** A cohesion/file-size watcher with WARN/ERROR thresholds and
  a ratchet baseline (#370 / #371, audit #374); a security-scan workflow —
  pip-audit + npm audit + bandit (#377 / #378); and a complexity watcher —
  radon for Python, eslint's `complexity` rule for TypeScript, with inline
  PR annotations and a `make check-complexity` target (#400 / #405). None
  blocks a merge in this phase.

- **Vibe Coding Policy (#381 / #383).** A full policy document plus the
  condensed agent rules in `.claude/rules/vibe-coding.md` — prompt
  precision, layered architecture, test discipline, dependency hygiene, and
  the git/issue workflow.

- **Feature-state policy: visible-but-disabled, never hidden (#335 / #336).**
  A product feature the user owns is never `hidden`; it is `active` or
  `disabled` with a localized reason (a disabled section shows a notice card,
  a disabled button a tooltip). Applied first to the desktop-only sync
  controls.

- **Gitflow branching model (#334).** `main` holds releases only; `develop`
  is the active default branch; `release/*` branches carry the bump +
  changelog. New `make release-prepare` / `release-finish` targets, updated
  CI triggers, and Dependabot pointed at `develop`.

## Fixed

- **npm audit: two moderate advisories cleared (#379).** `qs` overridden to
  `^6.15.2`.

- **Dashboard: friendly titles for legacy `analysis-<uuid>` sets (#368 /
  #369).** A pre-fix synthesised set whose title was the raw
  `analysis-<uuid>` slug now renders a readable label.

- **Plugins: seven silent `except` blocks now log (#337 / #338).** Swallowed
  exceptions across the plugin tree are logged with context instead of
  vanishing.
