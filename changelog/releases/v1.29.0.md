# Adaptive Learner v1.29.0

**Released**: 2026-05-27

Phase 45 — **Free-Text + Word-Tiles Exercises** (EXP-002
Sprint 3 parts E-F). The two exercise renderers the v1.28.0
viewer was missing now ship. Every pilot French A1 lesson
walks end-to-end with all four exercise types scored; the
"Coming in v1.29.0" placeholder is gone for v1.0-schema
content.

## Why this release

v1.28.0 closed the lesson-viewer loop but left two of the
four authored exercise types as a friendly skip-placeholder.
That meant pilot lessons "worked" but their pedagogical
shape was incomplete — exercise variety is the point.
v1.29.0 fills the gap, so a learner who downloads
`language-fr-a1` and opens lesson 1 now hits, in order:

  Match the term to its translation → Pick the evening
  greeting (picture, text fallback) → **Type the answer**
  (free-text, typo-tolerant) → **Arrange the farewell**
  (word-tiles, tap-to-place) → summary screen with a real
  multi-type score.

After this release Phase 46 (Lesson Summary + SRS, the
unification with the session plugin's tracking surface) is
the next architecturally distinct unit.

## What changed

### Added

- **`FreeTextExercise` component**: single text input, Enter
  or Submit button. Case-insensitive NFC-normalized exact
  match against `exercise.accept`; Levenshtein <= 1 fallback
  catches single-edit typos ("Mercii", "Merc", "Mercy")
  without permitting near-miss wrong words ("Marci" — 2
  edits, rejected). Wrong attempt surfaces the canonical
  first entry. Optional inline "Need a hint?" toggle reveals
  `exercise.hint`. Mobile-first: full-width input, 44px
  touch targets.

- **`WordTilesExercise` component**: two-zone tap-to-place
  exercise. Scrambled bar at top with available tiles
  (deterministic Fisher-Yates shuffle keyed by exercise id);
  answer row underneath fills as the user taps. Tapping a
  placed tile returns it to the scrambled bar. Submit
  enables once every tile is placed. Validation accepts the
  canonical `tiles` order plus any `accept_orderings`
  permutation; if `accept_orderings` is absent, only the
  canonical order passes. No drag-and-drop library — tap-
  to-place works everywhere and keeps touch surfaces large.

- **ExerciseDispatcher wiring**: `SUPPORTED_EXERCISE_TYPES`
  grows from `{matching, picture_choice}` to all four
  shipping types. Two new branches in the dispatcher route
  the new components. The placeholder code path stays as a
  defensive fallback for any future schema_version that
  ships a fifth type whose renderer hasn't landed yet.

### Decisions confirmed in commit messages

- **D1**: Levenshtein threshold = 1, case-insensitive, NFC
  normalization. Threshold 0 would have forced authors to
  enumerate every typo variant; threshold 2 would have
  silently accepted real wrong words (e.g. "Marci" for
  "Merci"). Threshold 1 is the sweet spot.

- **D2**: AI semantic validation (P-114) deferred to
  Phase 46 alongside SRS. The dual-mode AI dispatch belongs
  in the dispatcher layer, not per-component — folding it
  into one renderer would create an asymmetric foundation
  to undo later.

- **D3**: Asset fetching (so picture-choice tiles render
  real images instead of text fallback) stays as a separate
  follow-up phase. Doubling Phase 45's surface area would
  have diluted the focus on the two new renderers.

- **D4**: `accept_orderings: null` means canonical-only.
  The schema docstring already specified this; explicit
  confirmation now lives in the regression-pin tests.

### Changed

- **Test counts**: backend unchanged at 930 (+1 skipped).
  Plugin tests unchanged at 826. Vitest 1579 → 1634
  (+55: 27 FreeText + 25 WordTiles + 4 dispatcher routes
  + 1 future-type defensive placeholder, with 2 existing
  Lesson.test.tsx assertions repurposed).
- **Dexie smoke gate**: still 17/17 — no new routes; the
  `/lesson/...` route already in the gate exercises the
  build with the wired dispatcher.
- **No backend changes** in this release. Schema, models,
  routes, plugins all unchanged. Phase 45 is a pure-
  frontend exercise-renderer phase.
- **No dependency bumps** in this release.

## i18n

- New `lesson.exercise.free_text.*` (8 keys) and
  `lesson.exercise.word_tiles.*` (10 keys) namespaces
  across all 8 catalogues (DE / EN / ES / FR / EL / PT /
  TR / JA). Native translations, not English passthrough.

## What's deferred

- **Phase 45.5 (asset fetching)** — extends the Phase 43
  download orchestrator to fetch `assets/*` referenced by
  picture-choice exercises, plus a Dexie blob namespace
  for browser-mode caching. Picture-choice continues to
  work today via the text-only fallback; this phase
  promotes it to "real images" when the user is online.

- **Phase 46 (Lesson Summary + SRS)** — unifies the
  Content-Loader's `LessonProgress` with the session
  plugin's XP / streak / progress-commit surface. After
  Phase 46, completing a lesson awards XP, advances the
  user's streak, and writes a `ProgressCommit` for the
  associated learning project, just like the AI session
  flow does today. P-114 (AI semantic validation in
  exercises) ships as part of this phase.

- **Phase 47 onwards** — see `docs/ROADMAP.md`.

## Upgrade notes

- **No schema migrations.** No Alembic bump; no Dexie
  schema version change. Existing users get the new
  exercise renderers on the next page load.
- **No breaking changes** to any namespace, route, or
  storage shape.
- Public GitHub Pages deployment picks the new bundle up
  automatically on the next visit.
