# Adaptive Learner v2.7.0

## For existing launcher users: the app is now downloaded, not built

Starting with this release, the desktop launcher no longer builds the app
image on your machine. It downloads a ready-built, verified image from
GitHub's registry (about 110-120 MB compressed) and starts it. The first
start gets faster and no longer needs the source download and 5-10 minute
build; later starts are unchanged. **Your data is preserved**: the launcher
mounts the same Docker volume as before - your learning progress, settings
and stored provider keys stay exactly where they are. If the launcher finds
data in two places (an installation history spanning older launcher
versions), it stops and explains instead of choosing for you. Building from
source remains fully supported for self-builders: clone the repository and
use `install.sh` or the compose stack - that path is unchanged.

## Für bestehende Launcher-Nutzer: die App wird jetzt geladen, nicht gebaut

Ab diesem Release baut der Desktop-Launcher das App-Image nicht mehr auf
deinem Rechner. Er lädt ein fertig gebautes, verifiziertes Image aus der
GitHub-Registry (etwa 110-120 MB komprimiert) und startet es. Der erste
Start wird schneller und braucht weder den Quellcode-Download noch den
5-10-minütigen Bau; spätere Starts ändern sich nicht. **Deine Daten bleiben
erhalten**: Der Launcher bindet dasselbe Docker-Volume ein wie bisher -
Lernfortschritt, Einstellungen und gespeicherte Provider-Schlüssel bleiben
genau dort, wo sie sind. Findet der Launcher Daten an zwei Orten (eine
Installationsgeschichte über ältere Launcher-Versionen hinweg), hält er an
und erklärt die Lage, statt für dich zu entscheiden. Selbst bauen bleibt
voll unterstützt: Repository klonen und `install.sh` oder den
Compose-Stack verwenden - dieser Weg ist unverändert.

## Before you install

AdaptiveLearner runs in Docker. You need Docker Desktop installed and running before starting the launcher.

- [Docker installation guide (English)](https://github.com/astrapi69/adaptive_learner/blob/main/docs/help/en/install/docker-desktop.md) - includes a "Is Docker safe to install?" section
- [Docker-Installationsanleitung (Deutsch)](https://github.com/astrapi69/adaptive_learner/blob/main/docs/help/de/install/docker-desktop.md) - mit Abschnitt "Ist Docker sicher zu installieren?"

The launcher detects Docker, downloads the ready-built AdaptiveLearner image from GitHub's registry (about 110-120 MB compressed, roughly 500 MB on disk - nothing is built on your machine), and opens the app in your browser. Later starts are fast and work offline.

## Download

| Platform | File |
|----------|------|
| Windows | `adaptive-learner-launcher.exe` |
| macOS (Apple silicon) | `adaptive-learner-launcher-macos.zip` |
| Linux | `adaptive-learner-launcher` (ELF binary) |

Each platform also ships a `*.sha256` checksum next to the binary.

## Verifying downloads

```bash
# macOS / Linux
shasum -a 256 adaptive-learner-launcher-<platform>
cat adaptive-learner-launcher-<platform>.sha256
```

```powershell
# Windows
Get-FileHash -Algorithm SHA256 .\adaptive-learner-launcher.exe
Get-Content .\adaptive-learner-launcher.exe.sha256
```

The hashes must match.

If your operating system warns about an unsigned binary, see the [AdaptiveLearner installation overview](https://github.com/astrapi69/adaptive_learner/blob/main/docs/help/en/installation.md).

## What's new

A minor release. The headline is the distribution change: the desktop
launcher no longer builds the app image on the user's device - it pulls a
published multi-arch image from GHCR (`ghcr.io/astrapi69/adaptive-learner`),
and this release is the first to publish that image, through a verification
chain that runs both architectures before anything reaches a user. On the
app side: a new exercise type (image description), single-lesson deletion,
a guard that stops content updates from silently orphaning learning
progress, and a set-status persistence fix that survives both storage modes
and the backup round trip.

## Added

- **Image-description exercises (`ext:al-image-description`, #2095).** A new
  exercise type combining an image with a free-text answer, with its own
  renderer group and normalization under the complexity gate.
- **Delete a single lesson from a user-generated set (#2064).** The
  confirmation names the learning progress at stake, repetition cards and
  favorites are cleaned up, and a backup from before the deletion restores
  the lesson (a backup is a point in time, by decision). Works in both
  storage modes.
- **Set-update guard (#2128).** Updating a content set can orphan progress
  and repetition data when the author changed exercise identities. The app
  no longer lets the 24h auto-sync overwrite silently and warns before a
  manual update, naming what is at stake (cards, lessons). Dialog localized
  in all 11 languages (#2160). The durable fix - schema-enforced stable
  exercise identity - is registered upstream (learn-content-engine#90,
  EXP-045).
- **Onboarding: port-change warning (#2069).** Browser-mode data is stored
  per origin; changing the port hides it. The app now says so up front, with
  a help page.
- **Language-aware set ordering (#2057).** The content library lists sets in
  the user's language first.

## Changed

- **Launcher: pull instead of build (#2110, #2165).** `launcher.json` ships
  `deployment_mode: "image"` with the reference pinned to the release tag.
  Users never build; the on-device source-tree download (~200 MB) is gone.
  A standalone launcher run anchors its runtime files in the launcher's
  config dir. The `dockerfile` mode remains supported as the source-tree
  path. Launcher engine pinned to docker-app-launcher 0.24.0 (deterministic
  compose recreation, one-step update, full CLI contract incl. `--doctor`,
  readiness wizard).
- **Single-container production stack (#2058).** FastAPI serves the frontend
  statics; the separate frontend container is gone.
- **Production image slimmed (#2132).** 243 MB of unused pandoc dropped and
  the build tool kept out of the runtime image: 803 -> 491 MB uncompressed,
  164 -> 107 MB compressed (amd64).
- **Dependencies:** react-router 7 -> 8 + postcss override (clears both open
  high advisories, #2040); brace-expansion override bump (advisory).

## Fixed

- **Volume-name break on deployment-mode switch (#2154).** Compose prefixes
  volume names with the project name; the launcher config named the volume
  unprefixed, so a compose-era installation switching to the new modes
  started with an EMPTY database while the real data sat invisible in the
  other volume. The config now names the prefixed volume (existing data is
  simply found again), and when BOTH volumes hold data the launcher stops
  and explains instead of choosing silently. Verified end-to-end with real
  volumes: compose -> dockerfile -> image bind the same volume, database and
  encryption key intact, no second volume.
- **Set lifecycle status survives everywhere (#2038, #2050, #2053).** The
  active/deferred/completed status now persists mode-agnostically (API and
  browser mode) and rides the backup export/import; pinned by tests in both
  modes.
- **Dashboard entry suggestion (#2123).** Finished or deferred sets with
  nothing due no longer surface as the "continue learning" entry.
- **Create-Lesson wizard (#2036, #2066).** The required-title warning
  scrolls into view on invalid submit, and switching the lesson in a
  multi-lesson set keeps the wizard step instead of resetting it.
- **Accessibility (#2037).** Every Select trigger carries an accessible
  name.
- **Launcher diagnostics never swallow a cause (#2109, #2126, #2165).** An
  unrunnable deployment mode is named with the real cause (path resolution,
  not settings); a leftover broken docker credential helper no longer aborts
  operations (the launcher works with a sanitised client config, contexts
  preserved); every fail-soft path in the wrapper warns with path and reason
  instead of falling back silently.

## Infrastructure (visible at release time)

- **GHCR publish chain (#2142, #2145, #2147, #2149, #2151, #2163).** The
  image is published on release with: a hard precondition that the release
  commit's own CI was green (pending/unknown/empty counts as not green), a
  multi-arch build, enforced public visibility, an anonymous pull per
  architecture on NATIVE runners, a real start of the arm64 variant with a
  health check, a compressed-size ceiling per architecture (amd64
  125,602,358 bytes; arm64 124,716,686 bytes, seeded from a native
  measurement run), and a hard tag/image/health version agreement.
