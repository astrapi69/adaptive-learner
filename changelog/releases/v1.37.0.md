# Adaptive Learner v1.37.0

**Released**: 2026-05-28

Phase 54 — **Asset Fetching for Picture Choice Exercises**.
Picture Choice exercises stop being text-only: lessons can
now ship real images via a manifest-declared `assets/`
directory, with deterministic placeholder SVGs as a backup
for color / number / unknown labels, and a text-only
fallback as the final safety net. Three modes — API,
Dexie, and the GitHub Pages offline build — all support
images end-to-end.

## Why this release

The picture-choice exercise type has been in the schema
since v1.27.0 (Phase 43) but every implementation since
then ignored `images[*].src` and rendered text-only,
because no path actually wired the bytes from a content
repo's `assets/` directory through to an `<img>` tag.
v1.37.0 closes that gap end-to-end:

- Content authors declare `assets:` in the set manifest,
  ship binary files alongside the lesson JSON
- The downloader fetches them into the cache (filesystem
  in API mode, IndexedDB blobs in Dexie mode)
- A small ref-counted resolver turns cache hits into blob
  URLs (with proper `URL.revokeObjectURL` cleanup on
  unmount)
- An inline-SVG placeholder generator handles colours,
  numbers, and any other label as an avatar, so even
  authors who ship NO images get a usable picture-choice
  experience

The rule everywhere: **text-only fallback is always
available**. Images are an enhancement, never a
requirement.

## Added

### Asset download + cache infrastructure (54A)

- **Pydantic schema** — new `ContentSetAsset` model with
  strict validators: slug-safe path, no `..` traversal,
  image-extension whitelist (`.png` / `.jpg` / `.jpeg` /
  `.webp` / `.svg`), per-asset cap of 500 KiB
- New `assets: list[ContentSetAsset]` field on
  `ContentSet` (default `[]` so existing manifests keep
  validating)
- **Python cache** — new `read_asset(cache_root, source,
  set_id, version, asset_path)` helper in `cache.py` with
  defense-in-depth path-traversal check
- **Service** — `download_set` now fetches declared
  assets alongside lessons via the GitHub adapter's
  `fetch_bytes`. Assets that 404 upstream are logged + skipped
  gracefully. Actual size > declared × 1.10 → reject
- **Frontend storage** —
  `IContentLoaderNamespace.getAsset(source, setId, assetPath)`
  added. ApiStorage delegates to a backend HTTP proxy
  (54F); DexieStorage downloads assets during
  `downloadSetDexie`, stores them base64-encoded in the
  existing `contentSetFiles` table (no Dexie schema bump
  needed), and decodes back to a `Blob` with MIME inferred
  from the path extension
- Mode-agnostic failure: every layer returns `null` /
  short-circuits gracefully on miss

### Asset resolver + useAsset hook (54B)

- **`frontend/src/lib/content/asset-resolver.ts`** —
  process-wide ref-counted cache for blob URLs.
  `resolveAssetUrl` + `releaseAssetUrl` with in-flight
  de-duplication (parallel resolves of the same key share
  one storage call + one URL)
- **`frontend/src/hooks/useAsset.ts`** — React-friendly
  wrapper returning `{url, loading, error}`. Cleanup
  releases the resolver ref on unmount, so
  `URL.revokeObjectURL` fires when the last consumer
  unmounts. Short-circuits to error on null/empty
  arguments (defensive against unpopulated props)

### Image rendering in PictureChoiceExercise (54C)

- `PictureChoiceExercise` rewritten with a
  `PictureChoiceTile` sub-component per image so
  `useAsset` stays a top-level hook (rules-of-hooks
  compliant)
- Resolution chain: authored asset bytes → legacy
  `resolveImageSrc` callback (kept for v1.28.0 callers) →
  placeholder SVG → text-only
- Tile states: `is-loading` (skeleton), `is-placeholder`
  (SVG fallback), `is-text-fallback` (no `<img>`),
  alongside the existing `is-correct` / `is-wrong`
- `ExerciseDispatcher` gains an optional `source` prop
  threaded to PictureChoice; `Lesson.tsx` passes the
  parsed source from URL params

### Placeholder SVG generation (54D)

- **`frontend/src/lib/content/placeholder-svg.ts`** —
  deterministic inline SVG data URIs for choice labels
  when no authored image is available
- 'color' category: solid swatch via multilingual color
  dictionary (EN + FR + ES + DE; covers `red` / `rouge` /
  `rojo` / `rot` and ~36 other common colour names with
  German umlauts preserved per the project's prose policy)
- 'number' category: large styled numeral on neutral
  background
- 'default' (avatar): first letter on a circle filled with
  a deterministic 12-hue hash of the label
- Pure + offline: output is `data:image/svg+xml;utf8,...`
  so the `<img>` tag renders it inline with zero network
  calls

### Pilot lessons + authoring guide (54E)

- No lesson JSON changes needed — the existing
  `assets/img/...` references in pilot content fall
  through the resolver chain gracefully, and color +
  number lessons get nice swatches automatically via the
  placeholder generator
- Content-authoring guide extended in EN + DE with a new
  'Assets' section: directory layout, manifest
  declaration syntax, path-prefix convention, size +
  format limits, sizing recommendations, and the 'when
  the placeholder is good enough' guidance for skipping
  authored images on color / number / abstract-concept
  lessons

### Backend asset proxy endpoint (54F)

- New `GET /api/plugins/content-loader/sets/{source_slug}/{set_id}/assets/{asset_path:path}`
- `:path` converter catches multi-segment paths like
  `img/cover.png`
- Reads via `cache.read_asset` (path-traversal guard
  enforced)
- `Cache-Control: public, max-age=31536000, immutable` —
  the cache layout is versioned so URLs are stable across
  a set version
- 404 on uncached set OR missing asset (matches
  DexieStorage's null return so the frontend resolver
  treats both modes identically)

### Image optimization + manifest validator (54G)

- New `SET_ASSETS_SOFT_LIMIT_KB = 10 MiB` constant
- New `ContentSet.assets_total_kb()` helper
- New `check_set_assets_size(content_set, soft_limit_kb=…)`
  function returns advisory warnings (warn + don't reject):
  total declared size > soft limit recommends WebP/SVG;
  asset count > 100 flags likely manifest typos
- Downloader logs warnings via `logger.warning` per set
  (single signal, not per-asset noise)
- Frontend: `<img>` tags carry intrinsic `width={100}
  height={100}` matching the placeholder SVG viewBox so
  the browser reserves the tile's box BEFORE the image
  loads — no layout shift when assets resolve

## Architectural notes

### Why no Dexie schema bump

Asset bytes piggy-back on the existing `contentSetFiles`
table (column `body` as base64 with `encoding: "base64"`).
The schema already supported a non-text encoding flag from
v1.27.0 (Phase 43); we just hadn't used it for binary
content before. Result: assets ship in v1.37.0 without
bumping the Dexie version (still v19), keeping the
upgrade path zero-cost for existing GH-Pages visitors.

### Why text-only fallback stays

The asset infrastructure failed gracefully at every layer
on purpose:
- Manifest validator rejects oversized assets, but the
  cache still loads validated ones
- Downloader skips 404s upstream (with a log line) so a
  stale manifest doesn't fail the whole set download
- Cache reader returns `ContentNotFoundError` on missing
  bytes; the frontend resolver maps that to `null`
- useAsset returns `error: true` on `null`; the
  PictureChoiceTile falls through to placeholder SVG
- If even the placeholder `<img>` fires `onError` (e.g.
  browser refuses the SVG), the tile flips to
  `is-text-fallback`

The label is the source of truth; the image is an
enhancement. This means content with bad asset references
still produces a usable lesson, and a Dexie-mode user with
limited storage can prune assets without breaking the
core flow.

### Cleanup contract

Blob URLs created via `URL.createObjectURL` must be
revoked, or the browser holds the underlying bytes in
memory until tab close. The asset resolver tracks
ref-counts so the URL revokes exactly when the LAST
consumer unmounts:
- Two PictureChoiceTiles for the same image share one
  blob URL; both must unmount before revoke fires
- The useAsset hook handles the cleanup contract
  automatically via useEffect's cleanup callback
- Tests pin the contract with mock `URL.createObjectURL`
  / `revokeObjectURL` stubs counting calls

## Deferred

- **Audio assets**: the asset extension whitelist deliberately
  excludes `.mp3` / `.wav` / `.ogg`. When audio support
  lands, the change is one-line: add the extensions to
  `_IMAGE_EXTENSIONS` (rename to `_ASSET_EXTENSIONS`) and
  extend the MIME map. The cache + resolver + Dexie path
  already handle arbitrary bytes.
- **Per-asset difficulty / tagging metadata**: the
  manifest only declares `path` + `size_kb` today.
  Authoring tools that want richer metadata (e.g. "this
  is a noun, this is an action verb") can ship it once a
  later phase needs it.
- **Asset CDN / external delivery**: the v1.37.0 proxy
  serves from local cache. A future phase could add a
  CDN-backed source ref for very large sets, but the
  current design works for everything up to the per-set
  soft cap.
- **Animal / food placeholder categories**: the spec
  mentioned animal silhouettes + food icons. Both need
  curated icon sets + multi-language lexicons; the avatar
  fallback handles them acceptably until then.
