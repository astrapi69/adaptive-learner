# Adaptive Learner v1.2.0

**Released**: 2026-05-20

Phase 15 — **Backup + Restore.** Single JSON wire format
that spans both storage modes (API/SQLite and Dexie/IndexedDB).
Backups made on either side restore cleanly on the other.
Adds an auto-backup ring in Dexie mode so the most-fragile
storage path keeps a rolling local safety net.

## Added

### 15A — Backend backup service + endpoints

- New ``backend/app/services/backup_service.py``:
  - ``create_backup(db, user_id, storage_mode)`` builds the
    canonical JSON payload by reusing
    ``sync_service.TABLES`` for the 14 sync tables plus two
    backup-only tables
    (``imported_conversations`` / ``imported_messages``).
  - ``restore_backup(db, payload, target_user_id)`` applies
    the merge: insert unknown ids, keep the newer side for
    mutable rows (``updated_at`` / ``assessed_at``
    comparison), skip duplicates for append-only rows,
    never delete.
  - ``get_backup_stats(db, user_id)`` returns per-table row
    counts for the pre-restore comparison UI.
- New ``backend/app/routers/backup.py``:
  - ``GET /api/backup/export?user_id=&storage_mode=`` returns
    the payload as a JSON file with
    ``Content-Disposition: attachment``. Pretty-printed
    (indent=2) so users can open it in a text editor before
    trusting a restore.
  - ``GET /api/backup/stats?user_id=`` for the pre-restore
    diff.
  - ``POST /api/backup/import?user_id=`` accepts the payload
    as the request body and returns the merge summary.
- Security: ``api_key_anthropic`` / ``api_key_openai`` /
  ``api_key_gemini`` are stripped on every export and
  silently dropped on every import. A hand-edited file
  carrying keys cannot poison the live ``UserSettings`` row.
- Defensive user-scoping at every level (``self`` / ``user`` /
  ``via_curriculum`` / ``via_project`` / ``via_session`` /
  ``via_conversation``). A row claiming to belong to a
  different user is skipped on insert and update.
- 26 new pytest cases in
  ``backend/tests/test_backup_service.py`` covering
  round-trip, table coverage, key exclusion, user filtering,
  stats parity, merge semantics in both directions,
  ValidationError on malformed payloads, NotFoundError on
  unknown user, HTTP endpoint contract.

### 15B — Dexie-mode backup and restore

- New ``frontend/src/storage/backup.ts`` mirrors the backend
  byte-for-byte:
  - ``createDexieBackup(userId, appVersion)`` reads all 16
    tables directly from IndexedDB, scoped to one user
    through four indirection patterns.
  - ``restoreDexieBackup(userId, payload)`` applies the same
    MERGE semantics as the backend.
  - ``getDexieBackupStats(userId)`` for the pre-restore diff.
- ``IStorageService`` gets a new ``backup`` namespace; pages
  and Settings depend on the interface, not the mode.
- 19 new Vitest specs in ``backup.test.ts`` covering the
  same matrix as the backend tests, plus a roundtrip with
  ``dexieStorage.backup``.

### 15C — Settings UI with export / import / comparison

- New ``frontend/src/components/BackupSection.tsx`` between
  ``SyncSection`` and ``AboutTab``:
  - "Create Backup" downloads a JSON file via a synthetic
    anchor click and persists
    ``adaptive-learner.last_backup_at`` in localStorage.
  - "Restore from Backup" opens a hidden file picker,
    parses the JSON client-side, shows a 16-row comparison
    table (current vs incoming counts per table) and only
    fires the merge after explicit confirmation.
  - Post-restore summary card lists inserted / updated /
    skipped counts plus an error count when any record
    could not be restored.
  - Reminder banner fires when the last backup is older than
    7 days.
- Strings live under ``backup.*`` in all 8 i18n catalogs:
  DE + EN translated, six others EN passthrough.
- 8 new Vitest specs in ``BackupSection.test.tsx``.

### 15D — Auto-backup rotation in Dexie mode

- New ``frontend/src/storage/auto-backup.ts``:
  - Second IndexedDB database
    (``adaptive-learner-backups``) that does not share a
    transaction surface with the live data DB.
  - Trigger: every 10 completed sessions OR every 7 days,
    whichever fires first. Counter + last-at land in
    localStorage so they survive a tab swap.
  - Capacity: 3 entries per user, oldest rotated out.
  - Toggle: ``adaptive-learner.auto_backup_enabled`` (default
    on in Dexie mode). Manual "Back up now" bypasses the
    toggle.
- Wiring: ``dexieStorage.session.end()`` now calls
  ``recordCompletedSession`` + ``maybeRunAutoBackup`` as a
  fire-and-forget. Errors are swallowed so a failing backup
  never breaks the session-end flow.
- Storage-pressure probe: ``navigator.storage.estimate()``;
  when usage > 90 % of quota the UI surfaces a warning
  urging an explicit file export.
- BackupSection gains a Dexie-only auto-backup block with
  the toggle, the "Back up now" button, the pressure
  banner, and a list of available snapshots with per-row
  Restore + Delete.
- 22 new Vitest specs in ``auto-backup.test.ts``.

## Changed

- ``CLAUDE.md`` "Current state" block now describes the
  v1.2.0 backup + restore surface.

## Security

- Backup files NEVER carry API keys.
  ``EXCLUDED_USER_SETTINGS_FIELDS`` strips them on both the
  backend and the Dexie sides; restore ignores them even if
  a hand-edited file carries injected keys. After a restore
  the user re-enters every provider key.
