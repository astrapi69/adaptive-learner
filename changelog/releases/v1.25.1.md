# Adaptive Learner v1.25.1

**Released**: 2026-05-25

CI-hygiene patch. Closes a multi-release CI-debt cluster that
left the `Backend ruff + mypy`, `Pre-commit hooks`, and
`Coverage Backend Coverage` jobs red across v1.23.2 → v1.25.0.
No user-visible runtime changes. No database schema changes.
No new runtime dependencies. Patch release.

## Why this release

`make test` and `make release-test` ran green on every release
in the v1.23.2 → v1.25.0 window. The aggregate Makefile target
doesn't invoke `ruff check`, `mypy`, or `pre-commit run
--all-files` directly, so a latent set of lint / type / format
violations accumulated under the radar and the per-job CI gates
went red without blocking releases.

v1.25.1 reconciles the gates: `ruff check`, `ruff format
--check`, `pre-commit run --all-files`, and `mypy` are all
clean against `main`. CI's `Backend ruff + mypy` and
`Pre-commit hooks` jobs now go green at the same time as
`Backend Tests`. The `Coverage Backend Coverage` job (fixed
in v1.24.x-era `573ef33` via `app.yaml.example` plugin
re-enablement) also picks up the cleanup.

## What changed

### Ruff (3 errors → 0)

1. `app/main.py`: import block resorted (alphabetical drift
   after a recent `from app.routers.projects` line landed out
   of order).
2. `app/services/sync_service.py`: import block resorted (3
   models added in a previous commit landed out of alphabetical
   order: `AnkiCardSuggestion`, `Badge`, `StudyQuestion`).
3. `app/services/identity_service.py`: `from datetime import
   timezone` → `UTC` (UP017 modernisation; `datetime.now(UTC)`
   is the 3.12+ idiom, `timezone.utc` is the legacy alias).

All three were auto-fixable via `ruff check app/ --fix` —
mechanical, no semantic change.

### Ruff format (2 files)

`app/main.py` (the inspect-plugin endpoint added in `e2f7c3c`)
and `app/services/help_glossary.py` had line-length drift past
the 100-char rule. `ruff format app/` normalised both.

### mypy (2 errors → 0)

`mypy app/` was SKIPPED at v1.25.0 because the `Backend ruff +
mypy` CI job fails fast on ruff before reaching mypy. With ruff
clean, mypy ran and surfaced 2 pre-existing latent errors:

1. `app/services/imports.py:48`: `role = role.value` after a
   `hasattr(role, "value")` check that mypy couldn't narrow
   past `None`. Tightened to `if role is not None and
   hasattr(...)`.
2. `app/main.py:459`: `from adaptive_learner_gamification.
   badge_service import seed_catalog` failed mypy with
   `import-untyped` because the plugin doesn't ship a
   `py.typed` marker. New `[[tool.mypy.overrides]]` in
   `backend/pyproject.toml` matches the existing
   `pluginforge.*` pattern: treat the gamification plugin as
   an untyped external module. Only gamification is imported
   directly by backend code; other plugins load via PluginForge
   entry points and don't need the override.

### Pre-commit (auto-fix on 1 file)

`frontend/src/chat_import/__fixtures__/claude-markdown-export.md`
carried trailing two-space line endings on the metadata header
(Markdown hard-line-break syntax). Pre-commit's
`trailing-whitespace` + `end-of-file-fixer` hooks normalised
it. The Claude.ai parser (`claude_md_parser.ts`) strips
trailing whitespace during tokenisation, so the change is
behaviourally inert. 170 parser tests still pass.
