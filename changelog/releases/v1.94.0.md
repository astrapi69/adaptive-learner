# Adaptive Learner v1.94.0

A launcher-hardening release on top of v1.93.0. The Docker-based desktop
launcher is reworked around a single, never-self-closing window backed by a
pure, fully-tested **Actions** layer, and a series of real-device bugs are
fixed end-to-end (it now builds, starts, and serves on the configured port).
Plus a few learning-UX improvements. No schema, API, or data-model change.

## Added

- **Launcher Actions layer + CLI↔GUI parity (#966).** A single Tk-free
  business-logic module (`actions.py`) that the GUI and CLI both call; every
  action returns `(ok, message)` and **verifies** its result. The headless
  flags `--check / --status / --install / --start / --stop / --uninstall /
  --open` route through it (plus `--version`), so every GUI operation is also
  scriptable. ≥5 unit tests per action (no Tk / no Docker needed); `docker.py`,
  `ports.py`, and `health.py` are reduced to thin wrappers over `actions`
  (#970), with `actions` adopting the stricter semantics (health requires JSON
  `status == "ok"`, port checks bind like Docker publishes).
- **Single persistent launcher window (#984).** Running the launcher from a
  source checkout opens **one** window that shows progress, errors, and success
  **in place** (scrollable status area) and is closed **only** by its window X —
  no dialog chain, no close-and-reopen. Includes an inline, live-validated port
  field (✓/✗ via a real bind check) that persists the chosen port.
- **Lesson retry with improvement tracking (#984/#983)** and a **my-answers ↔
  solution toggle** in the Matching exercise (#978).

## Fixed

- **Launcher works end-to-end (#948, #961, #962).** Fixed the startup crash
  (`StatusWindow` has no `destroy()` → use `close()`), the backend container
  crash (`useradd -r` had no writable home → Fernet `secret.key` EACCES; set
  `HOME=/app/data`), and the dialog/spinner issues; added a `--debug` flag
  (stdout + `launcher-debug.log`), a manual `TESTPLAN.md`, and cleanup scripts.
- **Uninstall actually removes the containers and verifies it (#964).** The old
  path relied on `docker compose down`, which reported success even when it
  removed nothing; it now force-removes by id and re-checks, reporting an honest
  error if a container survives. Also dropped a textless dialog button.
- **Prod Docker build resolves (#954).** `frontend/Dockerfile` uses
  `npm ci --legacy-peer-deps` (the same flag every CI workflow uses), fixing the
  `npm ci` ERESOLVE failure.
- **Correct repo slug + working links (#950, #952).** The launcher used
  `adaptive_learner` (underscore) instead of `adaptive-learner`, 404-ing the
  update check, the download, and the guide links; corrected everywhere, with a
  new Docker-install guide and release links pointing at `/releases/latest`.
- **Default port is 8501, not 7880 (#962).** 7880 is Bibliogon's port;
  defaulting there guaranteed a sibling conflict.
- **Health-check hits the published port (#985).** The chosen port is now
  written to `.env` before `compose up`, so the launcher health-checks exactly
  the port Docker publishes (fixes "did not respond" while the app was up).
- **Start no longer refuses an installed-but-stopped app (#979).** `start` runs
  `compose up -d` (which creates containers) instead of refusing when no
  container exists yet.
- **Launcher uses the local repo from a source checkout (#981)**, so it builds
  the current (fixed) Dockerfile and the correct compose file instead of a stale
  downloaded release in a tmp dir; error details are scrollable.
- **Dialogs no longer close on a browser-open link (#956)** — "Open download
  page" / "Open guide" open the browser and keep the dialog open.
- **i18n catalog completeness (#944)** and several mobile/layout fixes: lesson
  header height (#959), settings danger-zone overflow (#957), sticky progress
  (#959).

## Changed

- Launcher GUI/CLI handlers and the start/install workers now delegate to the
  Actions layer; the classic dialog-chain remains only on the end-user download
  path (until the window grows a download step).
- Developer onboarding guide added/refreshed (#947).
