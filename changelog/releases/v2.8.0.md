# Adaptive Learner v2.8.0

The first release of the 2.7/2.8 line that actually reaches users.
v2.7.0 shipped its tag and notes but no artifacts - the publish chain's
own green-precondition could not read the check status (#2178) and
refused, fail-closed, on every attempt; v2.7.1 was retired unreleased
during preparation. This release therefore deliberately carries BOTH
the distribution switch (the launcher pulls a published image instead
of building) and the state-driven review-progress recovery for the
corrected ja/ko/zh A1 lessons (#2161): the recovery notice appears
ONLY for users whose progress is already orphaned - withholding it
would keep exactly those users in a definitely broken state to protect
them from a possibly imperfect repair that offers a backup first. It
is an offer, user-triggered, never automatic.

## For existing launcher users: the app is now downloaded, not built

Starting with this release line, the desktop launcher no longer builds
the app image on your machine - it downloads a ready-built, verified
image from GitHub's registry (about 110-120 MB compressed). **Your data
is preserved**: the launcher mounts the same Docker volume as before,
and when it finds data in two places it stops and explains instead of
choosing for you. Building from source (`install.sh` / compose) remains
fully supported.

## Fuer bestehende Launcher-Nutzer: die App wird geladen, nicht gebaut

Ab dieser Release-Linie baut der Desktop-Launcher das App-Image nicht
mehr auf deinem Rechner - er laedt ein fertig gebautes, verifiziertes
Image aus der GitHub-Registry (etwa 110-120 MB komprimiert). **Deine
Daten bleiben erhalten**: Der Launcher bindet dasselbe Docker-Volume ein
wie bisher; findet er Daten an zwei Orten, haelt er an und erklaert die
Lage. Selbst bauen (`install.sh` / Compose) bleibt voll unterstuetzt.

## Before you install

AdaptiveLearner runs in Docker. You need Docker Desktop installed and running before starting the launcher.

- [Docker installation guide (English)](https://github.com/astrapi69/adaptive_learner/blob/main/docs/help/en/install/docker-desktop.md) - includes a "Is Docker safe to install?" section
- [Docker-Installationsanleitung (Deutsch)](https://github.com/astrapi69/adaptive_learner/blob/main/docs/help/de/install/docker-desktop.md) - mit Abschnitt "Ist Docker sicher zu installieren?"

The launcher detects Docker, downloads the ready-built AdaptiveLearner image from GitHub's registry (about 110-120 MB compressed, roughly 500 MB on disk - nothing is built on your machine), and opens the app in your browser. Later starts are fast and work offline.

## Download

| Platform | File |
|----------|------|
| Windows | `adaptive-learner-launcher.exe` |
| macOS (Apple silicon) | `adaptive-learner-launcher-macos.zip` |
| Linux | `adaptive-learner-launcher` (ELF binary) |

Each platform also ships a `*.sha256` checksum next to the binary.

## Verifying downloads

```bash
# macOS / Linux
shasum -a 256 adaptive-learner-launcher-<platform>
cat adaptive-learner-launcher-<platform>.sha256
```

```powershell
# Windows
Get-FileHash -Algorithm SHA256 .\adaptive-learner-launcher.exe
Get-Content .\adaptive-learner-launcher.exe.sha256
```

The hashes must match.

If your operating system warns about an unsigned binary, see the [AdaptiveLearner installation overview](https://github.com/astrapi69/adaptive_learner/blob/main/docs/help/en/installation.md).

## What's new in v2.8.0

### Added

- **Review-progress recovery for the corrected ja/ko/zh A1 lessons
  (#2161).** The identity correction in those sets had orphaned existing
  review progress; the app now offers a one-time recovery that remaps it
  onto the corrected lessons - as an offer with user choice, in both
  storage modes.
- **Reorder lessons in "Manage lessons" (#2172).** Display order is
  separate from lesson identity, so reordering never touches progress or
  repetition data.


### Fixed

- **Release publishers can pass their own green gate (#2178).** The
  #2145 precondition queried a bare `commits/<sha>/check-runs` path,
  which `gh api` never resolves against the current repo - so it 404'd
  and failed closed on every release event. The repo now defaults from
  `GITHUB_REPOSITORY`, with regression tests for all three resolution
  cases. The gate's fail-closed behaviour worked as designed throughout;
  v2.7.0 published nothing and stays an empty tag.

### Changed

- **Launcher engine: docker-app-launcher 0.25.1.** The install/update
  progress bar now clears after success AND failure (it previously stuck
  in both cases), operations gain a cancel control with honest per-state
  messaging, and the concurrency guard reports visibly when it cannot
  take effect.
