# Adaptive Learner v0.4.0

**Released**: 2026-05-18

Phase 7 — cycle-step advance, Dashboard polish, model picker,
spaced-repetition cards, plus three smoke-test fixes (multi-
select assessment, Onboarding Skip, returning-user
detection).

## Added

### Cycle-step advance (7A)
- `POST /api/plugins/session/{id}/message` now deterministically
  advances `LearningSession.cycle_step` by 1 on every successful
  user→AI round-trip, capped at 7. Failed AI calls (missing key,
  plugin raised, empty reply, role≠user) leave the step
  unchanged.
- The `/message` response carries the full `LearningSession`
  row so the frontend's `CycleProgress` updates without a
  separate fetch.

### Dashboard enhancements (7B)
- New 5-cell `SessionCounter` tile: streak / total sessions /
  total minutes / mean understanding / mean stress.
- `MethodDistribution` chart now consumes server-computed
  percentages and always renders all 6 methods (including
  zero-count bars) for a stable layout.
- New `RecentSessions` component: keyboard-accessible rows
  that navigate to `/progress` on click / Enter / Space.
- Tracking plugin's progress summary gains `streak_days`,
  `method_distribution`, and `recent_sessions` fields.

### Provider model picker (7C)
- `UserSettings` gains three nullable `model_override_*`
  columns (Anthropic / OpenAI / Gemini). NULL means "use the
  session plugin's `DEFAULT_MODELS` pick"; a non-empty string
  replaces the default for that provider only.
- New Settings UI section ("Model overrides") with a per-
  provider text input + datalist of suggestions + Save / Use
  default buttons. The active provider gets the same
  "Active" badge as the API-keys section.
- `ai_orchestration.resolve_model(provider, override=)` and
  the `/message` handler thread the override through to
  `ai_complete`.
- Alembic migration `0002_user_settings_model_override`.

### Spaced-repetition recommendations (7D)
- New `GET /api/plugins/tools/spaced/{project_id}?lang=`
  route returning up to 5 profile-driven action cards.
  Interval bands derived from each method's most-recent
  `ProgressCommit`: never→1d, >14d→1d, 7-14d→3d, 3-7d→7d,
  <3d→14d.
- New Dashboard "Spaced practice" card. Start button deep-
  links to `/session?method=<key>`; Dismiss hides the card
  for the rest of the local calendar day, persisted to
  `localStorage` so a reload keeps the dismissals.
- `Session.tsx` now reads `?method=` and threads it to
  `api.session.start`.

### Anthropic-first ordering (load-bearing)
- `AI_PROVIDERS` and `AIProvider` enum are documented as
  Anthropic-first by design (not alphabetical). Two
  regression-pin tests prevent a future "looks alphabetical,
  let me tidy it" refactor from re-sorting.

## Changed

### Multi-select assessment (Bug 1, smoke-test fix)
- 7 of 12 questions (q01, q02, q04, q05, q06, q08, q12) now
  render as multi-select checkboxes — these are the questions
  where multiple learning preferences genuinely apply at once.
- The other 5 (q03, q07, q09, q10, q11) stay single-select
  because their answers are mutually exclusive by design.
- `Question` schema gains `type: "single" | "multi"`. Backend
  output includes the field; missing defaults to "single".
- `_AnswerIn` schema accepts BOTH legacy `answer_id: str` and
  new `answer_ids: list[str]`. Backward compatibility preserved
  for existing single-select callers (session + tools
  integration tests).
- `calculate_profile` distributes each multi-pick's weight
  equally across selected answers (`weight / n_picked`) so
  picking 2 doesn't double-count.

### Onboarding Skip flow (Bug 2, smoke-test fix)
- New "Later" button on Onboarding alongside the existing
  Back + Submit. Creates a User with browser-detected language
  plus a localised placeholder LearningProject (topic "My
  learning", goal "Discover my learning style.", "Flexible"
  timeframe, 30 min/day), then lands on `/dashboard` —
  curious visitors are in the app in 2 clicks.

### Returning-user detection (Bug 3, smoke-test fix)
- On Landing mount, if `user_id` is in localStorage, the page
  verifies it via `GET /api/users/{id}` and redirects to
  `/dashboard` on success. 404 clears localStorage and falls
  through to the regular Landing UI; 5xx preserves
  localStorage so a reload can retry.
- First-time visitors (no `user_id` in localStorage) see no
  spinner and no network call — Landing UI renders
  immediately.

## Migrations

- `0002_user_settings_model_override`: adds three nullable
  `String(200)` columns to `user_settings`
  (`model_override_anthropic` / `_openai` / `_gemini`).
  Downgrade-safe — drops all three columns in reverse order.
