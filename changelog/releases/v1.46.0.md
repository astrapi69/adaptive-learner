# Adaptive Learner v1.46.0

**Released**: 2026-05-30

Minor release. **Phase 62 — EXP-018 Exercise Direction (Receptive
vs Productive).** Recognising a word ("Bonjour" = "Guten Tag") and
producing it (type "Bonjour" when shown "Guten Tag") are independent
skills; this release makes that direction explicit end-to-end and
tracks mastery separately for each. Also folds in a P0 fix to the
Save-as-Lesson flow and migrates lesson content out of the app repo.

## Added

- **Exercise direction.** Every exercise carries an optional
  `direction` — `target_to_source` (receptive, default),
  `source_to_target` (productive), or `both` / `random`. Additive;
  schema stays 1.2 and pre-62 content keeps working (defaults to
  receptive).
- **Direction-aware SRS.** `ElementError` gains a `direction` column
  and the per-element uniqueness grows to include it, so a card has
  independent receptive + productive rows with their own
  error/streak/mastery. A card is "fully mastered" only when BOTH
  directions are (`is_fully_mastered` / `isFullyMastered`). Alembic
  `0023` (batch constraint swap + receptive backfill); Dexie schema
  v23 re-keys existing rows under the new `#direction` segment.
- **Direction-aware renderers.** A shared `resolveDirectionDisplay`
  orients the prompt/answer; Matching flips its columns + headers by
  direction; the other renderers show a subtle eye (recognise) /
  pencil (produce) instruction hint. Cloze is in-context and exempt.
  Every recorded attempt stamps its concrete direction centrally.
- **Direction-aware review queue.** Productive errors are weighted
  1.2x (harder, more practice); the same element can surface twice
  (once per direction); the synthesised review drills the direction
  the error was recorded under.
- **Adaptive direction strategy.** The generator gains a
  `direction_strategy` (`auto` / `receptive_first` /
  `productive_focus` / `balanced`, default `auto` — receptive until
  recognition is solid, then productive), fed by a new **Settings >
  Learning → "Preferred exercise direction"** control.
- **Dashboard mastery split.** The Focus Areas card shows a
  receptive / productive mastered-count split.
- **Pilot content direction.** Pilot lessons gained a progressive
  direction (lessons 1-5 receptive, 6-8 mixed, 9-10 mostly
  productive).
- New `lesson.exercise.instruction.*`, `lesson.exercise.direction.*`,
  `settings.direction.*` and `dashboard.focus_areas.mastery_split`
  i18n in all 8 languages.

## Fixed

- **Save-as-Lesson (P0).** Saving a chat analysis as an offline
  lesson produced an unshareable set: identical source/target
  language, no `title_native`, a non-CEFR level
  (`beginner`/`intermediate`/`advanced`), and — for thin analyses —
  zero exercises. The Save modal now detects the target language
  from the topic + asks the user to confirm the language pair, maps
  the level to CEFR (A1/B1/C1), sets `title_native`, and gates Save
  on a shareable lesson (>= 5 exercises across >= 2 types) with a
  clear "not enough data" message. Defense in depth: the generator's
  shareability is checked at save time, not only at sharing time.
- **Direction-instruction testid collision.** The per-direction
  instruction line's testid no longer shadows the
  `picture-choice-` prefix selector (caught by the Dexie playthrough
  gate).

## Changed

- **Lesson content moved to its own repo.** Lesson JSON no longer
  lives in the app repo; it lives in
  `astrapi69/adaptive-learner-content`. The build sources it via
  `ADAPTIVE_LEARNER_CONTENT_DIR` (default: the sibling
  `../adaptive-learner-content` checkout) and fails open if absent;
  the GH-Pages deploy checks the content repo out so the public site
  keeps its bundled offline content (CI-verified). The app repo now
  holds only the content-loader plugin, the bundling pipeline, and
  the schema/validators. `test_pilot_content.py` was removed —
  content validates in the content repo's own CI.
