# Adaptive Learner v1.93.0

A focused launcher + content-dialog release on top of v1.92.0: the Docker-based
desktop launcher gets a Docker-first flow with visible progress and
configurable ports, and the AI content-check dialogs become usable on desktop
(scrollable + dismissable) and now show which provider/model ran the check. No
schema, API, or data-model change.

## Fixed

- **Launcher UX overhaul (#942).** Several fixes to the Docker-based desktop
  launcher:
  - Docker is now the **first** interactive step — a daemon-not-running dialog
    offers "Start Docker Desktop" (best-effort platform launch + poll), so the
    user never reaches a later step before Docker is up.
  - A **status window with a step checklist** (Check Docker / Download / Build /
    Start / Ready) plus a per-step spinner and failure glyphs, for both the
    start and install flows, so a slow first run no longer looks like a crash.
  - The launcher operates on the **host-facing public port**
    (`ADAPTIVE_LEARNER_PUBLIC_PORT`), configurable via `--port`, `launcher.json`,
    or `.env`; a **port conflict** (e.g. with Bibliogon) is detected before
    `compose up` and a free fallback port is suggested and persisted.
  - `docker-compose.prod.yml` pins the project name to **adaptive-learner**
    (explicit `container_name`/`image` per service, fixed internal backend port
    8000 matching the nginx proxy), fixing the nginx<->backend port mismatch;
    uninstall cleanup matches both `adaptive-learner` and the legacy
    `adaptive_learner`.
  - The launcher window uses the **brand icon** from the app branding.
- **AI / quality check dialogs are scrollable + dismissable (#937).** A new
  shared `ModalShell` (scrollable body with a sticky header, an always-visible
  X, Escape, and backdrop-click dismiss, `role="dialog"` + `aria-modal`, focus
  restored to the opener) backs both `AiValidationDialog` and
  `QualityCheckDialog`. On desktop a long report no longer grows past the
  viewport and pushes the Close button off-screen — the user is no longer
  blocked.

## Added

- **AI content-check provenance (#940).** The AI-check result dialog and its
  Markdown export now show **"Checked with: &lt;provider&gt; (&lt;model&gt;)"**
  (and a date in the export). The provider/model were already captured from the
  actual run; a shared `lib/ai/validation-provenance.ts` formats the line so the
  dialog and the export cannot drift. New `content.ai_check.checked_with` /
  `.date` i18n keys in all 11 languages.
