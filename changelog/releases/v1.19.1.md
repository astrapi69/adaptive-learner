# Adaptive Learner v1.19.1

**Released**: 2026-05-22

Patch release. Closes four import-pipeline bugs surfaced by
the Phase 33 audit against a real Claude.ai per-conversation
Markdown export. No new features, no schema changes, no
plugin changes. Backend Pydantic enums + the SQLAlchemy
model graph are untouched; this is entirely a frontend
parser + analyzer fix plus a regression-pin test expansion.

## Fixed

### `fix(chat-import)` — dedicated Claude.ai Markdown parser (BL-25, BL-26, BL-28)

The Claude.ai per-conversation Markdown export (the in-
product `Export as Markdown` button) is the natural surface
for "import this chat" — but the dispatcher routed it to
the generic `markdown_parser`, which classifies header words
against fixed `USER_MARKERS` / `ASSISTANT_MARKERS` allowlists.
Neither `prompt` nor `response` was in either list, so the
entire 73 KB / 50-turn transcript collapsed into a single
`user` message with no role boundaries, no per-turn
timestamps, and `source="manual"`.

Closed by a dedicated `frontend/src/chat_import/claude_md_parser.ts`:

- `isClaudeMarkdownExport` — 3-clause signature sniff (first
  non-blank line is an `H1`, head contains `**Link:**
  https://claude.ai/chat/`, at least one `## Prompt:`
  boundary).
- `parseClaudeMarkdownExport`:
  - Walks `## Prompt:` / `## Response:` exact-string
    boundaries (turn boundary). Internal `## Some Heading`
    lines inside response bodies stay in the body (the
    generic parser would have split mid-response).
  - Extracts the per-turn `D.M.YYYY, HH:MM:SS` timestamp
    line and normalises to ISO-8601 local-naive
    (`YYYY-MM-DDTHH:MM:SS`).
  - Keeps `\`\`\`plaintext` thought-process / tool fences
    inside the surrounding response body.
  - Skips the top-of-file `# Title` + `**Created:**` +
    `**Link:**` metadata block — surfaces the title as the
    conversation title and `**Created:**` as
    `metadata.created_at`.
  - Stamps `source="claude"`.
- Dispatcher (`index.ts`):
  - Auto-detect runs the Claude .md sniff **before** the
    markdown fallback would swallow it.
  - `detectFormat` returns `"claude"` for both the JSON
    bulk-export and the .md per-conversation export (UI
    label parity).
  - New explicit option `format: "claude-md"`; existing
    `format: "claude"` still rejects non-JSON input
    (back-compat preserved).

The generic `markdown_parser` is intentionally unchanged —
it remains the no-marker-found fallback for free-form
pastes from any source. Users who explicitly force
`format: "markdown"` on a Claude .md file still get the old
swallow-everything behaviour, which is the right call for
that parser's contract.

Regression-pinned:
- `claude_md_parser.test.ts` — 20 unit cases (signature
  sniff, turn boundaries, internal `##` headings, plaintext
  fences, timestamp normalisation including single-digit
  day/hour padding, graceful missing-timestamp + garbage-
  first-line, metadata + title extraction, error paths
  including the BL-26 minimal shape).
- `claude_markdown_export.audit.test.ts` — 17 cases against
  the anonymized real fixture (50 messages, every timestamp,
  internal headings preserved, plaintext fences preserved,
  no metadata leakage into bodies).

### `fix(analysis)` — vocabulary extraction in conversation analyzer (BL-27)

The `vocabulary` field had been declared in
`ConversationAnalysisResult` and consumed by the Anki Dexie
path (since v1.17.0 / Phase 30D) and the NotebookLM ZIP
exporter's `vocabulary.md` (since v1.19.0 / Phase 32). But
the `SYSTEM_PROMPT` in `analysis.ts` never asked for it and
`parseAnalysisResponse` never read it — three readers, zero
producers.

Closed:

- `SYSTEM_PROMPT` now lists `vocabulary` as an optional field
  in the JSON schema with explicit field semantics: emit
  only on language-learning topics; per-entry
  `{word, translation}` required; `example` should be a
  real sentence from the transcript (consumer builds cloze
  cards); `phonetic` + `tags` optional. The AI is the gate
  — one prompt, one call, no separate AI call.
- `parseAnalysisResponse` reads `vocabulary` via the new
  `asVocabularyArray` projector (drops malformed entries,
  returns `undefined` on empty so non-language analyses
  don't carry empty arrays).
- `mergeAnalyses` extended with `mergeVocabulary` —
  concatenates + dedupes across chunked-transcript chunks
  by the `(word, translation)` tuple, case-insensitive.

Downstream consumers now have data: the Anki Dexie
"vocabulary path" produces cards from language imports
again; NotebookLM `vocabulary.md` carries entries from any
analyzed language conversation.

Regression-pinned via `analysis.vocabulary.test.ts` — 13
cases (8 parser cases incl. omitted-field, empty-array,
non-array, malformed-tags; 4 merge cases; 1 import-build
pin).

## Phase 33 audit deliverables

Phase 33 was a manual-test + import-audit phase that turned
into a four-commit fix sequence. The audit artefacts are
also part of v1.19.1:

- `scripts/anonymize_chat_export.py` — name + cross-chat-
  reference + chat-URL scrubber. One-shot generator for the
  committed fixture from a raw Claude.ai export under
  `tmp/` (kept out of git).
- `frontend/src/chat_import/__fixtures__/claude-markdown-export.md`
  — the anonymized 73 KB / 50-turn fixture.
- `docs/manual-tests/phase-33-import-audit.md` — full audit
  report including Parts A1–A6 (parser + edge cases),
  Part B manual user-journey plan for browser-driven A2–A5
  verification, Part C bug summary with post-fix closure
  notes.

## What still needs Aster (deferred to manual flow)

A2 (analysis quality), A4 (curriculum from analysis), and
A5 (targeted session start) require a real provider call
against configured API keys. The CLI Phase 33 session
guarantees the AI now **receives correctly-structured input**
(25 user + 25 assistant role-labelled turns across 6
balanced chunks); the AI's response quality on that input
is browser-driven and lives in Part B section B7 of the
audit report.
