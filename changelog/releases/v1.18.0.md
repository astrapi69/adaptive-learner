# Adaptive Learner v1.18.0

**Released**: 2026-05-22

Phase 31 — **Voice Input / Output.** Web Speech API integration
adds text-to-speech for AI responses, speech-to-text for user
input, and a Pronunciation Practice mode for language-learning
projects. All zero-cost client-side — no ElevenLabs, no cloud
service, no API keys. Closes BL-20.

## Added

### 31A — Text-to-Speech (TTS)

- ``frontend/src/lib/voice/speech-synthesis.ts`` wraps
  ``window.speechSynthesis`` with safe async voice loading
  (handles the ``voiceschanged`` event timing), language-
  matched voice selection (exact lang → prefix → bare-prefix
  fallback), and rate/pitch clamping to [0.5, 2.0].
- ``SpeechButton`` component (icon + speaking/idle state)
  hides itself when the browser lacks support OR the user
  has TTS off in Settings.
- Wired into:
  - **SessionChat** — every settled assistant bubble gets a
    speech button.
  - **Assessment results** — "Read summary" button alongside
    Continue.
- 19 pure-helper unit tests + 5 SpeechButton render tests.

### 31B — Speech-to-Text (STT)

- ``frontend/src/lib/voice/speech-recognition.ts`` wraps
  ``webkitSpeechRecognition`` / ``SpeechRecognition`` with
  a callback API (onInterim / onFinal / onError / onEnd)
  and idempotent stop/abort handling (some browsers throw
  on double-call).
- ``MicButton`` component with pulsing-mic visual when
  listening. Hides when the API is unavailable (Firefox)
  or STT is off in Settings.
- Wired into **SessionChat input** — interim transcripts
  populate the textarea so the user sees the phrase build
  up; final transcripts commit there too (the user always
  reviews + clicks Send manually).
- 13 STT wrapper tests + 7 MicButton render tests.

### 31C — Pronunciation Practice Mode

- New backend module
  ``plugins/.../adaptive_learner_session/pronunciation.py``:
  - ``build_phrase_prompt`` + ``parse_phrase_response`` — AI
    generates one target phrase per request, optionally
    avoiding the user's recent practice list.
  - ``build_judge_prompt`` + ``parse_judge_response`` — AI
    compares target vs actual + returns
    ``{matches, score, feedback, missed_sounds}``.
  - ``JudgeVerdict`` dataclass + score-clamping +
    matches-derivation when the AI omits the field.
- New routes on the session plugin:
  - ``POST /api/plugins/session/pronunciation/phrase``
  - ``POST /api/plugins/session/pronunciation/judge``
  - ``GET  /api/plugins/session/pronunciation/eligibility/{project_id}``
- ``_is_language_project`` walks the project's subject
  taxonomy looking for a ``Languages`` (or ``Sprachen``)
  ancestor. Returns ``False`` for projects without subjects
  — intentional graceful degradation (the button stays
  hidden rather than guessing from the topic string).
- New ``/pronunciation`` page implements the
  generate → speak → submit → judge loop with the existing
  SpeechButton + MicButton components.
- Dashboard surfaces a "Pronunciation Practice" quick-start
  button when ``eligibility.eligible`` returns ``true``.
- Pronunciation is **NOT a session** (no cycle, no
  step-evaluator, no XP/streak interaction) and **NOT in the
  42-cell prompt matrix** — it's a separate practice loop
  with its own ephemeral state.
- Dexie mode: eligibility check works locally; the AI calls
  throw ``ApiError(501)`` with a clear "switch to API mode"
  message. Browser-direct AI for pronunciation is deferred
  to a polish patch.
- 16 plugin-side unit tests + 10 backend route integration
  tests.

### 31D — Voice Settings

- ``frontend/src/lib/voice/voicePref.ts`` localStorage prefs:
  - ``ttsEnabled`` / ``sttEnabled`` (default true)
  - ``autoPlayAi`` (default **false** — no surprise sound)
  - ``ttsRate`` / ``ttsPitch`` (default 1.0, clamped)
  - ``ttsVoiceName`` (default empty = auto-pick by lang)
  - ``sttLangOverride`` (default empty = project / UI lang)
  - ``pronunciationEnabled`` (default true)
- ``VoiceSettingsSection`` component mounted in Settings
  between Gamification and Sync. Hides the entire section
  when the browser supports neither TTS nor STT (graceful
  degradation). Renders only the supported half of the
  controls when only one capability is available.
- 24 pref-storage tests + 5 section render tests.

## Migration notes

No database migrations. No new models. No new dependencies.
Existing users will see the new mic + speech buttons start
appearing in the next page load. The defaults are conservative
(auto-play OFF, all features ON only when the browser
supports them) so behaviour stays predictable.

## Browser support

Web Speech API support varies:

| Browser | TTS (speechSynthesis) | STT (SpeechRecognition) |
|---------|----------------------|-------------------------|
| Chrome / Edge | ✅ Good voices, all platforms | ✅ Requires internet |
| Safari | ⚠️ Voices vary, pause flaky | ⚠️ Needs user gesture |
| Firefox | ✅ | ❌ Not implemented |

In all cases, the buttons hide themselves cleanly when the
relevant API is absent — Firefox users see no mic button at
all rather than a broken one.
