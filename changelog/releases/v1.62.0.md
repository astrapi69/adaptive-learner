# Adaptive Learner v1.62.0

Minor release — **backup-restore data-integrity hardening, GitHub-Pages
build provenance, content cache invalidation, and a batch of UI/i18n
conformance fixes**, plus new `.claude/rules` governance. No schema
change; both storage modes (API + Dexie / GitHub-Pages) carry
everything.

## Fixed — backup / restore (data integrity)

- **Restore 500 on `imported_messages.timestamp`** (#57): the restore
  datetime coercion only converted columns whose name ends in `_at`, so
  the `imported_messages.timestamp` `DateTime` column reached the INSERT
  as a raw ISO string and SQLite rejected it. Coercion is now
  **type-driven** — derived from each table's SQLAlchemy model — which
  also covers `user_streaks.last_freeze_earned_on` /
  `last_freeze_used_on` and `user_missions.assigned_date`.
- **Restore "FOREIGN KEY constraint failed" on orphaned rows** (#64):
  after the datetime fix, a restore could abort at the deferred-FK
  commit when an `imported_messages` row referenced a missing
  `imported_conversations` parent. A new FK-parent guard **skips an
  orphaned child row** (recording it in `errors`) instead of poisoning
  the whole restore. A systematic FK-order audit confirmed
  `_RESTORE_ORDER` already orders all 40 cross-table FKs correctly
  (parent before child); the gap was resilience, not order.

## Fixed — content / deployment

- **GitHub Pages showed Build "unknown" / Build date "unknown"** (#66):
  the Dexie build had no backend `git` and the deploy workflow injected
  no provenance. Vite now defines `__BUILD_HASH__` / `__BUILD_DATE__`
  from `VITE_BUILD_HASH` / `VITE_BUILD_DATE`, the Dexie system info reads
  them, and `deploy-gh-pages.yml` exports the short SHA + UTC date before
  the build.
- **Stale content cache on version change** (#62): a re-download at a
  newer content version left the old version cached (stale lessons,
  unbounded growth). The backend `download_set` now calls the existing
  `prune_old_versions`, and Dexie `downloadSetDexie` prunes prior-version
  rows + files. Likely root cause of the phantom "unknown exercise_type"
  on GitHub Pages.

## Fixed — UI / UX / i18n

- **Sync section hidden when no backend** (#51): in Dexie mode (GitHub
  Pages / PWA-only) the Sync section offered dead QR / pairing UI; it is
  now not rendered at all. The three sync roles
  (Desktop-server / Mobile-client / PWA-only) are documented in
  `docs/SYNC-ARCHITECTURE.md` + the `SYNC-UI-GATE` rule.
- **Exercise placeholder distinguishes missing vs unsupported type**
  (#55): a missing `exercise_type` is a content defect ("update the
  content"), not the "ships in a future version" case; the two are now
  separate messages (8 langs).
- **Dashboard filter strings untranslated** (#76): the ~12 `taxonomy.*`
  keys were missing from every catalog; added with real translations in
  all 8 languages + `{count}` interpolation.
- **shadcn button conformance**: Backup section actions (#53), the
  Learning-Repository "Save settings" button (#68), and the Dashboard
  project-row selectors (#78) migrated to shadcn `<Button>` (44px).
- **Settings → Learning: Language panel moved to the top** (#69).

## Changed — governance (`.claude/rules`)

- **GITHUB-ISSUE-PFLICHT** + **ISSUE-LIFECYCLE**: every bug needs a
  GitHub issue (searched first) before the fix; the fix commit/PR closes
  it via `Closes #NN`; applies retroactively to bugs found mid-fix.
- **Issues-as-a-queue** rule for "weiter" / "arbeite Bugs ab".
- **DOC-DOCSTRINGS-NOT-INLINE**: prefer docstrings/TSDoc over inline
  WHAT-comments.
- Adopted Bibliogon's issue/PR templates + 10 labels (`.github/labels.md`).
