# Adaptive Learner v1.26.1

**Released**: 2026-05-26

Patch release. Stops the v1.26.0 Phase 42 Dexie-mode crash
that hit every visitor of the public
[GitHub Pages deployment](https://astrapi69.github.io/adaptive-learner/),
ships a two-tier error-display layer so users never see raw
HTTP errors again, and adds a release-blocking smoke gate
that walks the GH-Pages-shape build before every tag.

No new features. No data model changes. No new endpoints.
Pure quality + stability for the public deployment.

## Why this release

Phase 42 (Learning Repository, v1.26.0) shipped three
components — `LearningRepoSettingsSection`, the `LearningRepo`
page, and `LearningRepoWidget` — that called
`api.pluginSettings.*` / `api.learningRepo.*` directly,
bypassing the storage abstraction. The GitHub Pages workflow
builds with `VITE_STORAGE_MODE=dexie` (no backend), so every
public visitor hit a raw `HTTP 404` toast on Settings,
Dashboard, and the Learning-Repo page for ~24h after v1.26.0.

This release closes the immediate gap (gates each crashing
surface on `resolveStorageMode()` with a friendly fallback
message), addresses the underlying class of bug (production
mode now maps HTTP status codes to friendly i18n strings —
users never see "HTTP 404" or stack traces in toasts), and
adds the regression-prevention layer (a release-blocking
Playwright smoke that walks every nav-reachable route
against the GH-Pages-shape build).

## What changed

### Fixed

- **Phase 42 Dexie-mode crash**:
  `LearningRepoSettingsSection`, `LearningRepo` page, and
  `LearningRepoWidget` now check `resolveStorageMode()` and
  render a friendly "only available in server mode"
  message in Dexie mode instead of firing 404s. The widget
  is hidden from the Dashboard so there's no entry point
  for the unavailable feature. New i18n keys
  `repo.dexie_unavailable_body` + `repo.back_to_dashboard`
  translated for all 8 catalogues.

### Added

- **Developer Mode toggle** (Settings > Interface). Off by
  default. When on, error toasts render the full technical
  message (status code, endpoint, stack trace) and a small
  red **DEV** badge appears in the navigation bar. The
  Phase 37 "Report Issue" button still submits the full
  technical detail in both modes — production users see
  the friendly toast but the GitHub issue body keeps the
  full diagnostic context.

- **Friendly error message mapping**. `notify.error()` now
  distinguishes the toast text from the technical message
  for the report dialog. When production mode + ApiError
  are present, the toast renders a status-code-mapped
  friendly string (`ui.errors.404` → "This page or feature
  was not found.", `ui.errors.502` → "The AI service is
  currently unreachable.", etc.). Eleven friendly strings
  per catalogue × 8 catalogues = 88 new translations.

- **Dexie-mode release gate** (`make test-dexie-smoke`).
  Builds the frontend with `VITE_STORAGE_MODE=dexie` and
  runs 15 Playwright specs against a `vite preview` static
  server with NO backend. Each spec asserts no uncaught
  errors, no `.Toastify__toast--error`, and either the
  expected page testid or a graceful redirect target.
  Aggregated into `make release-test` as a MANDATORY step
  — a red gate now blocks the tag the same way a red
  `make test` does. The gate ships green for this
  release.

### Changed

- **Bundle size**: route-level code-splitting via
  `React.lazy()`. Main JS chunk dropped 2,137 kB → 838 kB
  (61% reduction). The `[INEFFECTIVE_DYNAMIC_IMPORT]`
  warnings for `eventRecorder.ts` AND `gamification.ts`
  cleared. The 4 MB `maximumFileSizeToCacheInBytes`
  workaround in `vite.config.ts` is removed; the build
  succeeds under Workbox's 2 MB default precache cap.
  Closed `BUNDLE-SIZE-DYNAMIC-IMPORT-01`.

- **Lessons-learned rule**: new "Dexie-mode is part of the
  contract: same-commit or not at all". Any new feature
  whose default path makes an API call must route through
  `getStorage()` OR ship a friendly Dexie-mode fallback
  **in the same commit** — never deferred to a follow-up.
  The Phase 42 incident is the concrete example.

## Testing

- 1504/1504 frontend Vitest tests green (+25 over v1.26.0).
- 15/15 Dexie-mode Playwright smoke specs green (~20s).
- Production builds verified in both API and Dexie modes
  under Workbox's default 2 MB precache cap.

## What's deferred

- `PHASE-42-STORAGE-ABSTRACTION-01` (P0, open): the proper
  architectural cleanup — port `pluginSettings` +
  `learningRepo` into `IStorageService`, run the renderer
  client-side over the Dexie DB so the feature actually
  *works* in Dexie mode instead of merely degrading
  gracefully. Substantial work (porting
  `backend/app/services/learning_repo` to TypeScript) and
  intentionally not bundled into a patch release. The
  friendly fallback + the smoke gate protect users in the
  meantime.

## Upgrade notes

None. No migrations, no breaking changes, no config moves.
`v1.26.0` → `v1.26.1` is a drop-in replacement.
