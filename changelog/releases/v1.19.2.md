# Adaptive Learner v1.19.2

**Released**: 2026-05-22

Hotfix release. Closes BL-29 — a 422 ``Unprocessable Entity``
on every Claude.ai .md import attempt that v1.19.1 introduced.
No new features, no schema changes, no plugin changes.

## Fixed

### `fix(chat-import)` — locale-aware ISO normalisation for `metadata.created_at` (BL-29)

v1.19.1's new `claude_md_parser.ts` extracted the
`**Created:**` metadata line and exposed it as
`metadata.created_at` — verbatim, in whatever locale the
exporter's browser had at export time:

- US exports: `M/D/YYYY H:MM:SS` (e.g. `3/23/2026 8:53:40`)
- DE exports: `D.M.YYYY HH:MM:SS` (e.g. `23.3.2026 08:53:40`)

`Import.tsx` forwards `convo.metadata.created_at ?? null` as
the `source_created_at` field on the import POST body. The
backend Pydantic schema declares
`source_created_at: datetime | None`, which **only** accepts
ISO-8601 or `None`. Pydantic v2 rejected both locale shapes
with HTTP 422:

```
ts: Input should be a valid datetime or date, invalid character in year
[type=datetime_from_date_parsing, input_value='3/23/2026 8:53:40', ...]
```

Result: every import attempt on a Claude.ai .md export
failed at the API layer immediately after v1.19.1 shipped.

Closed by `normaliseMetadataDate` in
`frontend/src/chat_import/claude_md_parser.ts`:

- US locale `M/D/YYYY H:MM:SS` → ISO-8601 local-naive
  (`2026-03-23T08:53:40`)
- DE locale `D.M.YYYY[, ]HH:MM:SS` → same shape
- ISO already → pass through, normalising `T` separator
- Unrecognised shape → `undefined` (the caller drops the
  field rather than passing a string the backend will
  reject)

The per-turn timestamps in the parser were ALREADY emitted
as ISO-8601 naive (`2026-03-23T08:53:41`) via the existing
`normaliseTimestamp` helper, so this hotfix only touches
the metadata-block date.

Regression-pinned via 4 new cases in
`claude_md_parser.test.ts` covering US + DE-with-comma +
DE-without-comma + ISO pass-through + unrecognised → undefined.
The existing audit case at
`claude_markdown_export.audit.test.ts` is re-pointed at the
ISO output and re-labelled `BL-29 closed`.
