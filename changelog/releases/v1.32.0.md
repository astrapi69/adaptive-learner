# Adaptive Learner v1.32.0

**Released**: 2026-05-27

Phase 49 — **Learning Repo Storage Abstraction** (closes
PHASE-42-STORAGE-ABSTRACTION-01, open since v1.26.1). The
Learning Repository feature — Git-backed Markdown artefact
generation for every learning project, shipped in v1.26.0 as
Phase 42 — now works in **both** storage modes. Dexie-mode
users visiting `https://astrapi69.github.io/adaptive-learner/`
get the full render + ZIP-download surface client-side
instead of the v1.26.1 "only available in server mode"
placeholder panel.

## Why this release

v1.26.0 shipped the Learning Repository as an API-mode-only
feature: the FastAPI backend rendered the project tree into
Markdown, optionally `git commit`-ed it under a per-project
directory, and the frontend just navigated to the rendered
result. v1.26.1 patched a Dexie-mode crash with a friendly
"not available in browser mode" message — but the underlying
feature stayed gated for every GitHub Pages visitor.

PHASE-42-STORAGE-ABSTRACTION-01 has been the last
load-bearing P0 in the backlog ever since: the public landing
page advertised the feature, and visitors who clicked through
hit a dead end. v1.32.0 finally closes it.

The architectural choice was to **port the Python renderer to
TypeScript** rather than ship a separate Dexie-only design.
That keeps the data contract honest (decision: renderers
produce byte-identical Markdown on shared inputs) and the
parity test (49F) proves it: load the same RenderContext into
both renderers, both produce the same goldens, both pass.
**Parity passed on the first run** — no drift between Python
and TypeScript output.

After v1.32.0, the only Learning Repository feature that
stays server-side is `git persist`: it needs a filesystem
+ git binary to write commits + tags. The button is disabled
in Dexie mode with a friendly tooltip explaining why.

## What changed

### Added

#### Sub-phase 49A — pluginSettings namespace + bundling

- New `IPluginSettingsNamespace` on `IStorageService` with
  `get(name)` / `update(name, body)`. Response shape mirrors
  the API's `{plugin, settings}` payload 1:1 so consumers
  don't branch on storage mode.
- `ApiStorage.pluginSettings` delegates to the existing
  `api.pluginSettings.{get,update}` helpers (v1.26.0).
- `DexieStorage.pluginSettings` owns a new `pluginSettings`
  IndexedDB table (Dexie schema v18 → v19, additive `&name`
  primary key). On first `get` for a plugin without a row,
  falls back to the bundled YAML defaults at
  `frontend/src/data/plugin-config/{name}.json`. Unknown
  plugins return `{}` (defensive).
- New `scripts/sync_plugin_config_to_frontend.py` mirrors
  the existing `sync_i18n_to_frontend.py` shape: reads
  every `backend/config/plugins/*.yaml`, unwraps the
  `settings:` block, writes JSON. New `make sync-plugin-
  config` target.
- 5 plugin configs bundled (anki, content-loader,
  gamification, learning-repo, session).
- Drift-pin Vitest `plugin-config-sync.test.ts` catches a
  contributor who adds a YAML without regenerating.

#### Sub-phase 49B — RenderContext + Dexie loader

- New `frontend/src/lib/learning-repo/render-context.ts`:
  pure types (`ProjectData` / `SessionData` / `RatingData` /
  `StepEvaluationData` / `MethodSwitchData` /
  `SessionNoteData` / `TopicSlice` / `RenderContext`) that
  mirror the Python dataclass shapes 1:1. Pure-functional
  helpers (`ratingsFor` / `latestRating` / `notesFor` /
  `stepEvalsFor` / `notesByKind` / `methodDistribution`)
  replace the Python dataclass methods. `deriveTopics`
  ports the Python `derive_topics` byte-for-byte:
  ISO-timestamp sort, first-appearance order, dedupe of
  session_ids + methods per topic, malformed-JSON-silent,
  whitespace-trim. `buildRenderContext` is the pure
  "row tuples → context" transform.
- New `load-context-dexie.ts`: queries
  learning_projects / sessions / ratings / step_evaluations
  / session_notes / method_switches from IndexedDB via
  `getDb()`, maps Dexie row types to renderer data types,
  hands to `buildRenderContext`. Throws `ApiError(404)`
  on missing project — mirrors backend semantics.

#### Sub-phase 49C — README + STATS renderers + thresholds + labels

- New `labels.ts`: `Labels` interface (53 fields) +
  `DEFAULT_LABELS` (English defaults mirror Python's
  `@dataclass(frozen=True)` defaults) + `labelsFor(language)`
  factory reads the bundled `frontend/src/data/i18n/{lang}.json`
  `repo.*` block. `formatLabel` substitutes `{name}`
  placeholders. Same robustness contract as Python's
  `labels_for` — missing keys silently fall back.
- New `thresholds.ts`: ports Article-1 § 8 exit-threshold
  logic 1:1. `meetsPerSessionBar` (Understanding ≥ 9/10
  AND Transfer ≥ 8/10), `exitThresholdIndices`,
  `latestExitThresholdCycle`. Shared between the stats
  renderer and the future TS git-tagger if/when it lands.
- New `topic-folder-slug.ts`: `topicFolderName(order, title)`
  ports Python's `_topic_folder_name`. `NN_slug` shape with
  Unicode-aware lowercasing + non-alphanumeric → underscore
  + collapse runs + strip + `topic` fallback. Used by the
  README renderer (links) and the topic-folder generator.
- New `renderers/readme.ts`: README.md renderer. Section
  order matches Python: title (with `{topic}` substituted)
  → goal → status (active/archived) → progress (sessions +
  cycles count) → method-distribution (count desc + alpha
  tiebreak, only when non-empty) → topics (link list or
  no-topics placeholder) → see-also block.
- New `renderers/stats.ts`: LEARNING_STATS.md renderer.
  Per-session table (header + dash row + per-session row
  with /10-scaled understanding / transfer / stress +
  cycles + status; exit-threshold marker appended when
  pinned), method-switch table (sorted, pipe escape,
  newline flatten, YYYY-MM-DD date slice), exit-thresholds
  reminder block.

#### Sub-phase 49D — CHEATSHEET + ROADMAP + topic folders + orchestrator

- New `renderers/cheatsheet.ts`: Notes section
  (`kind="note"`, deduplicated by case-insensitive trimmed
  content) + Meta-Learning Insights section
  (`kind="meta_learning"`). Multi-line notes flattened to a
  single bullet via `content.split(/\s+/).filter(...).join(" ")`.
- New `renderers/roadmap.ts`: next-step suggestion priority
  chain (active → resume / most-recent-completed → start
  next / any sessions all-abandoned → start first / no
  sessions → placeholder) + open-topics block with N
  sessions + methods.
- New `topic-folders.ts`: per-topic `NN_slug/README.md`
  stub via `topicFolderName`. Title + parent link +
  sessions (8-char short_id in backticks) + methods.
- New `renderer.ts`: orchestrator. Pure function. Builds
  the 4-meta-file map, merges in topic-folder stubs. Same
  return shape as the backend `/render` endpoint.

#### Sub-phase 49E — DexieStorage.learningRepo namespace + ZIP

- New `ILearningRepoNamespace` on `IStorageService` with
  `render()` + `exportZip()`.
- `ApiStorage.learningRepo` delegates to the existing
  v1.26.0 backend endpoints.
- `DexieStorage.learningRepo`:
  - `render(projectId, language)`: dynamic-imports
    `loadDexieContext` + `renderRepository`, builds the
    context from IndexedDB, runs the TS renderer.
  - `exportZip(projectId, language)`: same render path
    + JSZip packs the `{path: content}` map into a Blob.
    Dynamic-imports JSZip (same pattern as
    `lib/anki/apkg-builder.ts`) so the ~190 kB chunk
    isn't paid on cold load.
- Git-persist endpoint NOT in the namespace by design
  (decision F): server-only, needs filesystem + git
  binary.
- LearningRepo page swaps the two `api.learningRepo.*`
  callsites that use render + exportZip to use
  `getStorage().learningRepo.*`.

#### Sub-phase 49F — Cross-renderer parity (Python == TypeScript)

- New shared fixture at
  `tests/fixtures/learning-repo-parity/input.json`: a
  representative project with 3 sessions across 2
  methods, 2 ratings (both qualify for the exit-threshold
  pin), 1 step evaluation, 1 method switch, 2 notes (one
  `kind="note"`, one `kind="meta_learning"` with
  multi-line content), 2 topics derived from cycle_topics.
- New shared golden tree at `tests/fixtures/learning-repo-
  parity/expected/`: 4 root meta-files + 2 topic-folder
  stubs.
- Python parity test
  (`plugins/.../learning-repo/tests/test_parity.py`):
  loads fixture, builds RenderContext via
  `parity_helpers.load_parity_context` (SimpleNamespace
  adapter so the fixture exercises the renderer without
  SQLAlchemy models), asserts each output equals the
  matching golden. Regen mode via
  `LEARNING_REPO_PARITY_REGEN=1`.
- TS parity test
  (`frontend/src/lib/learning-repo/parity.test.ts`):
  reads the same fixture via Node's fs, calls
  `buildRenderContext` + `renderRepository`, asserts
  byte-for-byte equality + that the renderer-output keys
  match the golden-file set.
- **Parity passed on the first run.** No drift between
  Python and TypeScript output for the fixture.

#### Sub-phase 49G — Remove Dexie-mode fallback messages

- `LearningRepoSettingsSection.tsx`: dropped the
  `storageMode !== "api"` gate + "dexie-unavailable"
  return panel. Swapped `api.pluginSettings.*` →
  `getStorage().pluginSettings.*`. Initial load works
  in both modes via the 49A namespace.
- `pages/LearningRepo.tsx`: dropped the page-body gate
  + the `loadRepo` gate. Render fires in both modes via
  the 49E namespace. The "Persist to git" button stays
  disabled in Dexie mode with a friendly tooltip
  ("Git versioning is only available in server mode").
  404 response now navigates silently (no error toast).
- `pages/Dashboard.tsx`: dropped the
  `resolveStorageMode() === "api"` half of the
  `LearningRepoWidget` visibility gate. The widget
  renders in both modes when a project exists.
- Dexie-mode smoke spec updated: route's expected
  testids now reflect the working page; widget-hidden
  test reframed (hides when no project exists; works
  in both modes).

### Architecture cleanup as a side effect

The IStorageService surface area grew by 2 namespaces this
release (`pluginSettings`, `learningRepo`) — the first
namespace additions since v1.30.0's `elementErrors`. With
49G's component swaps, the Dexie-mode crash surface from
the v1.26.1 audit is fully closed: every component that
used to call `api.*` directly in a context where the
backend might not exist now routes through `getStorage()`.

## Upgrade notes

- **Dexie schema v18 → v19** adds the `pluginSettings`
  table. Additive migration; no data conversion. Existing
  Dexie-mode users get the transparent upgrade on first
  load.
- **No backend schema changes.** The Learning Repository
  feature uses existing tables (learning_projects /
  learning_sessions / session_ratings / step_evaluations /
  session_notes / method_switches).
- **No new i18n keys.** The TS renderer reads the same
  `repo.*` block from the bundled catalog that the Python
  side reads from the YAML. Both go through
  `sync_i18n_to_frontend.py`.
- **No breaking changes** to existing routes, schemas, or
  storage shapes. ApiStorage's `learningRepo` namespace is
  additive; existing `api.learningRepo.persist` callers
  keep working (the namespace intentionally doesn't
  include `persist`, so the page still calls
  `api.learningRepo.persist` directly in API mode).
- **Dexie-mode git persist** is NOT supported and never
  will be — needs server-side filesystem + git binary.
  The button is disabled with a tooltip in Dexie mode.
- **Bundled plugin-config JSON files** ship 5 new files
  under `frontend/src/data/plugin-config/`. Regenerate
  via `make sync-plugin-config` after editing any
  `backend/config/plugins/*.yaml`. Drift-pinned by
  `plugin-config-sync.test.ts`.
