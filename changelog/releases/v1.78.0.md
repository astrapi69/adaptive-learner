# Adaptive Learner v1.78.0

Maintenance / code-hygiene release. No schema / API / data-model change and
no user-facing behaviour change. Three threads: the **complexity burn-down**
(the grandfathered `.complexity-baseline` offenders decomposed one at a time,
each PR shrinking the hard ratchet), two **governance rules** (Release-Freeze
and No-Amend) added to the Vibe Coding Policy, and two **flaky-test fixes** that
let `pytest-randomly` run on by default. Plus the EXP-025 / EXP-026 design
explorations. 29 commits since v1.77.0.

## Changed

- **Complexity gate Phase 2 — hard ratchet (#408).** `scripts/complexity_gate.py`
  / `make check-complexity-gate` is now a blocking CI gate (`complexity-check.yml`):
  a NEW over-threshold file, or a regression above a file's frozen worst-cc,
  fails the build. The `.complexity-baseline` is the per-file ratchet; it may
  only shrink, via `make check-complexity-gate-update`.

- **`routes.py` god-file split (#412).** The 1156-line session
  `routes.py` decomposed into focused route modules — the last entry on the
  backend cohesion baseline, which is now empty (`.filesize-baseline` clear;
  every god-file is under the 1000-line ERROR threshold).

- **Complexity burn-down across backend + frontend.** Each decomposition is
  behaviour-preserving with tests green throughout; the cyclomatic complexity
  of the named unit drops to the value shown:
  - `LessonPage` 67 → 12 (#418)
  - `ImportDetail` 58 → 18 (#420)
  - backup-diff `previewRow` switch → strategy map, 54 → 3 (#422)
  - `buildContentSetRow` 49 → 13 (#424)
  - `AiSettingsPanel` → extracted `ApiKeyRow`, 45 → 9 (#428)
  - `MatchingExercise` 45 / 32 / 24 → ≤ 17 (#433)
  - session `build_analysis_context` 33 → 3 (#416)
  - storage `buildAnalysisContext` (prompts) 33 → 3 (#448)
  - `formatEventLog` switch → formatter map, 40 → 4 (#436)
  - `NextStepSuggestions` → per-card components, 36 → 14 (#438)
  - `useNextStepSuggestions` fetch effect, 29 → 12 (#456)
  - `FreeTextExercise` 31 → 20 (#442)
  - `PictureChoiceExercise` + tile, 27 / 31 → ≤ 18 (#444)
  - `WordTilesExercise` 30 → 20 (#446)
  - `ClozeExercise` 29 → 17 (#458)
  - `ContentSetRow` via a reusable `ListRow` primitive, 28 → 8 (#460)
  - `validateLesson` split into per-concern checks, 30 → ~1 (#450)
  - `Navigation` + extracted `MenuToggleButton`, 30 → 12 (#452)
  - `parseChatImport` explicit/auto dispatch split, 30 → 6 (#454)

- **Vibe Coding Policy governance.** Two rules added so process discipline is
  written down, not folklore:
  - **Release-Freeze (#410):** while a `release/X.Y.Z` branch is open, no new
    PRs / merges to `develop` until the release is tagged and published — only
    the release workflow (exception: a P0 hotfix that blocks the release).
  - **No-Amend on open PRs** (`.claude/rules/coding-standards.md` § Git): never
    `--amend` + force-push a PR that could merge concurrently; add a NEW commit
    instead (origin: the #412 / #414 force-push that merged the pre-amend
    commit and dropped an eof fix).

## Fixed

- **`lesson-tts` Dexie-smoke flake (#165, PR #425).** The spec was deterministic-
  failing, not timeout-flaky: it asserted a follow-along view that #147
  intentionally removed in v1.68.0. Realigned to the intended behaviour
  (mini-player + engine checks; dropped the stale follow-along assertions) and
  given deterministic setup.

- **pytest-randomly reactivated (#426, PR #429).** Back in the backend dev deps,
  so `make test` (backend + plugins via the backend venv) runs under a random
  order and catches test-ordering / shared-state leaks. The suite is robust
  across seeds.

- **`.filesize-baseline` trailing blank line (#414).** `scripts/check-file-sizes.sh`
  now handles an empty baseline cleanly (the success state once every god-file
  is split).
