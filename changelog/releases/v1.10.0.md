# Adaptive Learner v1.10.0

**Released**: 2026-05-21

Phase 23 — **Swipe Gestures on Assessment + Session.** A
reusable touch-gesture hook + four consumer wirings that bring
iOS-style swipe interaction to the mobile UX. Everything is
ADDITIVE: all existing button + click navigation stays, and
the gestures themselves are opt-in via the new Settings
toggle (default ON for touch-capable devices, OFF for
desktop). Closes BL-08 (deferred from Phase 9 / v0.6.0
Mobile PWA).

## Added

### 23A — useSwipe hook

- ``frontend/src/hooks/useSwipe.ts`` — typed React hook that
  attaches passive touch listeners to a ref'd container and
  fires ``onSwipeLeft`` / ``onSwipeRight`` callbacks on a
  completed horizontal flick.
- Contract: ``|dx| > |dy|`` (so vertical scroll is never
  hijacked); default 50 px threshold; velocity floor ~0.15
  px/ms; ``prefers-reduced-motion`` doubles the threshold to
  100 px; ``enabled=false`` detaches listeners entirely.
- ``hapticSwipe()`` helper for ``navigator.vibrate(10)`` with
  safe no-op fallback.
- 10 unit tests pin every threshold + velocity + intent path.

### 23B — Assessment swipe + keyboard navigation

- Swipe-left = next question (Submit on the last one with all
  answers filled); swipe-right = previous question.
- Arrow-left / arrow-right keyboard equivalents. Suppressed
  when an INPUT/TEXTAREA/SELECT has focus.
- 200 ms GPU-accelerated slide animation on transition,
  honouring ``prefers-reduced-motion``.
- First-question swipe hint shown ONCE per user; persisted in
  localStorage and never returns after any navigation action.
- Haptic feedback on every successful navigation when
  supported.

### 23C — Session CycleProgress swipe-to-peek

- Swipe left / right on the CycleProgress component to
  surface a brief overlay describing the previous or next
  cycle step.
- INFORMATIONAL only: the user cannot skip AI-driven cycle
  steps. Auto-dismisses after 2 s; tap-to-dismiss supported.
- Overlay reads the existing ``cycle_steps.{key}.description``
  i18n keys (already present since v0.5.0).
- Out-of-range targets (step 0 or step 8) render nothing.

### 23D — Curriculum topic swipe-to-reveal

- iOS-style swipe-to-reveal on the per-topic row.
  Swipe-left exposes the per-row action buttons (add, rename,
  delete) with a subtle accent left-border highlight;
  swipe-right or tap-anywhere-else collapses back.
- Clicks on the action buttons themselves fire the handler
  AND keep the row revealed so the user can chain further
  actions.
- Desktop layout unchanged (actions remain visible on hover);
  the hidden-by-default → swipe-to-reveal transition only
  applies on mobile (``@media (max-width: 768px)``).

### 23E — Settings gesture toggle

- New "Interface" section with a single checkbox toggle.
  Persists to
  ``localStorage["adaptive-learner.gestures_enabled"]`` —
  the same key the four consumer surfaces read via
  ``readGesturePref()``.
- Default: ON for touch-capable devices
  (``navigator.maxTouchPoints > 0``), OFF otherwise.
- i18n keys ``settings.section_ui`` +
  ``settings.gestures`` + ``settings.gestures_description``
  added to all 8 catalogs (DE + EN hand-translated, 6 EN
  passthrough).

## Migration

No breaking changes at any layer. Default gesture state
falls through cleanly:

- Touch-capable devices that have never visited Settings
  see gestures ON.
- Desktop / non-touch devices see gestures OFF and use
  keyboard arrows in Assessment as the equivalent
  enhancement.

Existing assessment / session / curriculum flows are
unchanged for users who never touch the new toggle and
never swipe — every button click + keyboard interaction
continues to work exactly as in v1.9.0.
