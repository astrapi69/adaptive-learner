# Adaptive Learner v1.33.0

**Released**: 2026-05-28

Phase 50 — **Dexie-Mode Lesson-XP Parity + i18n Repo-Key Fix
+ Bibliogon-Residue Cleanup**. Three real-user bugs/gaps that
were affecting GitHub-Pages visitors right now, closed together
in one release.

## Why this release

Three concurrent items:

1. **Dexie-mode lesson-XP gap** (D-DEXIE-GAMIFICATION). v1.31.0
   closed the lesson-XP loop for API-mode users (Phase 46E.1
   dispatches on `session.method="content"` through the existing
   `on_session_complete` hook; the gamification plugin's
   `award_xp_for_lesson_session` does the DB write). Dexie-mode
   users got `LessonProgress` + `ElementError` + the review queue
   in v1.30.0–v1.31.0 but NOT the lesson-XP / lesson-badge side
   effects (no backend, no hook). Completing a lesson on
   `https://astrapi69.github.io/adaptive-learner/` left their XP
   total unchanged. v1.33.0 closes that loop client-side using
   the same shared-fixture + parity-test methodology proven in
   Phase 49F.
2. **Broken i18n for `repo.*` button labels**. Frontend code
   calls `t("repo.action.rerender", ...)`, `t("repo.settings.toast.saved", ...)`,
   and 22 other dotted paths. The YAML catalogs stored them as
   flat keys (`action_rerender`, `settings_toast_saved`). The
   `t()` walker walks dotted paths and never resolved them, so
   every Learning Repository button + toast displayed in English
   regardless of UI language for ~6 releases (v1.26.0..v1.32.0).
3. **Bibliogon-residue cleanup**. `.claude/rules/` and
   `docs/journal/` carried significant inherited Bibliogon-domain
   prose (book-authoring metaphors, KDP/BISAC references,
   manuscripta export pipeline, audiobook/ElevenLabs lessons,
   Article/Book parallel-surface incidents). Every CC session was
   silently anchored on the wrong domain. This release rewrites
   `architecture.md` end-to-end and halves `lessons-learned.md`.

## What changed

### Added

#### Phase 50A — Lesson-XP parity scaffold + Python goldens

- New `tests/fixtures/lesson-xp-parity/input.json` with 10
  `compute_stars` cases (band edges 0/50%/75%/90%, zero/negative
  total guards, perfect score) + 13 `calculate_xp` cases (every
  star band × first_attempt × streak multiplier branch including
  the 7-day cap + negative/over-3 stars clamping).
- Per-case golden JSON files at
  `tests/fixtures/lesson-xp-parity/expected/{case}.json`. 2-space
  indent, sorted keys, trailing newline — the same shape the TS
  side emits via `JSON.stringify`.
- `plugins/adaptive-learner-plugin-gamification/tests/test_xp_parity.py`:
  Python parity tests pinning `compute_stars` (inline expected)
  + `calculate_lesson_session_xp` (per-case goldens). Golden-file-
  set cross-check catches contributors who add fixture cases
  without regenerating. Regen via `LESSON_XP_PARITY_REGEN=1`.

#### Phase 50B — TypeScript lesson-XP rule

- New `frontend/src/lib/gamification/lesson-xp.ts`: pure
  functions `computeStars` + `calculateLessonSessionXp` mirroring
  the Python `xp_service` line-by-line. Snake_case throughout per
  the parity contract + Phase 49 RenderContext convention.
  Includes a private `pythonRound` helper (banker's-rounding) to
  protect against `Math.round` divergence on exact-`N.5` results.
- New `frontend/src/lib/gamification/lesson-xp.parity.test.ts`:
  loads the shared fixture, runs both functions, asserts
  byte-for-byte equal against the Python goldens. **Parity passed
  on the FIRST run** — same outcome as the Phase 49F renderer
  port, validates the methodology a second time.

#### Phase 50C — TypeScript streak + first-attempt helpers

- New `frontend/src/lib/gamification/streak.ts`:
  `currentStreakDays(activity_dates: Set<string>, today: string)`.
  ISO date strings (YYYY-MM-DD) instead of `Date` instances to
  avoid TZ-induced off-by-one. UTC date arithmetic via `Date.UTC`.
- New `frontend/src/lib/gamification/first-attempt.ts`:
  `isFirstAttempt(step_results: string | null)`. Mirrors the
  Python `is_first_attempt_from_step_results` conservative-on-
  missing-data behaviour; `isPlainObject` guard rejects arrays
  + null + non-objects.
- Python side: extracted `is_first_attempt_from_step_results`
  pure helper from the DB-aware `_is_first_attempt` so the
  JSON-parsing logic is testable cross-language without a DB.
  Added an explicit `isinstance(attempts, bool): continue` guard
  for symmetry with the TS port's `typeof === "number"`.
- 9 streak cases + 15 first-attempt cases appended to
  `input.json` (with inline expected values, no per-case goldens
  needed for boolean/integer outputs).

#### Phase 50D — Dexie-mode lesson-XP on completion

- New `frontend/src/storage/lesson-xp-dexie.ts`:
  `awardLessonXpDexie(userId, LessonProgress)`. Composes the
  parity-tested helpers from 50B-C + reuses `persistXP` +
  `userActivityDates` from the existing session-XP wiring in
  `storage/gamification.ts` (added `export` to both; no
  behaviour change).
- `DexieStorage.lessonProgress.upsert` facade now reads the
  existing row, detects the `in_progress` → `completed` transition,
  and fires `awardLessonXpDexie` + `evaluateBadgesForUser` in a
  try/catch (same defensive shape as the session-end XP wiring
  at `tracking.end`). Re-upserting an already-completed row is a
  no-op for XP. Incremental `in_progress` upserts do not award XP.
- 8 end-to-end tests cover the 4 XP-formula branches (3-star +
  first + streak, attempts > 1, no streak, below 50%), the
  singleton-row-accumulation invariant, the `in_progress` →
  `completed` hook firing, the no-double-award contract, and the
  no-fire-on-in-progress invariant.

#### Phase 50E — Lesson-badge predicates (TS)

- 4 lesson badges added to `BUNDLED_BADGES` (`first_lesson`,
  `lessons_10`, `three_star_streak`, `review_master`); catalog
  now 28 entries, lockstep pin updated.
- 3 new private helpers in `storage/badges.ts`:
  `completedLessonCount`, `lastNLessonsAllThreeStar` (top-N by
  `completed_at` desc, every `computeStars == 3`),
  `masteredElementsCount`. Helpers mirror their Python siblings
  line-by-line.
- 4 evaluators registered in `EVALUATORS` with the same threshold
  arithmetic as the Python registry (≥ 1 / 10 / n=3 / 50).
- 7 round-trip tests cover: `first_lesson` awarded on first
  completion + NOT on `in_progress`, `lessons_10` fires only at
  the 10th, `three_star_streak` fires after 3 consecutive 3-star
  + NOT when the most recent is 2-star, `review_master` fires at
  50 mastered elements + NOT at 49.

### Fixed

#### i18n `repo.*` keys silently broken since v1.26.0

- `backend/config/i18n/*.yaml` (all 8 catalogs): nested 23 flat
  keys under their dotted-path subsections — `page.*`, `action.*`,
  `toast.*`, `error.*`, `widget.*`, `settings.*`, `settings.toast.*`,
  `settings.error.*`. Renderer-flat keys (`readme_*`, `stats_*`,
  `cheatsheet_*`, `roadmap_*`, `topic_readme_*`) preserved in place
  — they're read via the Python `labels_for` flat-key reader at
  `plugins/.../learning_repo/labels.py`, NOT via the frontend `t()`
  walker. Two namespaces, two readers, both correct now.
- `frontend/src/data/i18n/*.json`: regenerated via `make sync-i18n`.
  The existing drift-pin `i18n-sync.test.ts` would have caught any
  catalog where the YAML→JSON mirror diverged; nothing did.
- `frontend/src/data/i18n/i18n-sync.test.ts`: +1 regression-pin
  test walks the exact 24 dotted paths the frontend consumes
  (mirroring `grep -rEho 't\("repo\.[^"]+'`) and asserts each
  resolves to a non-empty string in every catalog. Future drift
  at the call site or in the catalog fails loudly at commit time.

## Architectural decisions

Phase 50 added three:

| ID | Decision | Rationale |
|----|----------|-----------|
| **D-DEXIE-GAMIFICATION** (CLOSED) | Lesson-XP runs locally in Dexie mode via parity-tested TS port | 49F validated the methodology. ~150 LOC TS, byte-identical to Python on first run. |
| **D-PARITY-FIXTURE-PATTERN** | Cross-language ports use shared fixture + per-case goldens + regen-via-env-var | Phase 49F + 50A-C have now used this twice with zero drift. Reusable for any future port. |
| **D-RULES-DOMAIN-COHERENCE** | `.claude/rules/` describes Adaptive Learner, not its upstream Bibliogon | A rules file silently anchored on the wrong domain misdirects every session. The audit checkpoint is `grep` for Bibliogon-residue keywords; zero matches required. |
