# Adaptive Learner v1.16.0

**Released**: 2026-05-21

Phase 29 — **Gamification (XP, Badges, Streaks).** A new
``adaptive-learner-plugin-gamification`` plugin adds an optional
motivation layer: experience points with an exponential level
curve, 24 earnable badges across 5 categories, and an enhanced
streak system with freezes + weekend mode + a GitHub-style
activity heatmap. All gamification is OPTIONAL — the user can
fine-tune (or disable) each surface in Settings without losing
their learning data. Closes BL-18.

## Added

### 29A — XP system

- ``UserXP`` singleton model (per user_id), Alembic 0009,
  Pydantic schemas, sync surface entry (mutable, direct scope).
- ``adaptive_learner_gamification.xp_service``:
  - ``level_threshold(n) = 50 * n * (n - 1)`` exponential curve;
    levels 1/2/3/4/5 at 0 / 100 / 300 / 600 / 1000 XP.
  - Session base 50 XP + 10 per completed cycle + 25 per cycle
    that reached step 7 + 50 first-time-method bonus, multiplied
    by 1 + 25% × min(streak_days, 7) (caps at 2.75x at 7 days).
  - Assessment + import flat earns (100 / 75 XP, no multiplier).
- ``GamificationPlugin`` subscribes to ``on_session_complete``
  and contributes the ``gamification`` namespace to the
  dashboard summary.
- Routes under ``/api/plugins/gamification/xp/*``:
  ``GET /{user_id}``, ``POST /{user_id}/award-assessment``,
  ``POST /{user_id}/award-import``, ``POST /{user_id}/award``.
- Frontend Dexie v7 + browser-side calculator with banker's
  rounding parity. ``XPWidget`` dashboard component (level
  badge + progress bar + "XP to next level"). Animation
  component (``XPNotification``) is shipped and tested but not
  wired into per-page flows in v1.16.0.

### 29B — Badges + achievements

- ``Badge`` (catalog) + ``UserBadge`` (earned) models, Alembic
  0010, Pydantic schemas, sync surface entries.
- ``badges.yaml`` ships 24 badges across 5 categories:
  - getting_started (3): first_session, first_assessment,
    first_import
  - consistency (4): streak_3_days, streak_7_days,
    streak_30_days, streak_100_days
  - method_explorer (7): all_six_methods + 6 ``<method>_10``
    badges
  - depth (7): five_cycles_one_session, sessions_10/50/100,
    level_5/10/25
  - polyglot (3): two_languages, three_providers,
    import_10_conversations
- ``badge_service``: idempotent ``seed_catalog`` (runs from
  FastAPI lifespan), 24 evaluators matched to the catalog,
  ``evaluate_user`` (returns newly earned), ``list_badges_with_
  progress`` (catalog + per-user state).
- Plugin's session-complete hook + the award-assessment +
  award-import routes evaluate badges after each action.
- Routes: ``GET /badges``, ``GET /badges/{user_id}``,
  ``POST /badges/{user_id}/evaluate``.
- Frontend Dexie v8 + ``BUNDLED_BADGES`` constant (lockstep
  with YAML) + browser-side evaluator with identical
  predicates.
- ``BadgeShowcase`` dashboard component: tiles grouped by
  category, earned colored + dated, locked greyed out.

### 29C — Enhanced streaks

- ``UserStreak`` singleton model, Alembic 0011, sync surface
  entry.
- ``streak_service``:
  - ``compute_current_streak_with_state`` walker: freezes
    pause (not reset) a streak across missed days; weekend
    mode skips Sat/Sun gaps.
  - 1 freeze granted per 7 streak days (capped at 3
    stockpiled, no double-grant within a 7-day window).
  - ``calendar_heatmap`` returns [{date, count}] for the
    last N days (default 365, clamped to [7, 730]).
- Routes: ``GET /streak/{user_id}``, ``GET .../heatmap``,
  ``POST .../weekend-mode``.
- Frontend Dexie v9 + browser-side service + ``StreakWidget``
  (current / longest / freezes) + ``StreakCalendar``
  (GitHub-style 5-tier heatmap, weekly columns Mon..Sun).

### 29D — Gamification settings

- Settings > Gamification section:
  - XP notifications toggle (localStorage)
  - Badge notifications toggle (localStorage)
  - Weekend mode toggle (persisted server-side in
    ``user_streaks``)
  - Daily session goal 1..10 (localStorage, clamped)
  - Reset progress button: double-confirm pattern, fires
    ``POST /api/plugins/gamification/reset/{user_id}`` which
    wipes ``user_xp`` + ``user_badges`` + ``user_streaks`` for
    that user (catalog badges shared, survive).
- ``lib/gamificationPref.ts`` localStorage prefs with safe
  defaults (notifications ON, goal 1).

## Migration notes

Existing installs run Alembic upgrades 0009 → 0010 → 0011 in
order; all three are clean-add migrations with no data
backfill required. The badge catalog seeds on first startup
after upgrade. Users see zero XP / no badges / no streak
freezes until they complete their first session post-upgrade.

## Backlog

- BL-18 closed (Gamification).
- Cross-device merge semantics for ``user_xp`` are last-write-

  Import page integrations are deferred to a polish patch
