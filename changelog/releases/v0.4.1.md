# Adaptive Learner v0.4.1

**Released**: 2026-05-18

Patch release on top of v0.4.0. Three bug fixes surfaced during
post-release smoke-testing: the Onboarding Skip button was
functionally correct but discoverability-broken, the favicon
was rejected by some browsers, and the CI Release Gate had been
red on every tag push since v0.0.0.

## Fixed

### Onboarding Skip button hoisted above the fold
- v0.4.0's "Later" Skip button sat at the bottom of a 6-field
  form (~800-900px tall). On a typical viewport, users landing
  on `/onboarding` saw the title + first 3 fields above the
  fold and the Skip button only after scrolling — many never
  found it.
- Added a SECOND Skip button in the onboarding header, top-right
  of the title row, sized smaller than the form-action buttons
  so it reads as a side-affordance ("you don't have to do
  this") rather than competing with Submit. Same `handleSkip`
  handler — one click → default user + project → `/dashboard`.
  The bottom Skip stays as-is for users who scroll.
- Pinned in tests: the top-right Skip MUST be inside
  `.onboarding-header` (not `.form-actions`); a future refactor
  that moves it back to the bottom fails loudly.

### Favicon rejected by some browsers
- `favicon.svg` had `<!-- ... (--accent: #6366f1) -->` — illegal
  `--` inside an XML comment per XML 1.0 §2.5. Chromium tolerated
  it; stricter SVG parsers (including ImageMagick and some
  tab-restore code paths) rejected the SVG outright. Comment
  reworded in prose, no double-hyphen.
- No `/favicon.ico` was shipped, only `/favicon.svg`. Modern
  browsers respect the SVG `<link rel="icon">` for the tab, but
  Chrome/Edge ALSO request `/favicon.ico` directly for tab-
  restore-after-suspend, bookmark icons, and most crawlers. With
  nginx's SPA fallback (`try_files ... /index.html`), that
  request returned `index.html` with `Content-Type: text/html` —
  Chrome rejected it as a malformed icon AND cached the rejection
  for hours.
- Generated a multi-resolution `favicon.ico` (16/32/48/64) via
  ImageMagick from the now-valid SVG. Added
  `<link rel="icon" href="/favicon.ico" sizes="any"/>` to
  `index.html` BEFORE the SVG link. Extended Vite PWA
  `includeAssets` + workbox `globPatterns` to precache it.

### CI Release Gate red on every tag push since v0.0.0
- `scripts/verify_version_pins.sh` greps for hardcoded
  `__version__ = "X.Y.Z"` literals in `plugins/` and flags them
  as regressions. `scripts/sync_versions.py` writes exactly
  those literals during release. The two halves of the
  project's own version-management infrastructure disagreed —
  Release Gate failed on every tag push since v0.0.0; the GitHub
  Release ceremony only succeeded because it ran independently
  of the gate.
- Per the canonical pattern in lessons-learned.md "Single source
  of truth for version pins", switched the 7 plugin
  `__init__.py` files to derive `__version__` via
  `importlib.metadata.version("<dist>")` with a
  `PackageNotFoundError` fallback to `"0.0.0+unknown"`.
- `sync_versions.py` already had a skip-on-derivation guard
  (`"importlib.metadata" in content`) so it leaves these files
  alone — pyproject is the single canonical source. The verify
  script's regression filter excludes lines containing
  "importlib" so the new code passes the gate.
- Net effect at this release: `make sync-versions` writes 12
  files for v0.4.1 (down from 19 at v0.4.0).
- A trailing-newline regression in the rewritten plugin
  `__init__.py` files (Python rewriter used `new.rstrip()`
  which silently dropped the final `\n`) caused a one-shot
  pre-commit `end-of-file-fixer` CI failure on the next push;
  fixed in the follow-up commit.
