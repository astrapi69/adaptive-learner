# Adaptive Learner v1.67.0

Minor release — **backup is now a complete, self-contained snapshot** and
the **user content repository** story lands. The backup work closes the
recurring restore failures for good (proven by a real export→import
round-trip, not just unit tests) and adds the downloaded lesson content
to the backup so a restore onto a fresh install actually works. Alongside
it: EXP-023 multi-repository content, and a small Chrome-console cleanup.
Both storage modes (API + Dexie / GitHub-Pages) carry everything.

## Added

- **Downloaded content sets are part of the backup** (#130). Lesson
  CONTENT lives in a cache outside the 30 sync tables (filesystem in API
  mode, `contentSets`/`contentSetFiles` in Dexie), which the backup never
  carried — so a restore left lessons unopenable ("not downloaded") and,
  worse, **user-generated sets** (Lesson Creator / saved offline lessons
  / adaptive snapshots) were permanently lost. The backup now serialises
  every cached set (manifest + lessons + binary assets as base64) into a
  `content_sets` segment and restores it on the other side — a single
  relative-path-keyed wire model shared by both storage layers. Proven by
  a real round-trip: restore onto a fresh install, then the lesson reads
  back (HTTP 200). Backup wire format `1.2.0 → 1.3.0` (older backups
  restore unchanged).
- **Persistent error toasts + a per-table import summary** (#126). Error
  toasts no longer auto-dismiss (they stay until you close them, and a
  click or drag won't dismiss them by accident); the toast container
  scrolls when several stack. The backup restore screen shows a
  scrollable per-table breakdown (inserted / updated / skipped / errors)
  plus per-row error details, and the browser console logs the full
  import result for debugging.
- **EXP-023 — user content repositories** (#118, #122, #124). Beyond the
  official content repo, you can connect your **own** content
  repositories: add / remove / reorder multiple repos (order = source
  precedence), share one via an `/add-repo` deep link + QR code, and
  browse with a per-repo source badge and filter. Repos are validated
  automatically (a Trust level that re-checks on each sync — at least one
  lesson and no executable content), synced manually or every 24h, and
  cached in both modes. Private / coach repos use a per-repo token kept
  out of the exportable config. A curated `recommended-repos.json` drives
  a Settings discovery section with one-click add + an "Officially
  recommended" badge, plus a local-only per-repo star rating.

## Fixed

- **Backup restore — complete export + restore, no more silent drops**
  (#126). The export now ALWAYS carries all 30 tables (empty = `[]`,
  never omitted) — reverting the v1.66.0 "skip empty tables" optimization
  — so an absent table can never be confused with an empty one (the exact
  ambiguity behind the recurring restore bugs). The whole restore path is
  now logged (INFO per table, ERROR per failed row, a final summary), and
  the errors are returned as a full list instead of one.
- **Restore no longer duplicates the subject taxonomy** (#127). Subjects
  had no natural key, so restoring onto a freshly-seeded install (the
  taxonomy re-seeded under different ids) inserted every node a second
  time (154 instead of 77). Subjects now reconcile by `(parent_id, name)`
  — a new UNIQUE constraint (Alembic `0028` + a one-time dedup),
  null-aware matching for root nodes, and self-referential `parent_id`
  remapping so the whole tree reconciles. Same fix class as the
  `badges.key` reconciliation.
- **Restore onto a fresh install / different identity now works**
  (#129). The disaster-recovery case: a backup from a prior identity (a
  wiped or re-created install, or a Dexie-origin file) carried a
  different `user_id`, so the merge restore rejected every user-scoped
  parent (conversations, curricula, projects, sessions) and every child
  then cascade-failed with "missing parent" — the whole backup dropped.
  Restore now re-homes the backup to the importing user, so the entire
  dataset lands. Verified with a real backup: 0 errors where it
  previously produced 192.
- **Chrome console cleanup** (#119). The API-key and GitHub-token
  password inputs are wrapped in a form element so the browser stops
  warning "Password field is not contained in a form" (and
  password-manager / autofill detection works). The PWA install banner
  was already handled correctly; no change there.

## Notes

- New acceptance gate `BACKUP-AKZEPTANZTEST` (`.claude/rules`): no
  backup-touching change merges without a proven real export→import
  round-trip in `make dev`, with the console output attached as evidence.
  Five prior "fixed" backup releases each shipped with green unit tests
  yet no working end-to-end import; the round-trip is now the gate.
- Migration: Alembic `0028` adds `UNIQUE(parent_id, name)` to `subjects`
  (with a one-time dedup of any pre-existing duplicates). No Dexie schema
  bump.
