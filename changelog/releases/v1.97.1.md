# Adaptive Learner v1.97.1

A content-browsing UX and release-tooling release on top of v1.97.0. The
ContentHub is reorganised so "Meine Inhalte" shows only downloaded content
while the import/creation actions move to the Import tab; the content browser
gains a list/grid toggle and download-time ordering; the Discover tab gets a
compact Search/Filter bar; and the encrypted key-export passphrase flow is
friendlier. Under the hood the one-click `workflow_dispatch` release actions
land and are hardened to run Playwright in the official container. No schema,
API, or data-model change.

## Added

- **Content browser — list ⇄ grid view toggle (#1243).** A compact,
  mobile-first list view as an opt-in alternative to the rich
  source→target→level tree on `/content`. A keyboard-operable toggle
  (`aria-pressed`, 44px target) switches between them and the choice persists
  across navigation/reload (localStorage UI-pref, default = grid). List rows
  are minimal (title + the `de→en` language codes for language sets; title
  alone for knowledge-domain sets) and each links to the single-set deep link.
  New `content.view.{grid,list,aria}` i18n in all 11 catalogs.
- **Discover — compact Search/Filter toggle bar (#1247).** The Discover
  ("Inhalte entdecken") view replaces its always-on filter panel with a
  compact two-button bar ("Search"/"Filter"): filters collapsed by default,
  "Filter" expands the panel inline (prefilled with the active values),
  "Search" collapses it, the two are mutually exclusive, and collapsing never
  resets an active filter. A new reusable `shared/forms/SearchFilterBar`
  composes the existing `SearchField` + `FilterBar`. New
  `discover.bar.search`/`filter` i18n in all 11 catalogs.
- **ContentHub — info button replaces the permanent intro text (#1252).** A
  compact info button replaces the always-on intro paragraph in the ContentHub
  header, reclaiming vertical space (notably on mobile).

## Changed

- **ContentHub IA — actions + My Lessons move to the Import tab (#1256).**
  "Meine Inhalte" now shows only downloaded content; the five import/creation
  actions (Import Lesson / Import Chat / Anki export / Learning Path / Create
  New Lesson) and the standalone "My Lessons" section (user-generated +
  adaptive sets with their full action set) move to the "Importieren" tab. The
  former `ContentToolbar` splits into `ContentSearchBar` (search, stays on
  "Meine Inhalte") and `ContentActionButtons`; a new `ImportActionsPanel`
  carries the action buttons + My Lessons + the import/share/delete modals,
  reusing the existing `useContentSetsData` / `useContentSetActions` /
  `useContentSharing` hooks so every action behaves identically at its new home.

## Fixed

- **Content browser — freshly downloaded sets surface first again (#1242).**
  The #1211/#1212 fix wired the shared `compareByDownloadPriority` comparator
  only into the Learning Path "Persönlich" list; the Content browser
  (`buildContentTree`) still sorted sets within each level / knowledge-domain
  group purely by title. `buildContentTree` now reuses the comparator (DRY) so
  a just-downloaded set shows first within its group; structural
  source→target→level grouping is preserved. Dexie carries the real timestamp;
  API mode falls back to title (no regression).
- **Key-export passphrase — inline validation, not an error toast (#1245).**
  A too-short or non-matching key-export passphrase previously raised a red
  error toast carrying a "Report Issue" button, so a normal input-validation
  case looked like a defect. Validation is now inline (field-level hints,
  `aria-invalid`, submit disabled); real, expected failures stay a plain
  warning, and the now-dead error strings were removed.
- **Key-vault passphrase fields no longer trigger the password manager
  (#1239).** The encrypted AI-key export/import passphrase fields reuse the
  shared `SecretInput` (text + CSS masking, password-manager opt-out, own
  reveal toggle) instead of raw `type="password"`, so the browser/extension
  password manager no longer offers to save/autofill a crypto passphrase. The
  fields stay masked by default and remain accessible.

## Tooling / CI

- **One-click `workflow_dispatch` release actions (#1233 / #1234 / #1235).**
  Two dispatchable stages — `release-prepare` (verify a prepared
  `release/<version>` branch + run the full `make release-test` gate) and
  `release-finish` (merge to main + tag + back-merge develop + publish the
  GitHub Release) — plus a combined `release.yml` driver, all built on the
  existing Make targets so they cannot drift from the Makefile.
- **Release gates run in the Playwright container (#1248 / #1250).** The
  release workflows run inside `mcr.microsoft.com/playwright` (browsers
  pre-baked) instead of the flaky `cdn.playwright.dev` download — the
  established #317 fix — which previously hung the gate 30+ minutes on the
  Playwright install. A brittle `LD_LIBRARY_PATH`-stripping test was fixed in
  the same pass (#1250); the `make test-e2e-smoke` dev-server contention inside
  the container is tracked as #1254.
- **Lean TDD inner-loop make targets (#1237).** `test-one` (single
  path-routed test with the real exit code), `test-watch` (frontend Vitest
  watch), `tdd-help`.
