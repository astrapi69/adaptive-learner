# Adaptive Learner v2.17.0

A privacy release. The privacy policy was rewritten in all eight help languages and describes when and where data leaves your device. Alongside it, the documentation site loads nothing from servers other than GitHub Pages, where it is hosted, and its search no longer puts your search terms into the result links. Images and videos in learning content and AI replies that point to another server show as a link and load only after a click, and links from the app send no referrer. An error report includes the environment info and the action history only when you tick them. Read-aloud prefers a voice on your device, and a session started from an imported chat sends its AI opening once instead of on every reload. The privacy notes of the two AI checks now say what is sent, with the set's languages and level, replacing their earlier promise about personal data.

The end of a lesson leads to fixing it. When a run had mistakes, the compact summary offers Fix mistakes, a Your corrections panel shows what you fixed, and the detailed evaluation marks each mistake Corrected or Still open. Reaching the summary now completes the lesson, and the summary shows the time of this run instead of every visit added up. In exam mode, a set that brings its own evaluation rules is graded by them, an exam counts only in one sitting, and a run started in another mode no longer continues as an exam. A paused lesson resumes on the step you last visited.

Backups carry more and land in the right profile. Importing another learner's backup in Settings merges its progress into the active profile, a browser restore keeps earned badges and the streak, and connected repositories, redeemed invites and AI content-check reports now travel with a backup. Restore a backup made with v2.17.0 only in v2.17.0 or newer (see Compatibility). In the lesson creator, saving locally needs only a valid lesson, the content minimums apply when you share, and Save and share opens the share wizard. Error messages, reports and page titles follow the interface language, and every help page now exists in all eight help languages.

## Before you install

AdaptiveLearner runs in Docker. You need Docker Desktop installed and running before starting the launcher.

- [Docker installation guide (English)](https://github.com/astrapi69/adaptive-learner/blob/main/docs/help/en/install/docker-desktop.md) - includes a "Is Docker safe to install?" section
- [Docker-Installationsanleitung (Deutsch)](https://github.com/astrapi69/adaptive-learner/blob/main/docs/help/de/install/docker-desktop.md) - mit Abschnitt "Ist Docker sicher zu installieren?"

The launcher detects Docker, downloads the ready-built AdaptiveLearner image from GitHub's registry (about 110-120 MB compressed, roughly 500 MB on disk - nothing is built on your machine), and opens the app in your browser. Later starts are fast and work offline.

## Download

| Platform | File |
|----------|------|
| Windows | `adaptive-learner-launcher.exe` |
| macOS (Apple silicon) | `adaptive-learner-launcher-macos.zip` |

Each platform also ships a `*.sha256` checksum next to the binary.

## Verifying downloads

```bash
# macOS / Linux
shasum -a 256 adaptive-learner-launcher-<platform>
cat adaptive-learner-launcher-<platform>.sha256
```

```powershell
# Windows
Get-FileHash -Algorithm SHA256 .\adaptive-learner-launcher.exe
Get-Content .\adaptive-learner-launcher.exe.sha256
```

The hashes must match.

**macOS blocks the binary on first open** and, depending on the macOS
version, offers only "Move to Trash" and "Done" - no Open button. The
program is not notarized by Apple (that needs a paid developer account).
Dismiss with **Done**, then open **System Settings > Privacy & Security**,
scroll down and click **Open Anyway**. Windows shows a SmartScreen notice
with a "More info" > "Run anyway" path. Full walkthrough per platform:
[launcher guide](https://github.com/astrapi69/adaptive-learner/blob/main/docs/help/en/install/launcher.md).

Verify the checksum first. When the system cannot tell you where a file
came from, a matching checksum is the check you can still make yourself.

## What's new

### Compatibility

The backup format moves from 1.6.0 (v2.16.0) to 1.9.0. Each step adds a segment:

- 1.7.0: purchases made with XP (#3679).
- 1.8.0: connected content repositories, redeemed invites and the Learning Repository switch (#3697).
- 1.9.0: cached AI content-check reports (#3706).

v2.16.0 and older accept a 1.9.0 backup but skip the segments they do not know, without a message, so those parts are lost. Restore a backup made with v2.17.0 only in v2.17.0 or newer. The browser version updates itself and the desktop app does not, so update the desktop app before you restore a browser backup in it.

**Is this a breaking change?** No, by this project's reading of SemVer, which is why this is a minor release. "Backward-compatible" means that v2.17.0 works with everything an older version wrote:

- it restores older backups, because every format step only added segments and an older backup imports with the defaults for what it lacks (the restore tests cover, among others, 1.2.0 and 1.3.0 backups);
- it upgrades the browser database from schema 33 to 35 on first start (34 adds the purchases table, 35 completes progress rows without a schema change).

The reverse direction is not covered: an older version reading what v2.17.0 wrote.

- A backup: v2.16.0 restores a 1.9.0 backup without the newer segments and without saying so. #3827 makes that visible, but it is still open, so v2.17.0 will treat a later 1.10.0 backup the same way.
- The browser database: an older version can still open it. Measured with Dexie 4.4.6, which v2.16.0 also uses: a schema-33 app opens a schema-35 database and reads its data. It does not see the purchases table.

SemVer does not promise that an older version understands newer data. Because a part of a backup is lost silently, this note says so instead of leaving it to the version number. A later backup-format or schema change is judged the same way: minor as long as the new version reads everything older versions wrote, with what older versions lose named here.

### Added

- Lesson summary: when a run had mistakes, the compact summary offers "Fix mistakes (n)" above its actions. It opens the correction round at the first exercise and, once some are fixed, shows "n of m corrected". A run without mistakes shows neither, so the compact view still fits one phone screen.
- Lesson summary: after the correction round, or as soon as anything is corrected, a "Your corrections" panel shows the first-try tally and every mistake as Corrected or Still open, with your first answer against the correct one and, while it is open, the explanation. An error replay started from the summary ends with the same panel.
- Detailed evaluation: the answers overview and "Why you missed these" mark every mistake Corrected or Still open. A corrected mistake stays in the list instead of dropping out.
- Exam mode: a set with its own `evaluation` block is graded by it, on the first-pass score and in place of your own pass threshold: pass or fail, a grade, or an advisory percentage, under the set's own title. A note says the set's rules applied, and no star rating appears beside the verdict. Other modes and sets without the block are unchanged (learn-content-engine `gradeFor`).
- Lessons keep your last ten actions (steps visited, answers, pause, leaving, start over, completion). A paused or interrupted run resumes on the step you last visited if the lesson still has it, even when that step lies before a graded exercise.
- Browser version: when a learning session reaches step 7, a notice says that only the desktop app starts the next cycle with a new topic, and what to do instead.
- Help: every help page now exists in all eight help languages. New translations cover four user-guide pages, five feature, content and install pages, three developer pages, the legal notice and the privacy policy; the lesson-format and API references are generated for every language, with their tables in English. The feature overview lists the arcade, game mode, set review, mentor mode, avatars and Perplexity (desktop app only), and the help explains the GitHub token's three uses and how to register a repository.
- The API reference lists every endpoint, generated from the OpenAPI snapshot. Two reference documents describe the app as built: `docs/reference/APP-FLOW.md` and `docs/reference/DESIGN-BRIEF.md`.
- Documentation site: help pages can carry Mermaid diagrams. They render from a self-hosted copy of Mermaid 11.17.2, and the licence notices of the packages in that bundle ship next to it. A docs check parses every diagram and requires an accessible title and description.
- Developer help: a data-model page in every help language shows generated ER diagrams of the server database and the browser database, area by area, with a check that fails on a stale page or an unassigned `*_id` field (#3828). The diagrams keep their size and scroll sideways inside their block instead of shrinking to the column (#3861).

### Changed

- Privacy policy: rewritten in all eight help languages. It describes when and where data leaves your device, each with recipient, trigger, data and legal basis, and the transfer to the USA where one applies. As a legal text it uses the formal address; the German version is binding. The legal notice and the privacy policy are now available in Spanish, French, Greek, Portuguese, Turkish and Japanese as well, and both give a new contact e-mail address.
- Documentation site: no page loads anything from another host. It uses the system fonts instead of Google Fonts, the repository link no longer asks the GitHub API for stars and the latest release, and a browser without `ResizeObserver` gets a local stand-in instead of a polyfill from unpkg.com (it keeps the element sizes measured on load). The built site is scanned for third-party fetches on every pull request and before deployment. Search result links no longer carry the search terms (`?h=`), so a result's address does not hold what you searched for.
- Images and videos: a Markdown image that points to another server (lesson theory, reading passages, explanations, AI replies, learning-repository documents, the help glossary, release notes) shows as a link and loads only after a click. YouTube resource cards show a local placeholder instead of the thumbnail and open the video on YouTube in a new tab. The text editor does not load an image from another server, and the hotspot editor offers such an image as a link. The app's pages send no referrer, and their content security policy allows images and media only from the app itself, `data:`, `blob:` and `raw.githubusercontent.com`.
- Error report: "Environment info" (version, browser, OS) and "Action history" start unticked and go into a report only when you tick them. An untouched report carries the error description, with the technical details of a failed request, and the reproduction steps. "View" sits beside the history checkbox, so looking at the history cannot tick it. The help says that GitHub receives the prefilled report as soon as "Open on GitHub" opens its form.
- Read-aloud: the app prefers a voice that the browser reports as running on the device. An online voice reads only when there is no local voice for the language, when you chose one in Settings, or in the first moments after a page loads, before the browser has listed its device voices; auto-read waits up to 1.5 seconds for them. Lessons, exercise prompts, AI replies and pronunciation practice all pick their voice this way. The privacy policy and the settings help name the three cases.
- Imported chats: a session started from an imported chat sends its AI opening once. A reload, reopening it with Continue session or a second tab resumes the stored conversation instead of sending the opening, with the imported chat, to the AI provider again.
- AI checks: the notes in the AI content check and in the AI review before sharing say what is sent (the set's cards, or the lessons you share, each with the set's source and target language and level) and that your AI provider also receives, among other things, your IP address and API key, replacing the earlier promise about personal data. Both notes link the privacy policy, the sharing note names the provider by its settings label, and the FAQ in all eight help languages says which check sends what. A docs check keeps that promise from coming back in any of the 11 interface languages.
- Lesson summary: reaching the summary completes the lesson, and the "Mark as complete" button is gone. Lessons you left with "Next lesson" now count for lesson XP, missions and the flash round. The summary shows the time of this run; statistics and missions keep the total time.
- Exams and modes: a run started in another mode, with exam on either side, is not continued, and a started exam reopened as an exam starts over, because an exam counts only in one sitting. The resume dialog says why and offers Start over. The mode can be changed until the run's first answer, also after starting over.
- Read-aloud player: its X ends read-aloud for the current lesson. Auto-read stays on for the next lesson; the options toggle is the one place that turns it off.
- The install hints (the iOS "add to home screen" hint and the install banner) are cards on the dashboard instead of bars laid over every page.
- Matching: a tap on a paired tile selects it instead of undoing the pair. Pairing it again overwrites the pair, and a collision swaps the two pairs.
- Lesson creator: Save locally, Save changes and Save as a copy check only that the lesson is valid, so a lesson with one exercise can be saved and played. Save and share also needs the engine's sharing minimums, listed under "Needed for sharing" on the review step.
- Sharing: a set that does not teach a language can be shared with "No level (not a language course)". The share check takes its set-level language rules from the content engine.
- Items bought with XP (avatar frames, the mascot variant, arcade games) are recorded as purchases in both storage modes, so they show as owned in another browser and after a LAN sync. Items bought earlier are recorded once, without a new charge.
- Wording: one term per concept for session and streak in German, Japanese, Korean and French, in the app and in the help (German: "Sitzung" and "Serie").
- Browser version: an AI step verdict moves a learning session on at the desktop app's confidence threshold of 0.7 instead of 0.6.
- Backups no longer carry what belongs to one device: the offline write queue, search and media caches, the auto-backup counters and the LAN-sync cursor. A queue that reaches the browser version from an older backup is never sent.
- Self-hosting: an empty repositories directory for the Learning Repository resolves to `repos` in the app data directory, so it follows `ADAPTIVE_LEARNER_DATA_DIR`. Settings that nothing read are gone: `gamification.yaml`, `content-loader.manifest_refresh_hours`, and in `app.yaml.example` the keys `app.name`, `description`, `supported_languages`, `version`, `server.port`, `plugins.config_dir` and `ui.title`/`subtitle` (the port comes from `ADAPTIVE_LEARNER_PORT`; existing `app.yaml` files keep the old keys unread). `anki.extraction_limit` is now read. A plugin placed by hand in `backend/plugins/installed/` is no longer put on the Python path; plugins are packages registered through entry points. AI provider failures that fall back to a default now leave a warning in the server log.
- Under the hood: learn-content-engine moves from 0.36.0 to 0.42.2. The lesson schema's revision marker (`x-schema-version`) moves from 1.19 to 1.20 for a corrected description; lesson files need no change. The desktop app's database gains migrations 0039 to 0041, applied at start. SQLAlchemy 2.1.4 (the backend declares the `asyncio` extra), Bun 1.4.2 in CI, the backend Dockerfile and `docker-compose.yml`, vite-plugin-pwa 2.0, happy-dom 21, pydantic 2.14, Pillow 13 in the launcher, and minor and patch updates elsewhere. For development, pre-commit runs the ruff version the backend lock pins (hook id `ruff-check`) and keeps the plugins formatted, and `make ci` also runs the folder-size gate. The i18n endpoint parses each catalog once per file version.
- Help: the FAQ, the settings help and the sync architecture page say that sync between devices is not available yet. Pairing a second device is not offered (the browser version shows a notice, and the desktop app's pairing link cannot be redeemed), so no data is exchanged; the feature lists no longer name local-network sync. The help previously described a QR scanner, push and pull buttons and an AI merge resolver that the app does not have (#3831).
- Under the hood: the visual regression run serves every content fetch from a frozen snapshot of the official content repository and fails on any request that leaves the test environment, so a new live source fails its first run instead of drifting the baselines (#3745).

### Fixed

- Errors: toasts and inline error panels show the friendly, localized message instead of a backend detail; Developer Mode still shows the detail, and the Report Issue dialog gets status, endpoint and stack trace. Storage errors in the browser version get the same messages as in the desktop app, and two curriculum load messages are no longer English in every language.
- Languages: a failed repository check (Add repository, content-repository settings, redeeming an invite, registry submission) is reported in the interface language, and the Markdown and PDF reports from Settings > Data render in it; before, nine interface languages got English reports. The browser tab names the current page in the interface language, and screen readers read the answer comparison, close buttons, star ratings and placeholders in it.
- Backups: in the browser version, a Settings > Data import of another learner's backup merges its progress into the active learner instead of dropping it, and the confirmation dialog says so beforehand; XP, streak and settings come from the backup. A browser restore keeps earned badges and the streak on a device with its own badge catalog and streak. Connected repositories, redeemed invites, the Learning Repository switch (not its folder) and cached AI content-check reports travel with a backup. A restored own set without a target language keeps it empty.
- Lessons: a new step is drawn at its final position, so a tap hits the option it shows; on an iPhone, a tap could record the neighbouring option. In the browser version, lessons that reached the summary before this release without "Mark as complete" are completed once, without retroactive XP.
- Lesson creator and sharing: saving an edited lesson keeps its purpose, resources and variation link. Save and share opens the share wizard for the saved lesson, and a curriculum created from an import opens itself instead of the first one. "Share as repository" writes the layout the app loads, checked by the content engine before anything is pushed, keeps lesson file names only when they sort in lesson order, and its note uses the singular for a one-lesson set.
- Content: a set listed only from the cache keeps its visibility, review status and evaluation in both modes, so a hidden set stays hidden. In the desktop app, a downloaded set keeps its description while its repository is offline, and a manifest without a target language or with an unknown visibility or review status is read the way the engine reads it instead of being rejected whole. Discover reads a set without a source language as English, as My content does, and a single imported lesson keeps its own language pair.
- Import: when the AI analysis of a chat cannot be parsed, no English placeholder topic or summary is stored, and the analysis note no longer promises 15 to 30 seconds.
- Layout: long page titles hyphenate instead of widening the page, two fieldsets lost the browser's groove border (Settings > Data export, combining lessons), eleven headings lost the browser's top margin (for example Continue learning on the dashboard), and the "Project created" toast no longer blocks the next tap.
- Help: bold text in the in-app help no longer shows as literal asterisks (mostly in Japanese), accents are restored in French, Spanish and Portuguese strings and in the German and Portuguese help, the Japanese and French pages describe the streak freeze correctly (one per 7 streak days, at most 3), and the settings help in six languages follows the regrouped tabs.
- Help: the backup link in the settings page of the Greek, Portuguese and Turkish help points to the backup page (#3860).

### Security

- The content cache and the content backup restore compare paths instead of string prefixes, so a sibling directory whose name starts with the same prefix can no longer be read or written.
- A missing lesson or asset in a cached set no longer puts the server's cache path, which can contain the user's home directory, into the error the app shows and passes to the report dialog; the path goes to the server log.
- prosemirror-view 1.42.6 for GHSA-c8x8-7fp4-3x9w (XSS in paste handling, in the editor) and source-map-js 1.2.2 for GHSA-68fv-2mgg-jv7q (build tooling only).
- certifi 2026.10.19 for PYSEC-2026-4320 in every lock file.
- virtualenv 21.14.12 for five pip-audit advisories (development dependency).
- black 26.10.1, filelock 4.2.4, dnspython 2.9.0 and msgpack 1.2.4 for the pip-audit advisories published on and after 2026-10-26; happy-dom 21.0.4 (test DOM, development dependency) for GHSA-834v-8h66-3h79 and zod 4.6.7 for GHSA-mrhx-c7xc-m3w5 (#3856).
- LAN sync: the sync engine and its server endpoints no longer send, accept or write AI provider API keys, and a pulled settings row keeps the browser's own keys. In this release no device can be paired, so the path was not reachable from the app; the fix closes it before pairing returns (#3854).
