# Adaptive Learner v1.11.0

**Released**: 2026-05-21

Phase 24 — **Provider Model Picker via API.** Settings now
shows the user the real list of models their API key has
access to, not a hand-curated static list. Three concrete
gains: (1) deprecated / renamed models drop off the picker
automatically as upstream rolls them, (2) new releases (e.g.
``claude-opus-5-2027`` the day it ships) appear in the
picker with no Adaptive Learner release, (3) session start
catches the case where a long-saved override has been
deprecated upstream and falls back to the provider's default
instead of failing at AI call time. Closes BL-09.

## Added

### 24A — Backend model discovery service

- ``backend/app/services/model_discovery.py`` — typed
  ``ModelInfo`` dataclass + per-provider fetchers
  (``fetch_anthropic_models`` / ``fetch_openai_models`` /
  ``fetch_gemini_models``) plus the agnostic
  ``fetch_models(provider, api_key)`` dispatcher.
- Each fetcher calls the provider's own ``/models`` endpoint
  via httpx (5s timeout) with the correct auth shape
  (``x-api-key`` + ``anthropic-version`` for Anthropic,
  ``Authorization: Bearer`` for OpenAI, ``?key=`` query for
  Gemini).
- In-memory cache keyed by
  ``(provider, sha256(api_key)[:16])`` with a 1-hour TTL.
  Lookups for the same ``(provider, key)`` pair within the
  hour return from cache (zero network); distinct keys are
  isolated.
- Non-chat models filtered out: embedding, whisper, TTS,
  DALL·E, moderation, search, deprecated completion families
  (``babbage-002`` / ``davinci-002``), audio / image /
  realtime / transcribe variants. Gemini drops embedding +
  AQA + vision-only models; the remainder must support
  ``generateContent``.
- Auth failures → ``ExternalServiceError("anthropic|openai|gemini", "Invalid API key.")``;
  network failures wrapped with the same shape. Empty key →
  empty list (no upstream call).
- New endpoint ``GET /api/settings/{user_id}/available-models?provider={p}``
  decrypts the stored key via the existing crypto path and
  delegates to the dispatcher. Returns ``[]`` when no key is
  stored for the requested provider; the response shape is a
  list of ``AvailableModelOut``
  (``id`` + ``name`` + ``context_window`` + ``description``).

### 24B — Browser-direct model discovery for Dexie mode

- ``frontend/src/storage/model-discovery.ts`` — the same
  three provider calls run browser-direct, mirroring the
  backend's filter + cache semantics. Anthropic includes the
  ``anthropic-dangerous-direct-browser-access: true`` header
  to bypass CORS (same opt-in the existing ``ai-providers``
  module uses).
- Cache lives in ``sessionStorage`` keyed by
  ``adaptive-learner.model-discovery.{provider}.{sha256(key)[:16]}``
  with a 1-hour TTL. Per-tab cache; survives F5 inside a tab
  and dies with the tab — the trade-off matches the
  in-memory cache on the backend.
- ``ISettingsNamespace.getAvailableModels`` joins the storage
  contract; both ``ApiStorage`` and ``DexieStorage`` now
  implement it. ApiStorage delegates to the new endpoint;
  DexieStorage reads the cleartext key out of IndexedDB and
  fires the browser-direct fetcher.
- ``api.settings.getAvailableModels(userId, provider)`` added
  to the typed API client.

### 24C — Settings model picker

- New ``components/ModelPicker.tsx``. Replaces the v0.4.0
  ``<input list="...">`` + ``<datalist>`` shape with a
  proper searchable dropdown. The fetch is deferred until
  the user focuses the input or opens the dropdown (the
  initial render never fires the network).
- Dropdown rows show: human-readable name (large), the
  technical model id (smaller, monospace), the context-window
  size as a badge (``200K``, ``128K``, ``1M``). When the
  cached list has more than 3 entries the dropdown groups
  the top 3 as **Recommended** and the rest as **All models**.
- Loading + error states: a "Loading models..." line while
  the fetch is in flight; on failure an error panel with
  the ``ApiError`` detail, a Retry button, AND the static
  ``MODEL_SUGGESTIONS`` rendered as the offline fallback so
  the user is never left empty-handed.
- "No API key" state: when ``has_{provider}_key`` is false,
  the dropdown shows an inline hint instead of firing the
  network — Settings has no key to forward.
- Default-model hint underneath the input: when no override
  is set, the picker shows ``Uses default: <model-id>`` so
  the user knows what they're getting from
  ``ai_orchestration.DEFAULT_MODELS``.
- Selected model renders as an info chip above the dropdown
  with name + id + context-window.
- 14 i18n keys (``settings.model_picker_*``) shipped: DE +
  EN hand-translated, ES / FR / EL / PT / TR / JA as
  EN-passthrough (consistent with the rest of the catalog).

### 24D — Model validation on session start

- ``model_discovery.get_cached_models(provider, api_key)``
  helper: peeks the cache without firing a network call.
  Returns ``None`` when no entry exists.
- Session ``POST /message`` now validates the chosen model
  against the cached list when one is available. Three
  branches: (a) no cache → skip validation, try the model
  anyway (the spec's "best effort"); (b) cache present AND
  model in list → proceed; (c) cache present AND model NOT
  in list → fall back to
  ``ai_orchestration.DEFAULT_MODELS[provider]`` and surface a
  non-fatal warning.
- New ``model_warning`` field on
  ``_SessionMessageExchangeOut`` carries the warning string
  ("Model 'xyz' is not in the available models for provider
  'anthropic'. Falling back to ..."). The existing
  ``ai_error`` field is reserved for hard failures; the
  warning is a separate, non-blocking channel.
- The validator is wrapped in ``try/except`` so any
  cache-lookup bug can never break the chat path — failure
  silently proceeds with the requested model.

### 24E — Model name + context window in session header

- Session header's provider chip now reads
  ``"<Provider>: <Model name>"`` instead of just the
  provider name. The model name comes from the
  available-models cache when the picker has populated it;
  otherwise the raw model id is shown.
- ``title`` attribute (tooltip on hover, long-press on
  touch) carries the full technical id + context window
  ("``claude-opus-4-20250514 · 200K tokens``").
- The model is resolved client-side via the shared
  ``resolveModel(provider, override)`` helper, so the
  header matches what the backend's
  ``ai_orchestration.resolve_model`` will pick at /message
  time.

## Behaviour notes

- The static ``MODEL_SUGGESTIONS`` map in
  ``frontend/src/lib/constants.ts`` is no longer consumed by
  the live picker dropdown. It now serves as the
  **offline fallback** that the picker renders when the
  fetch fails OR when no key is configured AND the user
  insists on typing a model manually. The
  ``DEFAULT_MODELS`` map on both sides is unchanged and
  still drives the "Use default" branch.
- Validation is **opt-in via the cache**. A user who has
  never opened Settings since this release will have no
  cache entry; their session continues to work exactly as
  before with no warning and no fallback. The first time
  they open the Settings picker the cache populates and
  the validation gains its safety net.
- The cache uses sha256 of the API key as the cache key
  (truncated to 16 chars). The key itself never appears in
  logs, debug repr, or error messages.

## Migration

No breaking changes. The
``model_override_<provider>`` schema is unchanged. The
``MODEL_SUGGESTIONS`` constant remains exported for the
fallback path. Existing Settings test selectors that
referenced ``model-override-input-*`` were renamed to
``model-picker-input-*`` to match the new component (see
``frontend/src/pages/Settings.test.tsx``); no external
consumer of these test-ids exists.
