# Adaptive Learner v1.27.0

**Released**: 2026-05-26

Phase 43 — **Content-Loader Plugin** (EXP-002 / EXP-005
foundations). First release of the content-repository pivot.
The app stops requiring an API key for the headline use case:
the new `/content` page downloads pre-built lesson sets from
public GitHub repos and caches them locally. AI features
remain available when a key IS configured; without one, the
app now has real lessons to surface instead of a wall of
"please configure a provider" prompts.

This is the single largest architectural addition since
PluginForge: a brand-new plugin (`content-loader`), a new
IStorageService namespace, two new Dexie tables, three new
hookspec concepts, route surface for the API path, a Set
Browser page in the frontend, a 5-Mode badge driven by the
existing `useApiKeyStatus` hook, full Dexie-mode parity
client-side, and a pilot lesson set ready to publish.

## Why this release

Adaptive Learner started as "AI-chat-only learning": every
core feature required an API key for one of the three
supported providers. That's a strong barrier for new users
who land on the public GitHub Pages deployment without yet
knowing whether to invest in a Claude / GPT / Gemini
subscription.

v1.27.0 reframes AI as an *enhancement*, not a *prerequisite*.
The content-repository pattern (per EXP-002) ships
pre-authored lesson sets via public GitHub repos. The user
opens `/content`, downloads a set, and the app has 10-15
minutes of structured material to work through — no API key
involved. EXP-005 dual-mode rides naturally with the same
release: the navigation bar always shows whether the app is
in `Content` (no key) or `AI+Content` (key configured) mode,
and clicking the badge jumps to the Set Browser so the user
can browse what's available locally.

## What changed

### Added

- **New plugin: `adaptive-learner-plugin-content-loader`**
  with eight new modules (`plugin.py`, `models.py`,
  `schema.py`, `schema_export.py`, `manifest_parser.py`,
  `github_adapter.py`, `cache.py`, `version.py`,
  `service.py`, `config_resolver.py`, `routes.py`,
  `exceptions.py`). PluginForge-based, mounts under
  `/api/plugins/content-loader/*`. Three hookspec
  concepts (`content_list_sets`, `content_download_set`,
  `content_get_lesson`) the service layer exposes; the
  routes ship the REST surface in the same shape.

- **Content schema v1.0** (`schema.py`): `Lesson`,
  `LessonStep`, `Exercise`, `Card`, `ExerciseType`,
  `StepType`. ExerciseType is a closed enum with four
  values (`matching`, `picture_choice`, `free_text`,
  `word_tiles`). Lesson model enforces referential
  integrity (every exercise's `card_ids` must resolve to a
  card in the lesson). JSON Schema export for every model
  via `schema_export.write_schemas(dir)` — six files
  total, ready for the content repo's CI workflow.

- **GitHub raw-URL adapter** (`github_adapter.py`).
  Public repos work tokenless; private repos accept an
  optional token through the three-layer secrets chain
  (env > `secrets.yaml` > Fernet DB). Bypasses the GitHub
  API's 60/h unauthenticated rate limit by talking to
  `raw.githubusercontent.com` directly. Typed exceptions
  (`ContentNotFoundError`, `ContentAuthError`,
  `ContentNetworkError`, `ContentFetchError`,
  `ContentSchemaError`) map onto the backend's
  `AdaptiveLearnerError` hierarchy in the route layer.

- **Filesystem cache + version reconciliation** (`cache.py`,
  `version.py`). Atomic store-via-tmp-rename; partial
  downloads never appear as cached. Semver-aware
  comparator with no external dep (handles `X.Y`, `X.Y.Z`,
  pre-release suffixes, build metadata per semver 2.0).
  `reconcile_set_version()` returns
  `(needs_download, cached_version_or_none)` so the
  service skips the heavy fetch when the cache matches
  the upstream. Cache root lives at
  `get_cache_dir() / content-loader / {owner--name} /
  {set_id} / v{version} /` — respects the v0.7.0
  filesystem-isolation tripwire.

- **IStorageService.contentLoader namespace**
  (`frontend/src/storage/types.ts`).
  `ApiStorage` delegates to `api.contentLoader.*`;
  `DexieStorage` runs the GitHub fetch + cache
  client-side via `content-loader-dexie.ts`. The
  GH-Pages-shape build works without a backend.

- **Dexie schema v16** — two new tables (`contentSets`,
  `contentSetFiles`) for the client-side cache. Same
  cache-key shape as the filesystem version, so both
  storage modes stay analogous.

- **Set Browser page** at `/content` (`frontend/src/pages/
  Content.tsx`). Lists available + cached sets with a
  single primary action button per row (Download →
  Downloading → Installed / Update). Mobile-first
  responsive: rows stack under 600px so the action
  button stays a 44px+ touch target. Lazy-loaded behind
  React.lazy per the bundle-size discipline shipped in
  v1.26.1.

- **App-mode hook + nav badge** (`useAppMode.ts`,
  `Navigation.tsx`). Interprets the existing
  `useApiKeyStatus` hook as `content-only` /
  `ai-augmented`. Badge always visible (next to the DEV
  badge if dev mode is on), colour-coded
  green=ai-augmented vs accent-coloured=content-only.
  Tooltip explains the mode + the path to Settings to
  upgrade. Click deep-links to `/content`.

- **Pilot French A1 content** (`docs/explorations/
  sample-content/fr-a1/`). Two lessons (Greetings,
  Numbers 1-10) covering 14 cards + 14 steps + 9
  exercises. Demonstrates every Phase 43 exercise type
  in working JSON form. `validate.py` mirrors the
  CI-template the future `astrapi69/adaptive-learner-content`
  repo will run.

- **Dexie-mode release gate** extended to the `/content`
  route. The smoke spec accepts any of `content-loading`,
  `content-page`, or `content-empty` as the rendered
  state so a GitHub Pages first-time visitor with no
  network reaches the empty state, not a crash. 16/16
  specs green.

- **i18n**: new `content.*` namespace (16 keys per
  language) + 6 new `nav.*` keys (Content link + 5 mode
  badge variants). All 8 catalogues translated natively
  (DE, EN, ES, FR, EL, PT, TR, JA).

### Changed

- **Plugin count**: 11 → 12 (added `content-loader`).
- **IStorageService namespace count**: 22 → 23.
- **Dexie schema version**: 15 → 16.

### Architecture

- Lessons are *data*, not code. The app downloads and
  validates them at runtime; nothing is bundled at build
  time. Storage abstraction stays load-bearing — the same
  page works against `ApiStorage` (backend orchestrator)
  and `DexieStorage` (in-browser fetch + IndexedDB).
- Mode detection is a derived property of
  `useApiKeyStatus`, not a stored preference. The EXP-005
  P-113 + F-104 deliverables fold into this release instead
  of a separate phase per the user's design clarification.
- Phase 44+ will add the lesson viewer + exercise
  renderers + SRS integration on top of these data
  shapes; nothing in v1.27.0 commits to specific
  rendering APIs.
