# Adaptive Learner v1.15.0

**Released**: 2026-05-21

Phase 28 — **E2E Playwright Expansion.** 10 new smoke specs
land alongside the existing 6 from Phase 6D / 9. Coverage
goes from 23 baseline tests to **36 tests across 16 spec
files** in 2.6 min, with deterministic AI mocking via
``page.route()`` (no backend changes). Closes BL-13.

## Added

### 28A — E2E infrastructure + shared fixtures

- ``e2e/helpers/onboarding.ts``: ``createTestUser``
  shorthand combining onboarding + assessment.

  ``startSessionWithMethod`` / ``sendChatMessage`` /

  ``sendChatMessage`` helper papers over three real-world

## Behaviour notes

- AI mocking is browser-level via ``page.route()``;
  matches Bibliogon's ``e2e/smoke/ai-review.spec.ts``
  pattern. No backend test-mode plugin / env var was
  added.
- The E2E data dir at ``/tmp/adaptive-learner-e2e-data``
  is wiped at the START of the playwright session (not
  per-spec). Each spec creates an independent user via
  ``createTestUser`` to avoid cross-spec collisions.
- SSE mock body terminator: every frame ends with
  ``\n\n`` (matches the frontend's sse-reader split). A
  body that ends with a single ``\n`` leaves the final
  frame in the buffer; the partial-flush eventually emits
  it on EOF, but the multi-turn loop's downstream
  ``await streamMessage`` is more reliable with explicit
  per-frame terminators.

## Follow-up audit items

- **28C-DETAIL-GET-MOCK**: ``page.route`` matchers on
  GET /api/imports/{id} silently miss the request despite
  regex / function / glob shapes (verified with explicit
  ``page.on("request")`` confirming the GET reaches the
  network layer). The POST /analyze on the same path
  prefix DOES intercept correctly. Service worker
  unregister via ``page.addInitScript`` doesn't fix it.
  Filed for a follow-up debugging session — current
  workaround is to skip the post-navigation detail-page
  assertion and pin via ``waitForRequest`` on the analyze
  POST instead.

- **28J-SETTINGS-RACE**: the Settings page fires GET
  ``/api/settings/{user_id}`` twice on mount (React
  strict-mode double-effect). ``get_or_create_settings``
  races: both requests see ``user.settings is None``, both
  attempt to INSERT, the second trips a UNIQUE constraint
  on ``user_settings.user_id``. The race is in the
  BACKEND, not the spec — reproduces outside Playwright.
  Wrap the create in ``ON CONFLICT DO NOTHING`` semantics
  (or use ``user.settings`` lazy-load with a re-check
  inside a transaction with serializable isolation).
