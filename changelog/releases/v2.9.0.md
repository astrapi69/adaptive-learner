# Adaptive Learner v2.9.0

**The launcher can be closed again - update recommended for anyone who
downloaded a binary.** In v2.8.2 and earlier the downloaded launcher
could not be quit at all on a desktop without a system tray (Ubuntu
GNOME ships none by default): the X made the window disappear while the
process kept running, and only the task manager ended it. The launcher
engine now decides by the RUNTIME tray fact, and this app's binary
deliberately ships without a tray - so closing the window always quits
it there. The app itself keeps running in Docker and is right back on
the next start.

Also in this release: the lesson order you set now drives the LEARNING
sequence, not just the list, and editing belongs to the individual
lesson instead of the whole set.

**Der Launcher laesst sich wieder schliessen - Update empfohlen fuer
alle, die ein Programm heruntergeladen haben.** Bis v2.8.2 liess sich
der heruntergeladene Launcher auf einem Desktop ohne Tray-Symbol (Ubuntu
GNOME liefert standardmaessig keins) gar nicht beenden: das X liess das
Fenster verschwinden, der Prozess lief weiter, und nur der
Aufgabenmanager beendete ihn. Die Launcher-Engine entscheidet jetzt nach
der Laufzeit-Tatsache, und das Programm dieser App traegt bewusst kein
Tray - dort beendet Schliessen also immer. Die App laeuft in Docker
weiter und ist beim naechsten Start sofort wieder da.

Ausserdem: die von dir gesetzte Lektionsreihenfolge steuert jetzt auch
die LERNFOLGE, nicht nur die Liste, und Bearbeiten gehoert zur einzelnen
Lektion statt zum ganzen Set.

### Correction: the app IS reachable from your network

Until now the launcher help said the app "runs locally only
(`localhost`), so no firewall rule is needed", and the README described
the Docker install as starting "at `http://localhost:8501`". Both were
wrong. The container port is published on every network interface, and
the app has no authentication - so anyone who can reach your machine on
that port has full access to your learning data and can make AI calls
billed to your provider key.

Nothing in the app changed here; only the documentation, which now says
what actually happens. If your machine is on a shared or public network,
keep that port closed at your firewall. The NEXT release changes the
default so the app binds to `localhost` only, with an explicit setting
for anyone who deliberately wants to reach it from a second device.

**Korrektur: die App IST aus deinem Netzwerk erreichbar.** Bisher stand
in der Launcher-Hilfe, die App laufe "nur lokal (`localhost`), eine
Firewall-Freigabe ist dafuer nicht noetig", und die README beschrieb die
Docker-Installation als Start "auf `http://localhost:8501`". Beides war
falsch. Der Container-Port wird auf allen Netzwerkschnittstellen
veroeffentlicht, und die App hat keine Authentifizierung - wer deinen
Rechner auf diesem Port erreicht, hat vollen Zugriff auf deine Lerndaten
und kann AI-Aufrufe auf deinen Anbieterschluessel machen.

An der App selbst hat sich dafuer nichts geaendert, nur an der
Dokumentation, die jetzt sagt was wirklich passiert. Wenn dein Rechner
in einem geteilten oder oeffentlichen Netz haengt, halte den Port in der
Firewall geschlossen. Das NAECHSTE Release stellt den Standard um, so
dass die App nur noch auf `localhost` bindet, mit einer ausdruecklichen
Einstellung fuer alle, die sie bewusst vom Zweitgeraet erreichen wollen.

## Before you install

AdaptiveLearner runs in Docker. You need Docker Desktop installed and running before starting the launcher.

- [Docker installation guide (English)](https://github.com/astrapi69/adaptive_learner/blob/main/docs/help/en/install/docker-desktop.md) - includes a "Is Docker safe to install?" section
- [Docker-Installationsanleitung (Deutsch)](https://github.com/astrapi69/adaptive_learner/blob/main/docs/help/de/install/docker-desktop.md) - mit Abschnitt "Ist Docker sicher zu installieren?"

The launcher detects Docker, downloads the ready-built AdaptiveLearner image from GitHub's registry (about 110-120 MB compressed, roughly 500 MB on disk - nothing is built on your machine), and opens the app in your browser. Later starts are fast and work offline.

## Download

| Platform | File |
|----------|------|
| Windows | `adaptive-learner-launcher.exe` |
| macOS (Apple silicon) | `adaptive-learner-launcher-macos.zip` |
| Linux | `adaptive-learner-launcher` (ELF binary) |

Each platform also ships a `*.sha256` checksum next to the binary.

## Verifying downloads

```bash
# macOS / Linux
shasum -a 256 adaptive-learner-launcher-<platform>
cat adaptive-learner-launcher-<platform>.sha256
```

```powershell
# Windows
Get-FileHash -Algorithm SHA256 .\adaptive-learner-launcher.exe
Get-Content .\adaptive-learner-launcher.exe.sha256
```

The hashes must match.

If your operating system warns about an unsigned binary, see the [AdaptiveLearner installation overview](https://github.com/astrapi69/adaptive_learner/blob/main/docs/help/en/installation.md).

## What's new

### Fixed - user-visible

- **The launcher can be closed without a system tray** (#2272, engine
  docker-app-launcher#108). The downloadable binary now ships without
  the tray declaration it could never honour, and the engine decides by
  the runtime tray fact instead of the declared intent. The artifact
  property is now stated in the installation help: no tray in the
  binary, closing always quits, the tray stays a source-install option.
- **The lesson order drives the play sequence** (#2212). Reordering
  lessons in "Manage lessons" changed the list only; opening and
  continuing a set still followed the old order.
- **Editing belongs to the lesson, not the set** (#2210). In a
  multi-lesson set, Edit opens exactly the lesson whose row you used.

### Added - infrastructure

- **A gate proves that nameable doc references exist** (#2254): make
  targets, repo paths and constants named in the docs are checked
  against the Makefile, the git index and the code. Three same-day
  precedents of documentation naming things that had been deleted.
- **The publish chain re-verifies instead of re-building** an already
  published tag (#2187), so a repeated run can no longer ship an
  artifact other than the verified one.
- **Docker images carry the app version** as tag and OCI label (#2034),
  and the compose identity is env-parameterized so a second local
  instance no longer collides with a real installation (#2122).
- **A daily rollup surfaces red scheduled runs** in one place (#2225).

### Fixed - infrastructure

- The image-size gate measures the architecture it judges (#2268) and
  fails closed by name when docker is absent (#2241); the size ceiling's
  rationale is now proven rather than assumed - the same published image
  measures 12.78 MB apart on the two docker image stores (#2134).
- The docs-hygiene gate enumerates the git index instead of the file
  system, so gitignored local artifacts can no longer turn a clean tree
  red (#2217).
- The e2e suite no longer reaches the developer's real machine: the
  config directory (#2248) and the cache directory (#2263) are pinned
  inside the throwaway data dir, with the whole resolver class pinned by
  a test.
- `release-prepare` survives its own root-vs-checkout ownership mismatch
  (#2035), and the version-display sites now ride the sync-versions
  write path (#2179) instead of drifting after every release.
- The full smoke suite is live again: all six silenced specs rewritten
  against the current UI, the silencing budget spent back to zero
  (#2177).
