# Adaptive Learner v1.23.2

**Released**: 2026-05-23

Three small fixes plus the toggleable button-tooltip
preference. Focused patch on top of v1.23.1; no schema
changes, no new dependencies for users.

## Why this release

v1.23.0 shipped Phase 38 (in-app contextual help system) and
v1.23.1 was a small patch immediately after. Manual smoke
testing of v1.23.1 surfaced three issues that this release
fixes:

1. Recharts on the Dashboard logged a
   ``width(-1) height(-1) ... should be greater than 0``
   console warning on every page load.
2. The HelpTooltip dotted underline was too subtle to notice
   in normal use — users missed the contextual-help affordance.
3. Several user-listed icon buttons (Send, Rating, Import
   delete, Lesson edit/delete, ProjectTaxonomy chip remove,
   QRScannerModal close) had no `aria-label` or the title was
   not gated by user preference.

## What changed

### Recharts `width(-1) height(-1)` warning (commit `d74598a`)

The three Dashboard chart components (`ProfileRadar`,
`ProgressTimeline`, `MethodDistribution`) had the warning
fire on first render despite the `initialDimension`
suppression added in v1.23.0+. Root cause: the chart
wrapper `<div>` is a flex child of `.dashboard-card`
(`display: flex; flex-direction: column`). Without an
explicit `min-height` it collapses to 0 during the first
layout pass; Recharts' internal `ResizeObserver` measures
the parent as 0; the warning fires before the real
dimensions arrive on the next frame.

Three-layer fix:

- `minWidth: 0` on the outer `<div>` — lets the flex child
  shrink below its intrinsic content width in tight grid
  cells.
- `minHeight: height` on the outer `<div>` — prevents the
  first-pass vertical collapse.
- `minWidth={0}` prop on `ResponsiveContainer` — overrides
  Recharts' default that conflicts with the parent
  measurement.

The `initialDimension={{width: 100, height: 100}}` stays as
the belt-and-suspenders measure for the very first render.

### HelpTooltip discoverability (commit `d74598a`)

The dotted-underline on glossary terms was a 1px
`var(--fg-muted)` border — too subtle to be noticed during
normal reading. Bumped to:

- 2px dashed `var(--accent)` (the project brand colour
  defined in every theme palette).
- 2px horizontal padding + 4px border-radius so the new
  hover-tint background pill has room to render without
  shifting line layout.
- `global.css` rule:
  `.help-term:hover, .help-term:focus-within {
   background-color: color-mix(in srgb, var(--accent) 10%,
   transparent); }` — subtle accent-tinted background pill
  on hover (and on keyboard focus inside the popover).

`color-mix` is supported in Chrome 111+, Safari 16.2+,
Firefox 113+. The fallback (no tint) degrades gracefully on
older browsers. The HelpTooltip test was updated to assert
the new 2px / `var(--accent)` styling.

### Tooltip sweep finish (commit `d74598a`)

Completes the user-listed icon-only and ambiguous-text
buttons that the prior commit (`65d0651`) did not cover:

| Component | Buttons added |
|---|---|
| `SessionChat` | Chat send button — `aria-label` always + gated `title` |
| `RatingDialog` | 1-5 rating buttons — `aria-label` reads as "1 - Low" / "3 - Medium" / "5 - High"; `title` gated |
| `Import` (page) | Per-row delete button — existing `title` now gated on the toggle |
| `LessonList` | Per-row ✎ edit + ✕ delete icon-only buttons — `aria-label` always + gated `title` |
| `ProjectTaxonomy` | Chip-remove `×` button — `title` gated alongside the existing per-subject `aria-label` |
| `QRScannerModal` | Close `×` button — `title` gated alongside the existing `aria-label` |

Text buttons that already have a clear visible label
(Assessment next/back/finish, Onboarding submit/skip,
Export markdown/PDF/Anki, Backup export/import/compare,
Sync pair/unpair) are intentionally NOT touched in this
release — the visible text IS the accessible name and
adding `aria-label` would duplicate it. A proper
screen-reader walkthrough lives in Phase 39 (the WCAG 2.1
AA audit shipping in v1.24.0).

### Toggleable button-tooltip preference (commit `65d0651`)

Already on `main` before this release tag, included here
for completeness:

- Settings > Interface gains a "Show button tooltips" toggle
  (default ON). Visible tooltip on hover; the underlying
  `aria-label` is ALWAYS present regardless of the toggle.
- `useButtonTooltips()` hook reads `localStorage`
  (`adaptive-learner.button_tooltips_enabled`), listens for
  same-tab change events + cross-tab `storage` events, and
  defensively handles environments where `window` is
  stubbed without `addEventListener` (caught by the
  MicButton test suite). Subscribers re-render in lockstep
  when the user flips the toggle.
- 53 new `ui.tooltips.*` keys land in all 8 i18n catalogs.
  EN + DE handwritten (DE uses real umlauts per the
  project's authoring rule). PT/TR/JA translated (many
  tooltip strings hit Phase 26 EN-markers and would have
  failed the audit otherwise). ES/FR/EL passthrough.
- Coverage in this release: MicButton, SpeechButton,
  HelpLink, HelpDrawer close, Navigation hamburger + theme
  toggle, TopicNode expand-collapse + add + rename +
  delete, plus the sweep finish listed above.

## Migration

No schema changes. No new user-facing dependencies. The
button-tooltip preference defaults to ON; users who don't
visit Settings see no change in behaviour. Existing dev
databases work unchanged.

## What's next: Phase 39 (v1.24.0)

The full WCAG 2.1 AA accessibility audit was deferred from
this patch release. It ships as **Phase 39 / v1.24.0** with
its own changelog and a dedicated audit document at
`docs/audits/wcag-YYYY-MM-DD.md` covering keyboard
navigation, ARIA live regions, chart text alternatives,
colour contrast, `prefers-reduced-motion`, and `@axe-core/react`
integration. The handover prompt for that work lives at
`docs/session-handover-a11y.md` (committed in the same push
as this release).
