# Adaptive Learner v1.79.0

Minor release. Two user-facing features — **XP visibility** and **bidirectional
matching selection** — land on top of the maintenance thread that completes the
**complexity burn-down** (every grandfathered offender now decomposed, the
`.complexity-baseline` empty), tightens the **radon hard gate to Phase 2**, adds
a **plugin-tests CI job**, and ships a **cross-project reusability policy** with
the first reusable primitives extracted under `frontend/src/shared/`. Also a
**P1 matching scoring fix**. No schema / API / data-model change. 31 commits
since v1.78.0.

## Added

- **XP visibility (#505, PR #510).** XP was only on the Dashboard; it is now
  surfaced where the learner sees it. A persistent **header badge**
  (`NavXpBadge`) reads the XP state from whichever storage backing is active
  (API + Dexie, both via `gamification.getState`), shows level + total, links to
  the Dashboard, and stays live — it refreshes on route change, tab focus, and
  any XP-affecting celebration (lesson complete / level up / mission / badge).
  The **lesson summary** gains a `+N XP` reward pill computed with the same
  parity-tested formula the award path uses (stars + first-attempt + streak
  multiplier), so the shown gain matches what was credited. Built on a new
  generic, props-driven `shared/XpBadge`. Token-backed CSS (gold `--star`),
  44px touch target, reduced-motion-safe, i18n in all 8 languages.

- **Bidirectional matching selection (#507, PR #509).** In a matching exercise,
  selecting a tile from the right (B) column first and then its partner on the
  left now forms a pair, exactly like the existing A → B direction. Previously
  only A → B selection worked, which felt broken to anyone who started from the
  definition side.

- **Radon hard gate — Phase 2 (#494, PR #495).** The complexity CI gate now
  blocks any Python unit at cyclomatic complexity **> 20** and warns in a
  **> 15** band, on top of the per-file `.complexity-baseline` ratchet.

- **Plugin-tests CI job (#471, Goal A of #434).** A dedicated CI job runs
  `make test-plugins` (the full per-plugin suite — 1018 tests across the 13
  plugins) so plugin regressions surface on every push, not only under the
  backend aggregate.

- **Reusability policy + extracted primitives.** A cross-project reusability

  `LessonStepNav` (#476), and `XpBadge` (#510).

## Fixed

- **Matching scored by value, not index, for duplicate pairs (#480, PR #481).**
  A matching exercise with two pairs sharing a side scored by tile index, so a
  correct match against the duplicate value could be marked wrong (and vice
  versa). Scoring now compares the matched **value**, fixing the false
  correct/incorrect results on duplicate-bearing matching exercises. **P1.**
