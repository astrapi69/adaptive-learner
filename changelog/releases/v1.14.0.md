# Adaptive Learner v1.14.0

**Released**: 2026-05-21

Phase 27 — **Rich-Text Notes with TipTap.** Session-rating
notes, curriculum descriptions and lesson content all
graduate from plain ``<textarea>`` to a full TipTap-based
``RichTextEditor`` with bold / italic / underline / strike,
headings 1-3, bullet + ordered + task lists, blockquote,
inline code, code blocks with syntax highlighting, links,
text alignment, highlight, undo / redo, and a per-block
language picker + copy button on every code block. Past
session notes render as rich text on the Progress page;
Markdown / PDF exports honour the new shape end-to-end.

Closes BL-12.

## Added

### 27A — TipTap base editor + toolbar

- New ``frontend/src/components/editor/`` module:
  ``RichTextEditor`` (TipTap wrapper), ``EditorToolbar``
  (separate component, wired to a shared ``Editor``
  instance), ``content-utils`` (legacy plain-text +
  serialised TipTap JSON round-trip).
- 23 TipTap dependencies pinned to Bibliogon-aligned
  versions (StarterKit + Underline + TextAlign + Link +
  Placeholder + CharacterCount + TaskList / Item + Highlight
  + Typography + Focus + Image + Sub / Superscript +
  TextStyle + Color + Tables) plus ``lowlight 3.3.0``
  (consumed by 27D).
- Mobile-friendly toolbar: horizontal scroll on narrow
  viewports, 40 px touch targets at ``max-width: 768px``.
- Dark / light styling via the existing CSS variable palette
  in ``global.css``.
- 42 new tests (Vitest).

### 27B — Session-rating notes are rich text

- ``RatingDialog`` swaps the textarea for ``RichTextEditor``
  + ``EditorToolbar`` (headings + history hidden — short
  notes don't need H1 / undo UI). Submit serialises the doc
  to the existing ``notes: string`` field via
  ``content-utils``; empty docs serialise to the empty
  string so the contract stays unchanged.
- Character-count read-out wired from the editor's storage.
- ``ProgressCommitOut`` gains optional
  ``notes: str | None``; the tracking plugin's
  ``/commits/{project_id}`` endpoint LEFT JOINs
  ``session_ratings`` to populate it.
- Progress page renders a notes row under each commit when
  the rating carries notes, using ``RichTextEditor`` in
  read-only mode. Legacy plain text and TipTap JSON both
  display correctly.
- 4 new RatingDialog tests + 2 new Progress page tests + 2
  new backend regression-pin tests (legacy plain text +
  TipTap JSON round-trip; session-without-rating still
  surfaces with ``notes=None``).

### 27C — Curriculum description + lesson content

- New ``CurriculumDescriptionEditor`` component: inline
  view-or-edit widget. Empty -> "Add description" button.
  Present -> read-only editor + "Edit description". Edit ->
  toolbar + editable editor + Save / Cancel.
- ``Curriculum.tsx`` wires it under the topic-tree heading
  via the existing ``PATCH /api/curricula/{id}`` endpoint.
- ``LessonList.tsx``: view mode renders content as a
  read-only ``RichTextEditor`` (only when content is
  non-empty); edit mode shows ``RichTextEditor`` +
  ``EditorToolbar``. Legacy plain-text rows migrate to
  serialised TipTap JSON on first save.
- 7 component tests for the new description widget; 5
  lesson tests updated; 1 new test verifies the on-save
  migration emits valid TipTap JSON.

### 27D — Code-block syntax highlighting

- New ``code-block-config.ts`` registers 11 highlight.js
  grammars (``bash``, ``css``, ``html`` (xml), ``java``,
  ``javascript``, ``json``, ``markdown``, ``python``,
  ``sql``, ``typescript``, ``yaml``) against a module-level
  ``lowlight`` registry; replaces StarterKit's plain
  ``codeBlock`` with the highlighted variant.
- New ``CodeBlockView.tsx``: React NodeView with a per-block
  toolbar — native ``<select>`` language picker (chosen over
  Radix DropdownMenu per the project's happy-dom-portability
  rule) plus a copy-to-clipboard button. ``Copied`` feedback
  flashes for 1.5 s; failed clipboard writes no-op silently
  so the visible text stays user-selectable.
- Hand-rolled highlight.js token theme in ``global.css``
  using the existing CSS variable palette; dark-mode
  override carries brighter token colours.
- 8 new tests cover the language picker, the copy flow, and
  the toolbar-insert path.

### 27E — TipTap rich-text in Markdown / PDF exports

- New ``frontend/src/lib/tiptap-to-markdown.ts``:
  ``renderStoredContent`` walks any TipTap JSON doc and
  emits GFM-style Markdown. Plain-text inputs return
  verbatim so legacy v1.13.0-and-earlier rows export
  unchanged.
- Node coverage: ``doc`` / ``paragraph`` / ``heading``
  (levels 1-6) / ``bulletList`` / ``orderedList`` /
  ``listItem`` / ``taskList`` / ``taskItem`` /
  ``blockquote`` / ``codeBlock`` (with language fence) /
  ``hardBreak`` / ``horizontalRule`` / ``image`` /
  ``table`` + row + cell + header.
- Mark coverage: ``bold`` / ``italic`` / ``strike`` /
  ``code`` / ``link`` / ``underline`` (HTML ``<u>``) /
  ``highlight`` (GFM ``==..==``) / ``subscript`` /
  ``superscript``. ``textStyle`` + ``color`` drop (no MD
  equivalent). Unknown node / mark types skip silently.
- ``markdown-renderer.ts`` routes session-rating notes,
  curriculum descriptions, topic descriptions, and lesson
  content through the new converter.
- 19 new converter tests pin every node + mark type, the
  unknown-node skip, JSON-vs-plain-text detection, and the
  empty-input contract.

## Behaviour notes

- ``session_ratings.notes``, ``curriculums.description``,
  ``lessons.content`` and ``learning_topics.description``
  remain TEXT columns. No Alembic migration. The Phase-27
  rich-text columns store serialised TipTap JSON as a
  string; legacy plain text co-exists with the new shape
  indefinitely.
- ``content-utils.parseEditorContent`` detects plain text vs
  TipTap JSON on read; ``content-utils.serializeEditorContent``
  serialises on write, returning ``null`` for empty docs so
  freshly-mounted editors with no user input don't persist
  placeholder nodes.
- The lowlight node uses the same node name ``codeBlock`` as
  StarterKit's, so any existing document containing a code
  block renders unchanged with highlighting now applied.
- TipTap's standard rendering is identical in display + edit
  mode (``editable: false`` flips off the contenteditable
  surface but keeps the same DOM tree), so the
  Progress-page notes row and lesson-content view-mode use
  the same ``RichTextEditor`` component as the editing
  surface.

## Migration

No breaking changes. Existing data renders unchanged. The
first edit of a legacy row migrates the persisted value to
TipTap JSON; clients reading either shape continue to work
because every consumer goes through ``content-utils`` or
``renderStoredContent``.

Math formulas are deliberately not included in this phase
(no ``katex`` / ``tiptap-mathematics`` dependency). They are
filed as a future-phase candidate when there's a concrete
trigger.
