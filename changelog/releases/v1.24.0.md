# Adaptive Learner v1.24.0

**Released**: 2026-05-23

Phase 39 — comprehensive WCAG 2.1 Level AA accessibility audit
and remediation. Seven atomic commits, one new dev dependency,
two real WCAG AA violations caught + fixed by new regression
tests, and a 380-line audit document that records every
finding alongside the test it pins.

The release scope was set in the v1.23.2 handover at
[docs/handover/session-handover-a11y.md](../../docs/handover/session-handover-a11y.md).

## Why this release

Accessibility is a legal requirement in many markets, not an
optional polish. v1.23.2 closed the immediate Recharts warning
+ HelpTooltip discoverability + icon-button-tooltip sweep
items; this release is the systematic WCAG 2.1 AA conformance
work that was scoped out of v1.23.2 because it warranted its
own minor-release shape.

Full audit document at
[docs/audits/wcag-2026-05-23.md](../../docs/audits/wcag-2026-05-23.md).

## What changed

### C1 — Skip-to-content link + landmark structure (commit `5461243`)

WCAG SC 2.4.1 (Bypass Blocks) + SC 1.3.1 (Info and
Relationships) + SC 2.4.6 (Headings and Labels).

- New `SkipToContent` component mounts as the first focusable
  element on every page; visually hidden until focused, then
  appears top-left. Activating it jumps focus past the
  navigation directly into the page's `<main id="main">`
  landmark.
- New CSS utilities `.sr-only` and `.skip-to-content` in
  `global.css`. Reduced-motion safe.
- `id="main"` added to every `<main>` element across all 13
  page components (covers loading / error / success variants).
- Heading-hierarchy fixes: ImportDetail Card (`<h4>` → `<h3>`)
  and SyncConflictDialog field card (`<h4>` → `<h3>`) no
  longer skip levels.
- `scope="col"` added to every `<th>` in the three tables
  that lacked it (BackupSection, BackupCompare, Progress).
- New i18n key `ui.a11y.skip_to_content` in all 8 catalogs.

### C2 — Keyboard navigation + focus management (commit `5aabc75`)

WCAG SC 2.1.1 (Keyboard) + SC 2.1.2 (No Keyboard Trap) +
SC 2.4.3 (Focus Order).

- Escape closes the three custom modal dialogs that were
  missing the handler: `RatingDialog`, `AddTopicDialog`,
  `SyncConflictDialog`. The Radix-backed dialogs already
  handled this natively.
- `RatingDialog` 5-button rating groups now implement the
  full WAI-ARIA radio-group keyboard contract: roving
  tabindex, arrow keys with wrap-around, Home / End. Previously
  every button was its own tab stop and arrow keys did nothing.
- `SessionChat` textarea is focused on first mount so a
  keyboard-only user can type immediately. Skipped when the
  chat is disabled.
- Audit of `outline: none` in `global.css`: the single
  occurrence is paired with a `:focus-visible` rule on the
  next line that restores a 2px accent outline — WCAG-compliant.

### C3 — ARIA labels + live regions + form associations (commit `436c53c`)

WCAG SC 1.3.1 + SC 3.3.2 (form-input labels) and SC 4.1.3
(Status Messages, AA).

- 7 placeholder-only inputs now also carry `aria-label`:
  `ModelPicker`, `HelpBrowser`, `SubjectBrowser` ×2,
  `TagManager`, `ProjectTaxonomy`, Settings API-key.
- `role="status"` added to the 12 loading-state paragraphs
  across 10 pages and 2 components (StreakCalendar,
  BadgeShowcase).
- `role="alert"` added to the 6 error-state paragraphs across
  Assessment, Dashboard, Curriculum, Progress, Session, Settings.
- A fresh icon-only-button grep (single-line and multi-line
  patterns, lucide-react child) found zero new gaps — the
  v1.23.2 sweep is still complete.

### C4 — Chart text summaries + data table alternatives (commit `119558f`)

WCAG SC 1.1.1 (Non-text Content).

- New `ChartSummary` helper (`components/charts/`) renders a
  visible caption + screen-reader-only summary + an optional
  collapsed `<details>` data-table alternative for every
  chart that warrants one.
- Wired into all 4 dashboard charts: `ProfileRadar` (6-row
  method × score table), `ProgressTimeline` (per-session
  understanding / stress table; trend computed up / down / flat
  with a 0.05 threshold), `MethodDistribution` (per-method
  count + percentage table), `StreakCalendar` (per-cell
  `aria-label` "{count} sessions on {date}" / "No sessions
  on {date}").
- 11 new `ui.a11y.chart_*` i18n keys in all 8 catalogs. EN +
  DE handwritten (real umlauts per project rule), PT / TR / JA
  translated, ES / FR / EL EN-passthrough.
- ~50 lines of new CSS for `.chart-summary*`. Bundle delta:
  +8.8 KiB.

### C5 — WCAG AA color contrast + colorblind-safe method colors (commit `9dd8e0e`)

WCAG SC 1.4.3 (Contrast Minimum) + SC 1.4.11 (Non-text
Contrast) + SC 1.4.1 (Use of Color).

- New `frontend/src/styles/contrast.ts` implements the WCAG
  2.1 relative-luminance + contrast-ratio formulas exactly.
  Reads `global.css` at test time so the assertions cannot
  drift out of sync with the production CSS.
- **Real violation #1** caught by the new test: light theme
  primary button `--accent-fg #ffffff` on `--accent #6366f1`
  = 4.47:1 (needs ≥ 4.5:1). Brand-palette decision: promoted
  `--accent-hover` (`#4f46e5`) to `--accent` (6.29:1 ✓);
  picked `#4338ca` as the new `--accent-hover` (8.4:1). Dark
  theme already passed at 5.32:1 and stays unchanged.
- **Real violation #2** caught: method badges hardcoded
  `color: "#ffffff"` over the 6 method colors. White on
  `#10b981` = 2.5:1, white on `#f59e0b` = 1.9:1, several
  others below 4.5:1. Fixed WITHOUT changing the brand
  palette via a new `bestTextOn(hex)` helper that picks black
  or white per background. All 6 method colors pick `#000000`
  on the current pin. Applied to `MethodBadge`,
  `MethodSwitchBanner`, `ToolRecommendations`,
  `QuickStartButton`, Assessment dominant-method pill.
- `@media (forced-colors: active)` block ensures skip-link
  visibility in Windows High Contrast Mode.
- Method palette contains red (`error_based`) + green
  (`dialogic`) — the classic deuteranopia / protanopia
  confusion pair — but every method badge pairs color with a
  text label, so color is never the sole carrier. WCAG 1.4.1
  satisfied; no palette change required.

### C6 — `@axe-core/react` integration + lang-attribute live sync (commit `e39a5d4`)

WCAG SC 3.1.1 (Language of Page) + SC 3.1.2 (Language of Parts).

- `@axe-core/react` ^4.11 added to `frontend/devDependencies`.
  NOT in `dependencies`. Tree-shaken out of the production
  bundle: the dynamic `import("@axe-core/react")` is guarded
  by `import.meta.env.DEV` which Vite replaces with `false`
  at build time. Verified bundle delta: 0 KiB.
- In dev mode, axe runs every 1000 ms and logs WCAG violations
  to the browser console so contributors see regressions live.
- `useI18n` now mirrors its active `lang` state to
  `document.documentElement.lang` via a 3-line `useEffect`.
  Previously `<html lang="de">` was hardcoded in `index.html`
  and stayed `"de"` when the user switched the UI to English /
  Spanish / etc.

### C7 — `prefers-reduced-motion` catch-all (commit `d6e3385`)

WCAG SC 2.3.3 (Animation from Interactions) + SC 2.2.2 (Pause,
Stop, Hide).

- Catch-all `@media (prefers-reduced-motion: reduce)` block at
  the end of `global.css` resets `animation-duration` +
  `animation-iteration-count` + `transition-duration` +
  `scroll-behavior` for every element via the universal
  selector. `!important` is required so the catch-all wins
  against per-component animation shorthand declarations.
- Existing per-animation overrides (cycle-pulse,
  assessment-slide, xp-rise, qr-scanline, etc.) stay in place.
  The catch-all is the safety net for animations that don't
  have their own override.
- Phase 38 HelpTooltip's inline CSS-in-JS hover transition
  moved to `.help-term` in `global.css` so the catch-all can
  reach it (inline styles bypass media queries).

## Migration

No database schema changes. No new production runtime
dependencies (axe-core is dev-only). No user-facing dependency
bumps.

**Brand-palette change**: the light-theme primary-button accent
color shifts from indigo `#6366f1` to slightly darker indigo
`#4f46e5` (the previous hover color). The hover state becomes
even darker (`#4338ca`). Same brand family, half-shade darker
for AA contrast.

Existing user storage works unchanged. Existing dev databases
work unchanged.

## What's next

The C6 axe-core integration logs to the dev-mode browser
console; the per-route manual walkthrough remains an
operational checklist. Any axe finding beyond the violation
classes covered by C1–C5 becomes a `WCAG-AXE-FOLLOWUP-NN`
backlog item.
