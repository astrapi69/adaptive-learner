# Adaptive Learner v1.73.0

Minor release — centralizes feature gating on **@astrapi69/feature-strategy**,
adds an end-to-end feature-test suite for the no-API-key surfaces, key-gates the
NotebookLM AI actions, and corrects a dependency/build break. Frontend +
test-infra + dependency hygiene; no schema, API, or data-model change.

## Added

- **Feature-strategy integration (#287).** Replaces the scattered, ad-hoc
  feature gating (per-button `disabled` + `title="API key required"`, hardcoded
  `apiKey.ready && !apiKey.hasKey` checks, Dexie-mode `resolveStorageMode()`
  section-hiding) with a single feature **registry + strategy** from
  `@astrapi69/feature-strategy` (+ its React adapter). Three states —
  **active / disabled / hidden** — resolved from one memoised `{mode, hasAiKey}`
  context. Descriptors carry the default (`active`); the strategy holds only the
  deviation rules (AI features that need a key → disabled in Dexie without one;
  desktop-only sync / git-persist → hidden in Dexie) and abstains otherwise,
  failing closed (unknown id → hidden). The AI-key status is now **reactive**:
  saving / switching / restoring / removing a provider key in Settings flips
  every gate **without a reload**. Migrated sites: Import-Detail
  (analyze / start-session / extract-Anki), the Anki empty state, the NotebookLM
  AI actions, the Dashboard quick-start, Pronunciation, the Settings Sync
  section, and the Learning-Repository git controls. Logic branches that route
  rather than gate (export engine, danger-zone reset) deliberately stay on
  `resolveStorageMode()`.
- **End-to-end feature tests (Dexie mode).** New Playwright specs against the
  GitHub-Pages-shape build (no backend): external content-repository import +
  error paths + external-repo playthrough (#278), Anki extraction gating +
  `.apkg` export (#279), and the NotebookLM package + learning-materials surface
  (#280).

## Fixed

- **NotebookLM AI buttons key-gated (#281).** "Generate study questions" and
  "Download study guide" are AI-backed but were enabled without a provider key,
  so a keyless click surfaced a raw error toast. They now disable with an
  explanatory notice when no key is configured (the Anki / Import pattern); the
  client-side ZIP "Download NotebookLM package" stays enabled.
- **TipTap v2/v3 build break (#267, #288).** Dependabot bumped
  `@tiptap/extension-highlight`, `-table-cell` and `-task-item` to `3.26.0`,
  pulling `@tiptap/core@3` peers against the rest of the editor stack on
  `2.27.2`. The skew broke the production build with `MISSING_EXPORT`
  (`getStyleProperty`, `TableCell`) and failed the editor test files at load.
  Pinned the three back to `2.27.2`, realigning the whole editor on the v2 line.
- **Progress page test (#289, #290).** After the NotebookLM feature-system
  migration, `Progress.test.tsx` rendered a `useFeature` consumer outside a
  provider and threw. Wrapped its render helper in the shared
  `TestFeatureProvider`.

## Changed

- **Dependency bumps** (Dependabot): ESLint 9 → 10 (#266), mypy 1.20 → 2.1
  (#263), the frontend and backend minor-patch groups (#261, #262), and the
  GitHub Actions `checkout` 5 → 6 (#260), `setup-node` 5 → 6 (#259),
  `upload-artifact` 6 → 7 (#258).
- **Handover documentation (#291)** for the feature-strategy work recorded under
  `docs/journal/`.

## Notes

- Deliberate behaviour changes encoded in the feature table: AI features are no
  longer key-gated in **API mode** (they resolve to `active` there); `sync`,
  `git-persist` and `learning-repo-git` are **hidden** (not disabled) in Dexie
  mode, matching the "a function that is not available is not offered" rule.
- The frontend install now requires `--legacy-peer-deps` due to a pre-existing
  `eslint-plugin-react` vs ESLint 10 peer conflict; `@testing-library/dom` is
  declared explicitly so the resolution keeps it.
