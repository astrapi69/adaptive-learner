# Adaptive Learner v0.6.0

**Released**: 2026-05-18

Phase 9 — **mobile PWA**. Learning is inherently mobile and
Adaptive Learner is now usable where people actually learn: on
their phones. Responsive UI across the seven main routes,
installable manifest with proper PNG + SVG icons, service-worker
caching for offline browsing of past work, online/offline
indicator in the nav, and a touch-optimised RatingDialog +
SessionChat + CycleProgress.

## Added

### Responsive foundation (9A)
- Hamburger menu drawer at ≤768px (toggles `.nav-links`
  visibility, `aria-expanded` + `aria-controls`, auto-closes on
  route change). Desktop horizontal top-bar unchanged at
  ≥769px (Phase 9 Q2 — hamburger on mobile only, sidebar
  mention in the spec was loose).
- 44×44 touch targets at ≤768px on every interactive element:
  `.btn`, `.nav-link`, `.nav-hamburger`, `.nav-theme-toggle`,
  every `input`, `select`, `textarea`, `.answer-option`,
  `.landing-cta`, `.landing-lang-btn`, `.onboarding-skip-top`,
  `.spaced-rec-actions .btn`. Desktop sizing untouched (Q3).
- Input `font-size: 16px` at mobile suppresses iOS Safari's
  auto-zoom on focus.
- Layout overflow fixes: `.form-actions` stacks vertically,
  `.onboarding-header-row` columnar, `.api-key-row-input` and
  `.model-override-row-input` columnar, `.landing-lang-options`
  wraps, `.spaced-rec-card` stacks, `.commit-table-wrap` gets
  horizontal scroll with momentum, `.step-eval-metrics` single
  column.
- Extreme-narrow (≤360px) safety net shrinks page padding.

### PWA manifest + service worker (9B)
- Manifest: `short_name: "Adaptive"` (fits Android's ≤12-char
  recommendation; full name "Adaptive Learner" still shows in
  app switchers). `categories: ["education", "productivity"]`
  + `lang` + `description` for browser install dialogs.
- PNG icons at 192/512 alongside the existing SVGs. PNGs carry
  `purpose: "any maskable"` so Android can crop into its
  platform shape without losing the network-mark visual.
- Service-worker strategy: GET `/api/` → `NetworkFirst` with
  4s timeout / 24h LRU / 60-entry cap (returning users see
  cached dashboard / progress / commits offline). Mutating
  `/api/` → `NetworkOnly`. `navigateFallbackDenylist` keeps
  the SPA shell out of `/api/` paths so backend errors don't
  get masked.
- Precached `offline.html` is the deep static fallback for
  the rare case where even the SPA shell isn't cached.
- `InstallPrompt` component captures `beforeinstallprompt`,
  shows a dismissable banner (full-width on mobile, anchored
  bottom-right card on desktop). Dismissal persists to
  `localStorage[adaptive-learner.install_dismissed]`. Hides
  on `appinstalled` event.

### Touch optimisation (9C)
- **RatingDialog**: sliders → 1-5 button group universally
  (Q4 — sliders are imprecise UX for a 5-position scale at
  any input device; one code path beats two). `role="radiogroup"`
  + `role="radio"` + `aria-checked` on every button.
- **SessionChat**: at ≤768px the chat surface grows to
  `calc(100vh - 14rem)`, messages take flex remainder, input
  row hugs the bottom of the card. Send button widened to
  ≥4rem so it's a clear thumb target.
- **CycleProgress**: at ≤768px collapses to a single horizontal
  row of 7 narrow circles (`minmax(2.4rem, 1fr)`) instead of
  the v0.5.0 two-row 4×2 grid. Eye scans position at a glance.
- **RatingDialog modal**: full-width + max-height 92vh with
  vertical scroll on mobile so the 3-row rating + notes +
  Cancel/Submit fit.

### Offline capabilities (9D)
- New `useOnlineStatus` hook subscribes to `online` / `offline`
  window events. SSR / no-navigator environments default to
  `true`.
- `nav-online-indicator` between nav-links and theme toggle:
  green/red dot + label ("Online"/"Offline"), `role="status"` +
  `aria-live="polite"`, `title` tooltip carrying the longer
  explanation. Label hides at ≤768px (dot + tooltip carry
  meaning).
- Session offline guard: `/session` mount checks
  `navigator.onLine` and renders the inline
  `session-error` panel with a clear localised message
  ("New sessions need a network connection — past sessions
  stay readable from the Dashboard") instead of firing a
  POST that would 503. Going back online auto-retries via
  the effect dep array.

### Mobile viewport pins (9E)
- New `e2e/smoke/mobile-viewports.spec.ts` parametrises 4
  device sizes (iPhone SE 375, iPhone 14 390, Pixel 7 412,
  iPad 768). Each runs 4 checks: Landing no-overflow,
  hamburger visible at the breakpoint, Dashboard no-overflow,
  online indicator present. 16 net new e2e cases.

## What's NOT in v0.6.0

- **Real-device testing** — Lighthouse + DevTools device
  emulation stay on the smoke-tester side (Phase 9 Q6).
- **Swipe gestures on Assessment** — deferred (Q5). Buttons
  work fine for prev/next; gesture pass can come later if
  users ask.
- **iOS-Safari `display: standalone` quirks** — manifest is
  cross-browser standard but iOS has its own
  `apple-mobile-web-app-*` meta tags that aren't yet wired.
  Add if iOS PWA installs show degraded UX.
- **Push notifications** — separate concern; the foundation
  (registered SW) is there, the wiring isn't.
