# Adaptive Learner v1.61.0

Minor release — **app-wide shadcn/ui button conformance, lesson
resume-at-paused-step, cross-repo content validation, and two
backup-restore data-integrity fixes**. One additive schema change
(Alembic 0027); both storage modes (API + Dexie / GitHub-Pages) carry
everything.

## UI — app-wide button audit

- Systematic audit of **every** button across all 13 page areas against
  the shadcn/ui standard (documented in `docs/audits/button-audit.md`),
  then conversion of ~200 genuine action buttons from legacy
  `.btn`/raw `<button>` to shadcn `<Button>` with the correct variant
  (`default` / `secondary` / `outline` / `destructive` / `ghost` /
  `link`), a 44px touch target, lucide icons + responsive labels
  (icon-only on mobile, icon + text from `md` up), and preserved
  `aria-label` / `data-testid` / handlers.
- Settings (all tabs), Lesson viewer + exercises + error-replay,
  Dashboard + Content Browser + Share Wizard, Create Lesson + Anki +
  Import, Learning Path (3 views) + Session, and the modals / nav /
  help surfaces all converted.
- Legitimately-raw interactive elements (exercise option tiles, the
  rich-text editor toolbar toggles, xyflow graph nodes, curriculum-tree
  controls, drag handles, radio/chip/tile widgets, list-row nav links)
  are documented and intentionally left as-is.
- **Settings → Datensicherung:** the backup actions are now prominent
  shadcn Buttons (Create = `default`, Restore = `outline`), full-width
  on mobile, and the section scrolls back to the top after a restore so
  the buttons stay visible while the result toast shows.

## Features

### Resume a paused lesson at the exact step

- A paused lesson restarted from step 1 because the resume position was
  reconstructed only from `step_results`, which records *graded
  exercise* steps — theory steps and the current unanswered exercise
  write none, so the navigation position was lost on pause.
- `LessonProgress` gains a `current_step` column (Alembic **0027**,
  non-null, `server_default 0`) + Dexie field (no version bump — a
  non-indexed field). The viewer persists it on every step / autosave /
  pause and resumes at `max(step_results-derived, current_step)`.
  Backward compatible: pre-feature rows read 0 (old behaviour). Reset on
  abandon / restart.

### Cross-repo content validation (no more stale-content drift)

- `scripts/validate_bundled_content.py` makes the content repo the
  single authority: it reads the content-repo manifest directly (via
  `ADAPTIVE_LEARNER_CONTENT_DIR`, fallback the sibling checkout) and
  keeps an auto-generated **CONTENT-STATS** block in the README in
  lock-step (`--write-readme` regenerates; `--check-readme` exits 1 on
  drift or on orphan set dirs / manifest-vs-filesystem count
  mismatches). Skips cleanly when no content checkout is present.
- Wired as defense-in-depth: a pre-commit hook (writes), a
  `Content stats drift` CI job that checks out the content repo **fresh**
  (the PR gate), and a double-safety step on the GitHub-Pages deploy.
  The README now reports the live **330 lessons / 16 sets / 3 domains**.

## Fixed — backup / restore data integrity

- **Restore UNIQUE on `badges.key`:** badges are a seeded catalog with a
  random per-install `id` + UNIQUE `key`; restoring onto a DB whose
  catalog was seeded under different ids crashed on a duplicate-key
  insert. Restore now matches seeded-catalog rows by a declared natural
  key (`TableSpec.natural_key`, `badges → "key"`), updates in place
  keeping the local id, and remaps `user_badges.badge_id` (backup →
  local) so earned badges keep referential integrity across
  installs / re-seeds.
- **Restore FK ordering:** `_RESTORE_ORDER` derives from the FK
  topological sort (a referenced table always precedes its referrers)
  intersected with the sync surface, fixing a latent FK violation when
  restoring curriculum/session rows that came from a chat import; a
  comprehensive FK-position pin guards it.
- Backup now includes `imported_conversation_id` on the curriculum +
  session backup columns.
